# Release Note - v1.0.114

## [1.0.114] - 2026-08-20

작성: 2026-08-20 23:40 KST

부팅이 눈에 띄게 빨라집니다. 다국어 데이터를 채우는 단계가 233초에서 1초로 줄었습니다. 함께 조회 전용 역할이 실행 상세에서 볼 수 있는 것과 누를 수 있는 것을 갈랐고, 데이터베이스를 비우고 처음부터 올릴 때 시드가 깨지던 세 곳을 고쳤습니다.

### 주요 변경 사항

#### ⚡ 부팅 시 다국어 시딩 233초 → 1초

원인이 두 겹이었고 각각 따로 고쳤습니다.

* **영속성 컨텍스트가 계속 커졌습니다**(233초 → 51초). 시딩 헬퍼는 항목마다 기존 값을 조회하는데, JPA 는 조회 전에 보류 중인 변경을 반영하고 관리 중인 데이터를 전부 훑습니다. 전체가 한 트랜잭션이라 뒤 단계가 앞 단계보다 느려졌습니다. 같은 분량인 한국어 49초와 영어 75초가 그 증거였습니다. 하위 초기화 50개를 단계로 감싸 각 단계 뒤에 컨텍스트를 비웁니다. 트랜잭션은 그대로 유지되므로 실패 시 통째로 되돌아가는 성질은 변하지 않습니다.
* **항목마다 조회를 세 번 했습니다**(51초 → 1초). 키 이름으로 키, 언어 코드로 언어, 그 둘로 기존 번역을 각각 찾았습니다. 번역 7,351건이면 조회가 2만 번을 넘습니다. 키 이름·언어 코드·번역값을 처음 한 번만 읽어 메모리에 두고 그 뒤로는 그것으로 판정합니다. 적재는 32밀리초입니다.
* 원래 동작을 보존했습니다. 로그 문구를 파일별로 유지했고, **기존 값을 덮어쓰는 초기화 16개는 그대로 덮어쓰고 i18n 보강 계열 4개는 그대로 유지합니다.** 이 넷을 함께 덮어쓰게 바꾸면 번역 관리 화면에서 고친 값이 부팅마다 되돌아갑니다.

#### 🌐 번역값만 있고 등록되지 않던 키 4건

시딩은 키를 먼저 만들고 그 키에 언어별 값을 붙입니다. 값만 추가하고 키 등록을 빠뜨리면 경고만 남고 그 값이 버려집니다. 부팅은 정상으로 끝나고 화면은 코드에 박힌 기본값으로 뜨므로 번역이 빠진 것을 알기 어렵습니다.

| 키 | 이전 상태 |
|---|---|
| `testcase.version.button.create` | 한국어·영어 값 있음, 키 없음 |
| `testcase.spreadsheet.export.excel.title` | 한국어·영어 값 있음, 키 없음 |
| `testcase.version.summary.restored_to` | 영어만 있음, 키 없음 |
| `testcase.version.summary.steps_updated` | 영어만 있음, 키 없음 |

뒤 둘은 버전 히스토리 화면의 변경 요약에 그대로 나오는 값입니다. 키가 없어 값이 버려졌으므로 영어 화면에서도 뜨지 않았습니다. 네 건을 등록하고 빠진 한국어 두 건을 채웠습니다.

#### 👁️ 실행 상세에서 볼 수 있는 것과 누를 수 있는 것을 나눴습니다

* **수정·저장 버튼에 역할 조건이 없었습니다.** 조회 전용 역할에게도 그대로 보였습니다. 편집 권한이 있을 때만 내보냅니다.
* **결과 입력 버튼은 권한이 없을 때 비활성으로만 뒀습니다.** 비활성은 "지금은 못 누른다" 를 뜻하므로 권한 없음과 같은 표현으로 두면 눌러 보고 실패해야 알게 됩니다. 역할 조건과 실행 상태 조건을 나눠, 권한이 없으면 버튼을 내보내지 않고 권한은 있으나 실행이 진행 중이 아닐 때만 비활성으로 둡니다.
* **조회 경로는 막지 않습니다.** 결과 기록 권한이 없으면 `입력` 대신 `보기` 가 나오고, 케이스 이름은 역할과 무관하게 눌러 결과 화면으로 들어갑니다. 그 화면은 조회 전용 역할에서 저장 버튼 없이 뜹니다. 결과 입력 링크 복사는 쓰기 흐름이라 감춥니다.
* 1.0.113 의 노출 실측에서 이 화면이 빠져 있었습니다. 그 회차 기록은 조회 전용 역할에게 보이는 쓰기 버튼이 0개라고 적었으나, 실행 상세에 수정 1개와 결과 입력 12개가 남아 있었습니다.

#### 🌱 데이터베이스를 비우고 다시 올릴 때 깨지던 세 곳

셋 다 재실행해야 드러나는 종류라 평소 개발에서는 보이지 않았습니다.

* **같은 프로젝트를 두 초기화가 만들었습니다.** 기본 데이터 초기화가 `MOBILE-TEST` 를 만든 뒤 조직 데이터 초기화가 같은 코드로 또 만들려다 유일 제약에 걸렸습니다. 예외를 잡아 로그만 남기고 넘어가는데 영향이 있었습니다. 조직을 들고 있는 쪽이 예외로 빠지므로 **그 프로젝트가 조직에 연결되지 않은 상태로 남고**, 그 뒤의 멤버 배정이 통째로 건너뛰어졌습니다. 코드로 먼저 찾는 형태로 바꿨고, 이미 있으면 조직만 채우고 이름·설명은 덮지 않습니다.
* **샘플 데이터 시드가 지워진 프로젝트 ID 를 재사용했습니다.** 상태 파일은 데이터베이스를 비워도 남습니다. 확인 없이 재사용해 뒤 단계가 전부 실패했습니다. 캐시한 ID 를 한 번 조회해 없으면 버리고 프로젝트 코드로 다시 찾습니다.
* **결과 판정이 이번 회차에 만든 건수만 셌습니다.** 자동화 통과 30건 이상 같은 조건을 확인하는데, 이미 결과가 있는 데이터베이스에서는 새로 만드는 것이 0 이라 판정이 실패했습니다. 물어야 할 것은 몇 건을 만들었나가 아니라 샘플셋이 조건을 갖췄나이므로 기존 결과를 계수에 넣었습니다.

#### 🧪 회귀 방지 검사 3종

부팅 로그를 사람이 읽어 잡는 방식은 작동하지 않습니다. 시딩 한 회차의 로그가 수천 줄이고, 실제로 번역 키 4건이 그 사이에 남아 있었습니다.

* **번역값이 있는 키는 모두 등록되어야 한다**: 키 등록과 값 등록을 소스에서 뽑아 차집합을 냅니다.
* **하위 초기화는 단계로 감싸야 한다**: 새 초기화를 추가하며 빠뜨리면 그 단계만큼 컨텍스트가 다시 커집니다.
* **시딩 헬퍼는 색인에 위임해야 한다**: 저장소를 직접 조회하는 옛 형태로 돌아가면 실패합니다.

셋 다 일부러 깨뜨려 실제로 실패하는지 확인하고 되돌렸습니다.

### 업그레이드 안내

* DB 마이그레이션 스크립트는 없습니다. 스키마 변경도 없습니다.
* 신규 i18n 키는 4개입니다. 한국어·영어 모두 시드되며, 이미 있는 값은 덮지 않습니다.
* 기존 데이터베이스로 올려도 시딩 결과는 이전과 같습니다. 변경 전 스냅샷과 전체 행을 대조해 확인했습니다.
* **권한이 좁아진 동작이 있습니다.** 실행 상세의 기본 정보 수정은 편집 권한(CONTRIBUTOR 이상)이 필요합니다. 이전에는 역할과 무관하게 버튼이 보였고 서버가 막았습니다.
* 조회 전용 역할은 결과 화면을 **열어 볼 수 있습니다.** 결과 입력 버튼이 `보기` 로 바뀐 것이며, 권한이 늘어난 것이 아닙니다.
* 로컬 샘플 데이터를 다시 만들 때는 시드 상태 파일을 지우지 않아도 됩니다. 없는 프로젝트를 가리키면 스스로 버리고 다시 찾습니다.
* 브라우저에 옛 화면이 캐시돼 있으면 강제 새로고침(⌘⇧R / Ctrl+F5)이 필요합니다.
* 1.0.113 변경은 [RELEASE_NOTE_1.0.113_KO.md](RELEASE_NOTE_1.0.113_KO.md)를 참고하세요.
