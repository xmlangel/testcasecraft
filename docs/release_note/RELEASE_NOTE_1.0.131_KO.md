# Release Note - v1.0.131

## [1.0.131] - 2026-10-21

작성: 2026-10-21 17:25 KST

대시보드 개요 화면이 케이스와 결과가 많은 프로젝트에서 3초 넘게 걸리던 문제를 고쳤습니다. 화면에 보이는 수치는 바뀌지 않습니다.

### 주요 변경 사항

#### 대시보드 개요 통계를 빠르게 계산합니다

대시보드 개요는 프로젝트의 케이스·플랜·실행 수, 최신 결과별 수, 우선순위별 미실행 수를 보여 줍니다. 이 세 통계를 구하는 조회가 프로젝트가 커질수록 크게 느려졌습니다. APM 에서 케이스 1,213개, 결과 3,329건인 프로젝트의 개요 요청이 3.6초 걸렸고, 그중 3.5초가 이 세 조회였습니다.

| 통계 | 느렸던 이유 | 데이터베이스 실행 시간(수정 전 → 수정 후) |
|---|---|---|
| 케이스·플랜·실행 수 | 케이스마다 모든 플랜과 실행을 곱한 뒤 다시 줄여, 중간 행이 약 97만 개 생기고 디스크 정렬이 일어남 | 1,393ms → 24ms |
| 최신 결과별 수 | 결과 한 건마다 그 케이스의 가장 최근 실행 시각을 다시 구함 | 782ms → 28ms |
| 우선순위별 미실행 수 | 위와 같음 | 744ms → 27ms |

이번 버전부터는 수마다 따로 세고, 케이스별 최신 결과를 한 번에 뽑습니다.

**영향:** 큰 프로젝트에서 대시보드 개요가 빨리 열립니다. 작은 프로젝트는 원래 빨랐으므로 체감 차이가 적습니다.

### 업그레이드할 때

- 데이터베이스 변경이나 따로 실행할 스크립트는 없습니다.
- 환경변수와 설정 파일은 바꾸지 않아도 됩니다.

### 확인한 범위

- 수정 전과 수정 후 조회를 같은 데이터베이스에서 나란히 실행했습니다. 프로젝트 7개와 존재하지 않는 프로젝트 ID 1개에서 세 통계 값이 모두 같았습니다.
- 한 케이스에 실행 시각이 똑같은 결과가 두 건 있으면 수정 전에는 둘 다 셌고 이번 버전은 한 건만 셉니다. 확인한 데이터에는 이런 경우가 없었습니다.
- 백엔드 테스트 109개 클래스 807건이 통과했고 실패는 0건입니다.
- 배포한 서버에서 APM 으로 개요 응답 시간을 다시 재는 확인은 아직 하지 않았습니다.

### 개발 절차

- `dev` 로 병합할 수 있는 브랜치 접두에 `fix/` 를 추가했습니다. 이제 `feat/`·`fix/`·`core/`·`doc/` 를 받습니다.
