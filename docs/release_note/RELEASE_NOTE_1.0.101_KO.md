# Release Note - v1.0.101

## [1.0.101] - 2026-07-30

작성: 2026-07-30 16:45 KST

테스트를 돌리다 "이 케이스는 손봐야 한다"고 알아챈 것을 나중에 모아 처리할 수 있게 했습니다. 결과에 태그를 달아 두면 나중에 그 태그로 다시 찾습니다. 태그를 입력하고 저장했는데 저장되지 않던 문제도 함께 고쳤습니다. 테스트케이스 트리에서는 이제 케이스 ID로 검색할 수 있습니다.

### 주요 변경 사항

#### 🐞 버그 수정

* **태그를 입력하고 저장하면 사라지던 문제**: 결과 입력 화면에서 태그를 타이핑한 뒤 곧바로 저장을 누르면 태그가 저장되지 않았습니다. 입력창이 Enter로 확정하지 않은 텍스트를 값으로 넘기지 않는 탓이었고, 경고도 없이 사라졌습니다. 이제 입력 도중에 저장을 눌러도 태그가 확정됩니다. 같은 입력창을 쓰는 일괄 입력 공통 태그와 실행 화면 태그 필터도 함께 고쳤습니다.
* **일괄 입력이 달아 둔 태그를 지우던 문제**: 공통 태그를 비워 둔 채로 여러 케이스의 결과를 한 번에 갱신하면, 케이스마다 달아 둔 태그가 매번 지워졌습니다. 이제 공통 태그를 비워 두면 각 케이스가 자기 태그를 그대로 유지합니다.

#### ✨ 새 기능

* **결과 태그로 걸러보기**: 실행 화면 필터에 태그 항목이 생겼습니다. 프로젝트에 이미 쓰인 태그를 골라도 되고 직접 입력해도 됩니다. 여러 개를 고르면 그 가운데 하나만 붙어 있어도 목록에 남습니다.
* **프로젝트 전체에서 태그로 조회**: 결과 조회 API에 태그 조건이 추가됐습니다. 실행별로 하나하나 들어가 확인하지 않고, 표시해 둔 것을 프로젝트 단위로 모아 볼 수 있습니다. 과거 회차에 달아 둔 태그도 함께 찾습니다.
* **테스트케이스 트리에서 ID·태그 검색**: 검색창이 이름만 찾던 것을 이름·케이스 ID·태그까지 찾도록 넓혔습니다. 트리에 `AGG-1016 · 케이스명` 으로 보이는데 그 ID를 넣으면 아무것도 안 나오던 것이 이 문제였습니다. `1016` 처럼 일부만 넣어도 걸립니다. 대소문자는 가리지 않습니다. 콤마로 여러 개를 넣으면 하나만 맞아도 남습니다.

#### 🔧 동작 변경

* **결과를 저장할 때 태그를 물려받습니다**: 결과는 덮어쓰지 않고 회차마다 쌓입니다. 그래서 태그를 달아 둔 케이스를 다시 실행하면 새 기록에는 태그가 없어, 화면(최근 기록만 표시)에서는 표시가 사라진 것처럼 보였습니다. 이제 태그를 따로 지정하지 않고 결과를 저장하면 그 케이스의 최근 태그를 이어받습니다. 자동화로 결과를 넣을 때도 이어받습니다.
  * 태그를 비운 상태로 저장하면 지워집니다. 다 고친 뒤에는 이렇게 표시를 뗍니다.
  * 일괄 입력에서 공통 태그를 입력하면 그 값이 우선합니다.

### 업그레이드 안내

* DB 마이그레이션 스크립트는 없습니다. 스키마 변경도 없습니다.
* 신규 i18n 키 3건(`testExecution.filter.tags`, `testExecution.filter.tags.placeholder`, `testcase.tree.filter.placeholderAll`)은 앱 기동 시 한/영 모두 자동 등록됩니다.
* 자동화로 결과를 적재하는 스크립트는 수정할 것이 없습니다. 태그 항목을 보내지 않으면 이전 태그를 이어받고, 빈 목록을 보내면 지워집니다. 회차마다 태그를 비우고 싶다면 빈 목록을 명시적으로 보내세요.
* 태그 이름은 팀에서 하나로 정해 쓰는 편이 좋습니다(예: `수정필요`). 자유 입력이라 표기가 갈리면 각각 걸러야 합니다.
* 결과 조회 API의 태그 조건은 대소문자를 가리지 않습니다. 여러 개를 넘기면 하나만 붙어 있어도 결과에 들어갑니다.
* 1.0.100 변경은 [RELEASE_NOTE_1.0.100_KO.md](RELEASE_NOTE_1.0.100_KO.md)를 참고하세요.
