# Release Note - v1.0.128

## [1.0.128] - 2026-10-13

작성: 2026-10-13 07:40 KST

요구사항 관리를 새로 넣었습니다. 요구사항을 문서 단위로 정리하고 테스트케이스와 연결하면, 어떤 요구사항이 얼마나 검증됐는지를 커버리지와 리포트로 볼 수 있습니다. 함께 서버 오류 문구를 영어로 통일했고, 사용자 매뉴얼을 작업 순서에 맞춘 21개 장으로 다시 배열했습니다.

### 주요 변경 사항

#### 요구사항을 등록하고 테스트케이스와 연결합니다

프로젝트에 「요구사항」 탭이 생깁니다. 요구사항 문서를 만들고 그 아래에 요구사항을 등록합니다. 범위와 설명은 테스트케이스와 같은 마크다운 에디터로 작성합니다.

요구사항마다 이를 검증하는 테스트케이스를 연결합니다. 연결한 케이스는 요구사항 화면에서, 연결된 요구사항은 케이스 화면에서 바로 열어 내용을 확인할 수 있습니다. 연결이 많은 요구사항은 목록을 접어 두고 검색으로 찾습니다.

요구사항 관리는 선택 기능입니다. 쓰지 않는 프로젝트는 지금처럼 테스트케이스부터 작성하면 되고, 기존 화면과 동작은 바뀌지 않습니다.

**영향:** 조회 전용 역할은 요구사항을 볼 수만 있고, 프로젝트 멤버가 아닌 사용자는 접근할 수 없습니다.

#### 커버리지와 리포트로 검증 상태를 봅니다

커버리지 탭은 요구사항마다 충족·부분·미연결·제외 중 하나로 판정하고, 전체 비율을 도넛 그래프로, 문서별 분포를 누적 막대로 보여 줍니다.

리포트는 테스트 플랜을 골라 요구사항별 실행 결과를 집계합니다. 연결된 케이스의 결과는 통과·실패·미실행·플랜에 없음 네 가지로 나뉘어 요구사항 단위로 표시됩니다.

#### 요구사항끼리 관계를 걸고 관계도로 봅니다

요구사항 사이에 상위·하위, 의존, 관련 관계를 겁니다. 다른 프로젝트의 요구사항, 자기 자신, 이미 있는 관계, 상위·하위가 돌고 도는 순환은 등록 단계에서 막습니다. 요구사항을 지우면 그 요구사항에 걸린 관계도 함께 지워집니다.

「관계도」 탭은 요구사항과 테스트케이스를 네트워크로 그립니다. 연결이 많거나 여러 요구사항을 잇는 노드일수록 크게 표시되고, 노드를 고르면 그 주변만 강조됩니다. 테스트케이스를 공유하는 요구사항끼리 묶어 보는 보기와, 아무 데도 연결되지 않은 요구사항 목록도 함께 제공합니다.

**영향:** 관계도를 그리는 라이브러리(`cytoscape`, MIT)는 이 탭을 열 때만 내려받습니다(gzip 약 177KB). 다른 화면의 첫 로딩은 이전과 같습니다.

#### 서버 오류 문구를 영어로 통일했습니다

서버는 화면 언어에 따라 오류 문구를 고르지 않습니다. 그래서 지금까지는 영어 화면에서도 한국어 오류 문구가 그대로 보였습니다. 예외 메시지, 오류 응답 본문, 입력값 검증 문구 1,144곳을 영어로 바꿨습니다.

성공 안내 문구, 로그, API 문서의 설명, 번역 데이터, LLM 프롬프트는 바꾸지 않았습니다.

**영향:** 한국어 화면에서도 서버가 돌려준 오류는 영어로 보입니다. JIRA 연결 오류처럼 오류 문구에 든 낱말로 상황을 판단하던 곳은 한국어와 영어 문구를 모두 알아보므로 동작은 이전과 같습니다.

#### 사용자 매뉴얼을 작업 순서에 맞게 다시 배열했습니다

한 파일이던 사용자 매뉴얼을 21개 장으로 나눠, 처음 쓰는 사람이 작업하는 순서대로 읽어 내려가게 했습니다. 전체 구조와 핵심 용어(1장), 처음부터 끝까지 한 번 따라 하는 예시(2장), 요구사항과 커버리지(5장)를 새로 썼습니다. 요구사항 장은 케이스 작성 앞에 두되 선택 단계로 표시해, 요구사항을 쓰지 않는 팀은 6장으로 건너뛰면 됩니다.

기존 본문은 문장을 고치지 않고 새 위치로 옮겼습니다. 앱의 `/manual` 화면 왼쪽 목차에 새 장 구조가 나옵니다.

예시 프로젝트 ShopFlow 에 요구사항 데이터(문서 3, 요구사항 11, 케이스 연결 14, 관계 6)를 넣는 시드 스크립트를 추가했고, 매뉴얼 5장의 그림은 이 데이터로 찍었습니다.

**영향:** 영문 매뉴얼은 아직 이전 구조이고, 영어 ShopFlow 에는 요구사항 예시가 들어가지 않습니다.

### 업그레이드할 때

- 요구사항 기능이 쓰는 테이블은 서버가 기동할 때 자동으로 만들어집니다. 따로 실행할 스크립트는 없습니다.
- 환경변수와 설정 파일은 바꾸지 않아도 됩니다.

### 확인한 범위

- 요구사항 관리 브랜치에서 백엔드 테스트 787건(요구사항 API 통합 테스트 포함)과 프런트엔드 테스트 731건이 모두 통과했고, 커버리지 그래프·관계 등록과 순환 차단·관계도 화면을 브라우저로 확인했습니다.
- 오류 문구 브랜치에서 백엔드 테스트 766건과 프런트엔드 테스트 724건이 모두 통과했습니다. 한국어 문구를 기대하던 테스트 21건은 영어 문구에 맞게 고쳤습니다.
- 매뉴얼은 합본 안 링크 끊김 0건, 그림 누락 0건을 확인했고, 요구사항 화면 그림은 ShopFlow 예시 데이터를 띄운 서버에서 찍었습니다.
- 세 변경을 모두 합친 dev 기준의 전체 테스트는 이 노트를 쓰는 시점에 돌리지 않았습니다. 배포 전에 한 번 돌려 확인해야 합니다.
