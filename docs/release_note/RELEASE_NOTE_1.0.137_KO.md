# Release Note - v1.0.137

## [1.0.137] - 2026-11-06

작성: 2026-11-06 14:53 KST

Docker 이미지에서 발견된 취약점 21건을 라이브러리 버전 상향으로 해결했고, 테스트 케이스 화면에 편집/보기 전환과 자동화 케이스 표시·필터를 추가했습니다.

### 주요 변경 사항

#### 테스트 케이스 폼에 편집/보기 전환을 추가했습니다

- 폼 상단 TC ID 옆에 「편집 / 보기」 토글이 생겼습니다. 편집 권한이 있는 역할에게만 보입니다.
- 보기 모드에서는 입력란이 비활성화되고 저장·취소·삭제·버전 생성 버튼이 사라집니다.
- 고른 모드는 브라우저에 저장되므로 다른 케이스로 옮겨도 유지됩니다. 기본값은 편집입니다.
- 새 케이스를 작성하는 중이거나 폴더 폼을 열었을 때는 보기 모드가 적용되지 않습니다.
- TESTER·VIEWER 역할은 토글과 관계없이 이전처럼 읽기 전용입니다.
- 보기 모드로 바꾸기 전에 입력한 내용은 자동 저장됩니다.

#### 자동화 케이스를 아이콘으로 구분합니다

- 자동화 여부가 체크된 케이스는 좌측 트리, 폴더를 열었을 때 나오는 케이스 목록, 폼 상단에 자동화 아이콘이 붙습니다.
- 폼에서 자동화 여부 체크를 바꾸면 상단 표시도 바로 바뀝니다.
- 수동 케이스, 자동화 여부 값이 없는 예전 케이스, 폴더에는 표시하지 않습니다.

#### 테스트 케이스 트리에 자동화 필터를 추가했습니다

- 트리 검색창 아래에서 「전체 · 자동화 · 수동」 중 하나를 고를 수 있습니다. 폴더만 보는 화면에서는 나오지 않습니다.
- 자동화 여부 값이 없는 예전 케이스는 수동으로 분류됩니다.
- 검색어와 함께 쓰면 두 조건을 모두 만족하는 케이스만 남습니다. 건수와 전체 선택도 필터 결과를 기준으로 계산합니다.
- 필터를 건 상태에서 일괄 삭제하면 필터에 걸린 케이스만 지웁니다. 체크된 폴더는 지우지 않습니다. 폴더를 지우면 필터 밖에 있는 케이스까지 함께 지워지기 때문입니다. 「전체」일 때는 이전과 같이 동작합니다.

#### 테스트 플랜에서 자동화 여부로 케이스를 골라 담을 수 있습니다

- 플랜 생성·수정 화면의 케이스 선택 트리에도 같은 필터가 나옵니다.
- 필터를 건 상태에서 전체 선택하거나 폴더를 체크하면 필터에 걸린 케이스만 플랜에 담깁니다.
- 필터 밖에 이미 선택된 케이스가 있으면 「필터 밖에서 선택된 케이스 N건도 함께 저장됩니다」라는 안내가 나옵니다.

#### Docker 이미지 취약점 21건을 해결했습니다

1.0.136 이미지를 Docker Scout 로 스캔해 나온 26건 가운데, 라이브러리 버전만 올리면 해결되는 21건을 처리했습니다.

| 라이브러리 | 이전 → 이후 | 해결 |
|---|---|---|
| tomcat-embed | 10.1.55 → 10.1.61 | Critical 4 |
| netty-bom | 4.1.136.Final → 4.1.139.Final | Critical 1, Medium 2 |
| bcprov / bcpkix-jdk18on | 1.84 → 1.86 | Critical 1, High 1 |
| jackson-bom | 2.21.5 → 2.21.8 | High 4, Medium 2 |
| snappy-java (전이 의존성) | 1.1.10.7 → 1.1.10.12 | High 2, Medium 1 |
| guava (전이 의존성) | 33.4.8-jre → 33.7.2-jre | High 1 |
| log4j2 | 2.24.3 → 2.25.5 | Medium 1 |

### 업그레이드할 때

- DB 스키마와 설정 변경은 없습니다.
- 새 화면 문구(번역 키 9개)는 서버가 시작될 때 없는 것만 자동으로 추가됩니다.
