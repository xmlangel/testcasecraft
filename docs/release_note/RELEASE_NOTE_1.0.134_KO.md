# Release Note - v1.0.134

## [1.0.134] - 2026-10-29

작성: 2026-10-29 18:20 KST

1.0.133 이후 `dev` 에 들어온 변경 열 건을 묶었습니다. 테스트 결과를 스텝마다 입력하고 리포트·내보내기·Jira 댓글에 그 결과를 싣는 기능이 중심입니다. 내보내기 파일에 이미지 주소와 공개 토큰이 남던 문제, 다국어 누락, 결과 화면 내보내기 버튼 정리도 함께 들어 있습니다.

### 주요 변경 사항

#### 테스트 결과를 스텝마다 입력합니다 (ICT-469)

결과 입력 화면의 스텝 표에 결과(Pass·Fail·Blocked) 버튼과 실제 결과 칸이 생겼습니다. 같은 버튼을 다시 누르면 결과가 미실행(NOT_RUN)으로 돌아갑니다.

- 스텝 결과를 바꾸면 케이스의 종합 결과를 다시 계산합니다. 하나라도 Fail 이면 Fail, Fail 없이 Blocked 가 있으면 Blocked, 미실행 스텝이 남아 있으면 미실행, 모두 Pass 면 Pass 입니다.
- 종합 결과는 사람이 직접 바꿀 수 있고, 바꾼 값은 스텝을 다시 고쳐도 유지됩니다.
- 스텝 결과에는 실행 당시의 스텝 설명과 기대 결과가 함께 저장됩니다. 나중에 케이스의 스텝을 고쳐도 지난 결과에 남은 내용은 바뀌지 않습니다.
- 이전 결과 대화상자와 케이스 실행 이력에 스텝 결과 요약이 보입니다.
- API 로 결과를 저장할 때 `steps` 배열을 함께 보낼 수 있습니다. 보내지 않으면 지금까지처럼 케이스 결과 하나만 저장합니다. 일괄 저장(bulk)은 `steps` 를 받지 않습니다.
- MCP 의 `testexecution_record_result` 도 `steps` 를 받습니다.

#### 「모든 스텝 Pass」는 메모를 받아야 저장됩니다 (ICT-479)

이전에는 이 버튼이 결과가 비어 있는 스텝만 Pass 로 채웠습니다. 그래서 직전 결과를 불러와 다시 실행하면 바뀌는 스텝이 없었습니다. 이제 모든 스텝을 Pass 로 바꾸고, 이미 적은 실제 결과는 그대로 둡니다.

- 버튼을 누르면 메모 입력 창이 열리고, 입력한 메모는 결과의 노트에 기록됩니다. 입력 창은 노트와 같은 마크다운 에디터입니다.
- 메모가 비어 있으면 저장하지 않고 메모 칸으로 이동하며, 자동 저장도 보류합니다.
- 입력 창이 열려 있는 동안에는 판정 단축키가 동작하지 않습니다. 메모에 입력한 글자가 결과 판정으로 처리되지 않게 하려는 조치입니다.

#### 리포트와 결과 화면에서 스텝 결과를 봅니다 (ICT-472, ICT-475)

- PDF·HTML 리포트의 케이스 카드에 스텝 결과 표가 스텝 순서대로 실립니다.
- 카드에 싣는 항목(폴더, JIRA 상태, 자동화 여부, 실행 타입, 태그, 연결 문서, 첨부, 사후 조건, 테스트 기법)은 그 열을 켰을 때만 나옵니다. 지금까지는 열 설정과 상관없이 정해진 항목이 나왔습니다.
- 스텝의 실제 결과는 마크다운 에디터로 입력합니다. 일반 텍스트로 저장된 기존 값은 줄바꿈이 유지된 채 보입니다.
- 실제 결과가 10,000자를 넘으면 입력 칸에 오류와 안내가 나옵니다. 서버는 원래 초과분을 거부했지만, 화면에서는 저장하기 전까지 알 수 없었습니다.
- 결과 상세 테이블의 「스텝 결과」 칸이 「스텝 정보」 칸과 같은 카드 형태로 바뀌었습니다. 카드마다 `Step N` 과 결과 표시가 붙고, 실제 결과는 마크다운으로 보입니다. 스텝 정보 칸을 꺼도 스텝 결과가 잘리지 않습니다.

#### 내보내기 파일에 이미지 주소와 공개 토큰이 남지 않습니다 (ICT-470)

비고나 단계에 붙인 본문 이미지가 엑셀·CSV 에 `![image](/api/testcase-attachments/public/...?token=...)` 형태로 그대로 들어갔습니다. 셀에는 읽을 수 없는 문자열이 보였고, 공개 토큰도 파일에 남았습니다.

- 결과 내보내기(엑셀·CSV·PDF·HTML), 서버 내보내기, JUnit 결과 CSV, 테스트케이스 스프레드시트에서 이미지를 `[이미지: 대체텍스트]` 로 바꿉니다. 대체텍스트가 없으면 `[이미지]` 입니다.
- 이미지가 있는 칸은 나머지 마크다운 기호도 걷어 낸 평문으로 내보냅니다. 이미지가 없는 칸은 원문 그대로입니다.
- 테스트케이스 스프레드시트를 다시 가져오기(import)할 때 쓸 원문은 내보내기 메뉴의 「가져오기용 원문」 CSV·Excel 로 받습니다.

#### 엑셀·CSV·PDF 내보내기에 스텝 결과가 들어갑니다 (ICT-469, ICT-472)

- 화면과 서버에서 만드는 엑셀·PDF·CSV 에 스텝 결과 열이 생겼습니다. 엑셀에는 「케이스 × 스텝」 상세 시트가 추가됩니다.
- 서버 내보내기에 Display ID, 설명, 사후 조건, 자동화 여부, 실행 타입, 테스트 기법, 태그, 연결 문서, 첨부 열이 추가되었습니다.

#### 서버 내보내기와 Jira 자동 댓글이 사용자의 언어를 따릅니다 (ICT-473, ICT-474)

- 서버가 만드는 엑셀·CSV·PDF 의 열 머리글, 시트 이름, 결과 값이 화면 언어로 나옵니다. 언어 정보가 없으면 지금처럼 한국어로 나옵니다.
- 한국어 내보내기의 자동화 여부 값이 `Automation`/`Manual` 에서 `자동화`/`수동` 으로 바뀌었습니다. 화면 내보내기와 같은 값입니다.
- 실행 실패 알림, 결과 업데이트, 실행 완료 요약 댓글은 댓글을 남기는 사용자의 선호 언어로 작성됩니다. 사용자를 찾지 못하면 한국어로 작성합니다. 사용자가 입력한 비고·스텝 설명·실제 결과는 번역하지 않습니다.
- 결과 업데이트 댓글에 Fail·Blocked 스텝이 기대 결과와 실제 결과 형식으로 실립니다.
- 실행 시각이 비어 있으면 결과 업데이트 댓글이 오류로 끝나던 것을 「미설정」 표기로 고쳤습니다.

#### 결과 화면의 내보내기 버튼을 하나로 합쳤습니다 (ICT-476, ICT-478)

결과 상세 그리드 툴바에 있던 기본 EXPORT(CSV·인쇄) 버튼과 「고급 내보내기」 버튼을 없애고, 표 위의 **내보내기** 버튼 하나만 남겼습니다. 처음에는 이 버튼이 모바일 폭에서만 보였는데, 데스크톱에서도 보이도록 고쳤습니다.

### 업그레이드할 때

- 스텝 결과를 저장하는 `test_result_steps` 표가 새로 생깁니다. `ddl-auto: update` 설정에 따라 서버가 기동할 때 만들어지므로 따로 실행할 SQL 은 없습니다. 기존 결과는 스텝 결과 없이 그대로 보입니다.
- 결과 화면 내보내기는 이제 그리드의 필터·정렬과 상관없이 전체 행을 내보냅니다.
- 한국어 서버 내보내기의 자동화 여부 값이 `자동화`/`수동` 으로 바뀌었습니다. 이 값을 읽는 스크립트가 있으면 확인해 주세요.
- 결과 내보내기 요청에 `language` 필드가 추가되었습니다. 생략해도 동작합니다.

### 확인한 범위

- 열 건이 모두 합쳐진 `dev`(`1e6a3dac`)에서 프론트엔드 단위 테스트 830건이 모두 통과했습니다.
- 백엔드 테스트는 ICT-474 를 합친 브랜치에서 947건 중 938건이 통과했습니다. 실패한 9건은 모두 `JiraSmartRedirectIntegrationTest` 가 H2 에서 기동하지 못한 것이며, 이번 변경 전 `dev` 에서도 같은 9건이 실패합니다. 열 건을 모두 합친 `dev` 에서는 백엔드 테스트를 다시 돌리지 않았습니다.
- ICT-469·470·472 는 로컬 서버에서 E2E 3건을 세 번씩 돌려 통과했습니다. 제품 코드를 일부러 망가뜨린 변이 8종을 넣었을 때 해당 테스트가 매번 실패하는 것도 확인했습니다.
- 결과 상세 테이블의 스텝 결과 카드는 로컬 화면에서 확인했습니다.
- 나머지 화면 변경(모든 스텝 Pass 메모, 데스크톱 내보내기 버튼, PDF·HTML 리포트 파일)은 브라우저에서 확인하지 않았습니다. 배포한 뒤 확인이 필요합니다.

### 알려진 문제

- 결과 편집 이력(승인형 편집)에는 스텝 결과가 들어가지 않습니다.
- 스텝 통과율 통계, 계층 내보내기의 스텝 결과, 스텝별 첨부·결함 연결은 아직 없습니다.
- 1.0.132 에 적은 두 문제(조직 멤버가 아닌 사용자의 프로젝트 카드 403, 인증 메일 재요청 시 앞선 요청 결과의 경고)는 이번 버전에서도 고치지 않았습니다.
