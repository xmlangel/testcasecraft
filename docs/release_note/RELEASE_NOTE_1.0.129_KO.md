# Release Note - v1.0.129

## [1.0.129] - 2026-10-13

작성: 2026-10-13 12:50 KST

요구사항 문서와 요구사항의 ID 를 서버가 자동으로 붙입니다. 지금까지는 ID 를 사용자가 하나씩 입력해야 했습니다. 같은 프로젝트에서 여러 사람이 동시에 저장해도 번호가 겹치지 않도록 테스트케이스 ID 를 붙이는 방식도 함께 고쳤습니다.

### 주요 변경 사항

#### 요구사항 문서와 요구사항에 번호가 자동으로 붙습니다

| 대상 | 자동 ID 예시 | 번호를 세는 범위 |
|---|---|---|
| 요구사항 문서 | `R-ONTS-001` | 프로젝트 안의 문서 |
| 요구사항 | `R-ONTS-001-001` | 소속 문서 안의 요구사항 |

추가 창을 열면 다음 번호가 미리 채워져 있고, 필요하면 고쳐서 저장할 수 있습니다. 요구사항 추가 창에서 소속 문서를 바꾸면 그 문서의 다음 번호로 다시 채워집니다. 사용자가 직접 고친 값은 덮어쓰지 않습니다.

ID 칸을 비운 채 저장해도 서버가 번호를 붙입니다. 이미 있는 항목을 수정하면서 ID 를 비우면 기존 ID 를 그대로 둡니다.

번호는 같은 형식의 기존 ID 가운데 가장 큰 번호에 1 을 더한 값입니다. `REQ-CART-001` 처럼 직접 입력한 다른 형식의 ID 는 계산에 넣지 않습니다.

**영향:** 다른 형식으로 ID 를 써 온 프로젝트도 기존 ID 는 바뀌지 않습니다. 새로 추가하는 항목에만 `R-` 형식 번호가 제안됩니다.

#### 동시에 저장해도 번호가 겹치지 않습니다

같은 프로젝트에서 여러 저장 요청이 한꺼번에 들어오면, 서버가 요청을 하나씩 차례로 처리하면서 다음 번호를 줍니다. 요구사항 문서·요구사항과 테스트케이스(단건 생성, 일괄 저장, 프로젝트 간 이동·복사)에 모두 적용했습니다.

이전에는 테스트케이스 ID 에 중복을 막는 장치가 없어, 동시에 만들면 같은 ID 를 가진 케이스가 두 건 생길 수 있었습니다. 요구사항은 같은 번호를 받은 쪽의 저장이 실패했습니다.

**영향:** 같은 프로젝트에 대한 저장이 동시에 몰리면 뒤에 온 요청은 앞 요청이 끝날 때까지 기다립니다. 서로 다른 프로젝트의 저장은 서로 기다리지 않습니다.

### 업그레이드할 때

- 데이터베이스 변경이나 따로 실행할 스크립트는 없습니다.
- 환경변수와 설정 파일은 바꾸지 않아도 됩니다.

### 확인한 범위

- 백엔드 테스트 794건과 프런트엔드 테스트 735건이 모두 통과했습니다. 실제 PostgreSQL 에서 두 번째 저장이 첫 번째 저장이 끝날 때까지 기다리는지 확인하는 통합 테스트를 추가했습니다.
- 실행 중인 앱에 요구사항 문서 8건, 요구사항 12건, 테스트케이스 12건을 동시에 저장했고, 모두 성공했으며 번호가 겹친 항목은 없었습니다.
- 브라우저에서 문서 추가 창의 번호 미리 채움과, 요구사항 추가 창에서 문서를 바꿀 때 번호가 다시 채워지는 동작을 확인했습니다.
- 지운 항목의 번호는 다시 쓰일 수 있습니다. 남아 있는 가장 큰 번호에 1 을 더하기 때문이며, 테스트케이스도 같은 방식이라 이번에 바꾸지 않았습니다.
- 서버가 시작할 때 테스트케이스 순번을 보정하는 작업에는 이번 처리를 넣지 않았습니다.
