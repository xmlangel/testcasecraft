# Release Note - v1.0.121

## [1.0.121] - 2026-08-25

작성: 2026-08-25 22:33 KST

마크다운을 쓰는 방식이 바뀌었습니다. 왼쪽에 기호를 적고 오른쪽에서 결과를 확인하던 두 칸 화면이 없어졌고, 이제 서식이 글 안에 그대로 그려집니다. 표는 표로 보이고 체크박스는 눌러서 켜고 끕니다. 저장되는 값은 예전과 같은 마크다운입니다.

### 주요 변경 사항

#### ✍️ 편집 화면에서 서식이 바로 보입니다

`## ` 을 치면 그 줄이 제목이 되고, `- ` 을 치면 목록이 됩니다. 기호가 사라지고 결과만 남습니다.

위쪽에 버튼 아홉 개가 생겼습니다. 굵게, 기울임, 코드, 제목, 인용, 목록, 번호 목록, 체크리스트, 표 넣기입니다. 표를 넣으면 3×3 이 만들어지고 칸 사이는 Tab 으로 옮깁니다.

여섯 화면의 마크다운 입력란이 모두 이 편집기로 바뀌었습니다.

| 화면 | 항목 |
|---|---|
| 폴더 | 설명 |
| 테스트케이스 | 설명, 사전조건, 기대결과 |
| 테스트케이스 | 스텝 표의 「Step 설명」과 「예상 결과」 |
| 실행 결과 | 비고 |
| 실행 | QA 총평 |
| 탐색적 테스팅 | 차터 |

스텝 표처럼 폭이 좁은 자리도 버튼 구성이 같습니다.

#### 🔍 비고를 전체화면으로 볼 수 있습니다

실행 결과의 비고가 길어지면 좁은 칸에서 읽기 어려웠습니다. 글자 수 옆 버튼을 누르면 화면 전체로 펼쳐집니다.

펼친 화면 위쪽에 「전체화면 나가기」 버튼과 `Esc` 안내가 함께 있습니다. 결과 판정 버튼은 아래쪽에 그대로 떠 있어 펼친 상태에서도 저장할 수 있습니다.

#### 📝 비고를 다시 편집할 수 있습니다

비고를 저장하고 다시 들어오면 보기 전용으로 열립니다. 예전에는 이 상태에서 편집으로 돌아갈 방법이 없었습니다.

연필 버튼이 생겼습니다. 누르면 편집으로, 다시 누르면 보기로 돌아갑니다. 고른 상태는 기억되므로 다음에 열 때도 같은 모드로 시작합니다. 읽기 권한만 있는 사용자에게는 이 버튼이 보이지 않습니다.

#### 🛟 열어 보기만 해도 결과가 덮이던 문제를 고쳤습니다

실행 결과 화면은 비고를 고치면 1.5초 뒤에 자동으로 저장합니다. 그런데 새 편집기를 붙이는 과정에서, 화면을 **열기만 해도** 편집한 것으로 처리되어 저장이 나가는 경로가 생겼습니다. 아무것도 건드리지 않았는데 남이 적어 둔 결과가 덮일 수 있는 상황이었습니다.

편집기가 실제로 글을 바꾼 경우만 저장으로 이어지도록 막았습니다. 화면을 열거나 커서를 옮기는 것만으로는 저장이 나가지 않습니다.

#### 📜 가려진 내용이 있으면 표시합니다

편집기와 보기 화면은 높이 상한을 두고 넘치면 안에서 스크롤합니다. 그런데 넘쳤다는 표시가 없어서, 잘린 자리에서 글이 끝난 것처럼 보였습니다. 표나 목록이 경계에 딱 맞게 걸리면 더 있다는 신호가 하나도 없었습니다.

가려진 쪽 모서리에 글줄을 닮은 막대 셋이 그 방향으로 흘러가며 사라집니다. 아래에 더 있으면 아래쪽에, 위로 올라간 내용이 있으면 위쪽에 붙습니다. 끝까지 내리면 아래쪽 표시가 사라져 다 봤다는 것을 알 수 있습니다. 내용이 상한을 넘지 않으면 아무 표시도 나오지 않습니다.

버튼처럼 보이지 않게 테두리와 그림자를 두르지 않았습니다. 색은 테마의 강조색을 따라가고, 동작 최소화를 설정한 사용자에게는 흐름이 멈추고 막대만 남습니다.

편집기에서 줄이 늘어 상한을 넘는 순간에도 바로 붙습니다. 보기 화면에서도 같게 동작합니다.

#### 🔤 저장할 때 표기가 다듬어집니다

편집기가 마크다운을 다시 쓰면서 표기를 한 가지로 맞춥니다. 뜻은 같고 모양만 바뀝니다.

| 쓴 것 | 저장된 것 |
|---|---|
| `__굵게__` | `**굵게**` |
| `_기울임_` | `*기울임*` |
| `* 목록` | `- 목록` |
| 표 칸 너비 | 칸을 맞춘 공백이 붙습니다 |

첫 저장에서 한 번 정리되고 그 뒤로는 바뀌지 않습니다. 저장을 반복해도 빈 줄이 늘어나지 않습니다.

**HTML 태그는 사라집니다.** 본문에 `<details>` 로 접기를 만들어 두면 첫 저장 때 태그가 없어지고 안쪽 글만 남습니다. 접기가 필요하면 지금은 담을 방법이 없습니다.

#### 🖼️ 이미지 붙여넣기 위치가 달라졌습니다

이미지를 붙여넣으면 업로드는 그대로 되지만, 커서 자리가 아니라 **글 맨 끝**에 들어갑니다. 넣은 뒤 원하는 자리로 옮겨야 합니다.

#### ⏳ 진행 중인 실행이 목록에서 바로 보입니다

목록에서 상태는 색만 달랐습니다. 끝난 것과 지금 도는 것이 나란히 있으면 어느 것이 진행 중인지 훑어서 알기 어려웠고, 화면마다 색도 달랐습니다(목록은 파랑, 작업 화면은 주황).

진행 중인 것만 움직입니다. 아이콘이 도는 진행 표시로 바뀌고 칩이 숨쉬듯 크기와 밝기를 오갑니다. 끝난 것과 시작하지 않은 것은 그대로 둡니다. 다 움직이면 무엇이 진행 중인지 다시 구별할 수 없습니다.

색과 모양도 상태마다 다르게 뒀습니다.

| 상태 | 색 | 채움 | 아이콘 |
|---|---|---|---|
| 시작 안 함 | 회색 | 테두리만 | 시계 |
| 진행 중 | 주황 | 채움 | 도는 진행 표시 |
| 완료 | 초록 | 채움 | 체크 |

**색만으로 구별하게 두지 않았습니다.** 채움 여부와 아이콘 모양, 움직임을 함께 갈라 색약이나 흑백 출력에서도 구별됩니다. 진행 중을 주황으로 옮긴 이유는 기본 디자인 시스템의 파랑이 회색과 명도가 가까워 나란히 두면 붙어 보였기 때문입니다.

적용한 자리는 실행 목록, 플랜 목록, 실행 작업 화면, 실행 요약 다섯 곳입니다.

#### 🌳 테스트케이스 트리가 케이스까지 보이는 상태로 열립니다

처음 들어오면 폴더만 보였습니다. 트리에 폴더만 나오니 펼칠 것이 없고, 케이스를 보려면 있는 줄도 몰랐던 토글을 먼저 눌러야 했습니다.

이제 케이스까지 보이는 상태로 시작합니다. 폴더만 보는 쪽을 한 번 고르면 그 선택은 그대로 기억합니다.

#### 🧰 트리 머리 버튼이 한 줄로 정리됐습니다

케이스를 선택하면 「프로젝트 이동/복사」와 「선택 삭제」 버튼이 나타나는데, 트리 폭이 좁아 글자가 한 자씩 세로로 접혔습니다(`프 로 젝 트 이 동 / 복 사`). 머리 영역이 그만큼 길게 늘어났습니다.

두 버튼을 아이콘으로 바꾸고 무엇을 하는 버튼인지는 툴팁으로 알립니다. 선택 개수도 툴팁에 들어갑니다. 선택 중에는 폴더·케이스 개수를 접고 선택 개수만 남겨 아이콘 여섯 개가 한 줄에 들어갑니다. 머리 높이가 380px 가까이에서 38px 로 줄었습니다.

#### 🔧 아이콘 크기를 하나로 맞췄습니다

화면 틀의 아이콘 크기가 세 가지로 갈려 있었습니다. 상단 바와 빵조각의 즐겨찾기·설정은 24px, 트리 머리와 보기 전환은 20px, 좌측 메뉴는 18px 과 20px 이 섞였습니다. 같은 줄에 크기가 다른 아이콘이 놓이면 어느 것이 더 중요한 버튼인지 잘못 읽힙니다.

18px 하나로 맞췄습니다. 상단 바, 빵조각, 트리 머리, 좌측 메뉴, 개별 폼·스프레드시트 전환이 모두 같은 크기입니다.

#### 🖥️ 자동화 결과 상세가 다른 화면과 같은 틀에서 열립니다

이 화면만 상단 바와 좌측 메뉴 없이 전체 화면으로 떴습니다. 실행 상세와 케이스 결과 화면은 좌측 메뉴 모드에서 껍데기를 유지한 채 오른쪽 영역에서 열리는데, 자동화 결과 상세에는 그 규칙이 빠져 있었습니다. 화면을 오갈 때 메뉴가 사라져 어디에 있는지 알기 어려웠습니다.

같은 규칙을 적용했습니다. 좌측 메뉴 모드에서는 껍데기 안에서 열리고, 가로 탭 모드에서는 예전처럼 단독으로 열립니다. 옛 주소(`/junit-results/...`)도 함께 맞췄습니다.

화면 제목도 34px 에서 24px 로 내려 다른 화면과 같은 단계가 됐습니다. 섹션 라벨과 필터 입력은 14px, 차트 범례와 축 눈금은 13px·12px 로 낮췄습니다. 화면 안의 동작 버튼(자동화로 돌아가기, PDF·CSV 내보내기, 새로고침, 결과 업로드)은 39px 에서 33px 로 줄여 다른 화면의 버튼과 같은 크기가 됐습니다.

#### 🔤 화면별로 달랐던 글자 크기를 맞췄습니다

RAG·탐색 세션·자동화 세 화면만 글자가 커 보였습니다. 스위치·체크박스 라벨과 입력 라벨이 기본값 16px 이었고, 본문도 16px 로 명시된 자리가 열아홉 곳이었습니다. 자동화 화면은 섹션 라벨과 차트 범례·축 눈금이 16px 였습니다. 다른 화면은 14px 로 표시합니다.

14px 로 맞췄습니다. RAG 화면의 섹션 제목도 24px 에서 20px 로 내려 다른 화면과 같은 단계가 됐습니다.

16px 이상이 차지하는 비율을 재 봤습니다.

| 화면 | 이전 | 이번 |
|---|---|---|
| RAG | 38% | 24% |
| 탐색 세션 | 32% | 21% |
| 자동화 | 55% | 30% |
| (기준) 테스트케이스 | 13% | 13% |
| (기준) 실행 | 10% | 10% |

남은 것은 화면들이 함께 쓰는 규격입니다. 빵조각과 화면 이름, 공용 화면 제목 컴포넌트(여섯 화면 공유), 자동화 화면의 큰 지표 숫자입니다. 지표 숫자는 대시보드와 같은 단계라 그대로 뒀습니다.

#### 🧹 JIRA 연동 오류 문구를 없앴습니다

JIRA 서버를 설정하지 않은 상태에서 화면을 열면 개발자 도구에 오류가 찍혔습니다. 설정하지 않은 것은 정상인데 오류처럼 보였습니다. 화면 동작에는 영향이 없었습니다.

#### 🌐 새 버튼의 한국어·영어 문구를 넣었습니다

편집기 툴바 아홉 개, 비고 버튼 넷, 트리 머리 선택 표시까지 새 문구를 한국어·영어 양쪽에 등록했습니다.

### 개발자 참고

마크다운 편집과 표시를 서로 다른 라이브러리로 나눴습니다.

| 구분 | 이전 | 이번 |
|---|---|---|
| 편집 | `@uiw/react-md-editor` | Tiptap (ProseMirror) |
| 표시 | `@uiw/react-md-editor` 의 `MDEditor.Markdown` | `react-markdown` |
| 표시 호출부 | 아홉 파일에서 직접 호출 | 공용 `MarkdownViewer` 한 곳 |
| 루트 클래스 | `.wmde-markdown` | `.markdown-body` |

`@uiw/react-md-editor` 를 제거했습니다. 그 패키지가 실어 오던 `markdown.css` 도 함께 사라져 표·코드·제목 서식을 `markdownStyles.js` 에서 직접 제공합니다.

**`react-markdown` 을 직접 의존성으로 올렸습니다.** 지금까지 `@uiw/react-md-editor` 를 통해서만 들어와 있었고, 그대로 제거하면 이미 `react-markdown` 을 쓰던 세 화면(RAG 채팅, 청크 미리보기, JIRA 코멘트)이 함께 깨졌습니다.

본문 HTML 은 `rehypeRaw` 로 살리고 `rehypeSanitize` 를 뒤에 걸었습니다. 테스트케이스 본문은 사용자 입력이고 다른 사용자가 결과 화면에서 열어 보므로, 걸러내지 않으면 심어 둔 스크립트가 그대로 실행됩니다.

**편집기 상호작용은 `jsdom` 에서 검증할 수 없습니다.** ProseMirror 가 좌표(`elementFromPoint`)로 입력 위치를 잡는데 `jsdom` 에 그 API 가 없습니다. 편집기 단위 시험은 렌더 결과와 권한, 외부 값 동기화만 덮고, 타이핑·툴바·표 삽입·전체화면은 실제 브라우저로 확인했습니다. 앞으로 이 계열 상호작용 시험은 Cypress 쪽에 두어야 합니다.

스크롤 표시는 `useScrollOverflow` 훅과 `ScrollHint` 컴포넌트로 편집기·뷰어가 함께 씁니다. `ResizeObserver` 로 내용 높이 변화를 관찰하고, 그 API 가 없는 환경에서는 스크롤 이벤트만 봅니다. 표시가 안 뜰 뿐 화면은 그대로 동작합니다.

만드는 동안 결함 셋을 실측으로 잡았습니다. ①호출부가 감싸는 Box 에 높이 상한을 주는 경우가 많아, 뷰어 요소에 붙인 관찰이 스크롤 주체를 놓쳤습니다. 자신부터 위로 올라가며 찾되 **우리 내용이 그 상자보다 클 때만** 인정합니다. 조건 없이 올라가면 페이지 스크롤을 우리 것으로 읽어, 짧은 스텝 편집기에도 표시가 붙었습니다 ②편집기 본문에 패딩이 없어 마지막 문단의 아래 여백이 밖으로 새어 나와 스크롤 높이에 더해졌습니다. 한 줄뿐인데도 상자가 정확히 5px 넘쳤습니다(171 대 166) ③표시를 음수 마진으로 올리려 했더니 마진이 먹지 않아 스크롤 상자 밖으로 잘려 나갔습니다(칩 1020~1040, 상자 하단 1014). 절대 위치로 그립니다.

진행 중 표시는 `inProgressPulse.js` 의 `isInProgressStatus` 와 sx 두 벌을 다섯 화면이 함께 씁니다. 서버가 `IN_PROGRESS` 와 `INPROGRESS` 두 표기를 함께 쓰므로 대소문자·공백·하이픈을 정규화해 둘 다 받습니다. 색상 값은 하드코딩하지 않고 `warning`·`success`·`default` 토큰만 지정합니다.

아이콘 크기는 `common/iconSizes.js` 의 `CHROME_ICON_SX` 한 곳에서 정합니다. 화면마다 따로 적으면 다시 어긋납니다.

트리 표시 모드 판정은 `TestCaseTree/treeViewMode.js` 로 뽑았습니다. 컴포넌트 안에 두면 기본값을 확인하려고 트리 전체를 띄워야 해서, 기본값이 다시 뒤집히는 것을 시험으로 막기 어렵습니다.

RAG 서비스 이미지 태그를 `RAG_SERVICE_IMAGE_TAG` 로 뺐고 기본값은 `latest` 입니다. 새 이미지를 쓸 때는 `docker compose pull rag-service` 를 먼저 돌립니다. 로컬 `latest` 태그는 저절로 갱신되지 않아, 받지 않고 띄우면 예전 판이 그대로 뜹니다.
