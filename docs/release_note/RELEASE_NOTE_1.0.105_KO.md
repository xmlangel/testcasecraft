# Release Note - v1.0.105

## [1.0.105] - 2026-08-07

작성: 2026-08-07 21:00 KST

결과 입력 화면에서 태그나 JIRA 이슈 키를 적을 때 N·P·F·B 가 글자로 들어가지 않고 판정 단축키로 먹히던 문제를 고쳤습니다. 글자만 사라진 것이 아니라 판정이 바뀌고 그대로 저장까지 됐습니다.

### 주요 변경 사항

#### 🐞 버그 수정

* **태그·JIRA 이슈 키 칸에서 N·P·F·B 가 입력되지 않던 문제**: 이 네 글자는 결과 판정 단축키입니다(N 미수행, P 통과, F 실패, B 차단). 화면 전체에 걸린 단축키가 여러 줄 입력(메모)에서만 물러나고 한 줄 입력에서는 그대로 동작해, 태그와 이슈 키 칸의 글자를 가로챘습니다.
  * 태그에 `Pass` 를 적으면 P 에서 판정이 통과로 바뀌고 곧바로 저장되며 성공 알림이 떴습니다. 원하지 않은 판정이 기록되는 경로였습니다.
  * 이제 글자를 치는 동안에는 단축키가 물러납니다. 한 줄 입력·여러 줄 입력·선택 목록·자동완성 칸이 모두 해당합니다.
  * 자동완성 목록을 펼친 상태에서 항목을 찾으려고 치는 글자도 지킵니다. 목록이 열리면 포커스가 항목으로 옮겨 가는데, 그 자리도 글자를 받는 곳으로 다룹니다.
  * 체크박스·라디오처럼 글자를 받지 않는 곳에 포커스가 있을 때는 단축키가 그대로 동작합니다.

* **태그 칸의 Enter 가 저장으로 넘어가던 문제**: 태그를 확정하거나 자동완성 목록에서 항목을 고르려고 누른 Enter 가 결과 저장으로 처리됐습니다. 같은 원인이며 함께 해결됐습니다.

* **버튼 위에서 누른 Enter 가 저장으로 넘어가던 문제**: 태그 옆의 삭제 버튼이나 닫기 버튼에 포커스를 두고 Enter 를 눌러도 그 동작 대신 결과가 저장됐습니다. 이제 버튼·링크 위에서는 단축키가 물러나 그 버튼이 눌립니다.

* **판정 키를 누른 채로 두면 저장이 연달아 나가던 문제**: 키보드 자동 반복이 매번 저장 요청을 일으켰습니다. 이제 누르고 있어도 한 번만 저장합니다.

### 내부 정리

* 단축키의 포커스 판정을 한곳(`useResultShortcuts`)으로 모았습니다. 화면마다 조건을 다시 조합하던 구조가 이번 문제의 원인이었고, 조합할 자리를 없애 같은 누락이 재발하지 않게 했습니다. 동작에 바뀐 점은 없습니다.

### 업그레이드 안내

* DB 마이그레이션 스크립트는 없습니다. 스키마 변경도 없습니다.
* 신규 i18n 키는 없습니다.
* 단축키 자체는 그대로입니다. 판정을 바꾸려면 입력 칸 밖을 클릭한 뒤 누르면 됩니다.
