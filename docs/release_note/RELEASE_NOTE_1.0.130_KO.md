# Release Note - v1.0.130

## [1.0.130] - 2026-10-19

작성: 2026-10-19 23:58 KST
최종 갱신: 2026-10-20 00:05 KST

요구사항이 들어 있는 프로젝트를 강제 삭제하면 `409 DATA_CONFLICT` 로 실패하던 문제를 고쳤습니다. 데이터베이스의 테이블과 컬럼에는 설명(`COMMENT`)을 붙이고, 한국어·영어 데이터 사전을 함께 제공합니다.

### 주요 변경 사항

#### 프로젝트 강제 삭제가 모든 데이터를 지웁니다

강제 삭제(`DELETE /api/projects/{id}?force=true`)는 지울 테이블 목록을 따로 들고 있었는데, 그 목록이 만들어진 뒤에 추가된 기능의 테이블이 빠져 있었습니다. 빠진 테이블은 두 갈래로 문제를 일으켰습니다.

| 증상 | 해당 데이터 |
|---|---|
| 삭제가 409 로 실패 | 요구사항·요구사항 문서, 탐색 세션·차터, 북마크, 그룹, RAG 카테고리, 케이스 첨부·표시 ID 이력, 결과 수정 이력 |
| 삭제는 되지만 데이터가 남음 | JUnit 결과, 요구사항 연결·관계, 케이스 버전, 이동 감사 로그, 에이전트 연결 |

이번 버전부터는 위 데이터를 모두 함께 지운 뒤 프로젝트를 삭제합니다. 다른 프로젝트의 데이터는 건드리지 않습니다.

**영향:** 지금까지 요구사항이 있어 지울 수 없던 프로젝트도 화면이나 API 에서 바로 지울 수 있습니다. 강제 삭제는 되돌릴 수 없으니 지우기 전에 프로젝트를 다시 확인해 주세요.

#### 데이터베이스 테이블과 컬럼에 설명이 붙습니다

지금까지 데이터베이스의 테이블·컬럼에는 설명이 하나도 없었습니다. 이번 버전부터 테이블 68개와 컬럼 650개 전부에 ISO/IEC 11179 기준의 한국어 설명이 붙습니다. DB 도구에서 테이블이나 컬럼을 열면 `명칭: 정의` 형식의 설명이 보이고, 코드 값을 저장하는 컬럼은 허용되는 값도 함께 적혀 있습니다.

| 파일 | 내용 |
|---|---|
| `db/comments/data-dictionary.csv` | 테이블·컬럼마다 한 행. 한국어·영어 명칭과 정의, 값 영역이 별도 열 |
| `db/comments/db-comments.sql` | 운영 DB 에 적용할 `COMMENT ON` 718줄 |
| `docs/database/DB_COMMENT_CONVENTION.md` | 설명 작성 규칙 |

서버가 시작할 때 현재 DB 의 설명을 위 SQL 과 비교해, 다른 대상에만 설명을 적용합니다. 이미 운영 중인 DB 도 이 버전으로 재배포하면 설명이 채워지며, SQL 을 따로 실행하지 않아도 됩니다. 적용에 실패해도 경고만 남기고 서버는 정상으로 시작합니다.

**영향:** 설명만 바뀌고 데이터와 스키마는 바뀌지 않습니다. 시작할 때의 설명 적용을 끄려면 `app.db-comments.sync.enabled=false` 를 설정합니다.

### 업그레이드할 때

- 데이터베이스 변경이나 따로 실행할 스크립트는 없습니다.
- 환경변수와 설정 파일은 바꾸지 않아도 됩니다.
- 이전 버전에서 강제 삭제로 지운 프로젝트의 남은 행(JUnit 결과 등)은 이번 버전이 정리하지 않습니다.

### 확인한 범위

- 두 변경이 모두 들어간 dev 에서 백엔드 테스트를 다시 돌렸습니다: 109개 클래스 807건 통과, 실패·오류 0.
- 데이터베이스의 외래 키를 읽어 프로젝트에 연결된 테이블이 삭제 목록에 빠짐없이 들어 있는지 확인하는 테스트를 추가했습니다. 이 테스트는 수정 전 코드에서 실패했습니다. 앞으로 프로젝트에 딸린 테이블을 새로 만들고 삭제 목록에 넣지 않으면 이 테스트가 실패합니다.
- 설명 적용 기능을 실제 PostgreSQL 두 곳에 실행했고, 처음 실행에서 16건을 고쳤으며 다시 실행했을 때는 고친 항목이 없었습니다. 서버를 띄우는 과정에서 동작하는지는 확인하지 않았습니다.
- 한국어·영어 설명 718개는 표본 검토와 규칙 검사로 점검했고, 전부를 한 줄씩 읽지는 않았습니다.
- 실제 서버에서 요구사항이 든 프로젝트를 화면으로 지워 보는 확인은 하지 않았습니다.
