# Release Note - v1.0.126

## [1.0.126] - 2026-09-08

작성: 2026-09-08 22:10 KST

자연어로 쓴 테스트 케이스를 LLM 이 읽고 브라우저를 조작해 수행하는 외부 QA 에이전트를 제품에 연결했습니다. 에이전트는 제품 밖에서 도는 별도 스택이고, 제품에는 프로젝트별 연동 설정과 결과를 받는 자리만 생깁니다.

### 주요 변경 사항

#### 프로젝트마다 에이전트를 연결합니다

프로젝트 설정에 「에이전트 연동」 탭이 생깁니다. 에이전트 주소·인증 토큰·기본 프로필을 넣고 연결을 확인한 뒤, 이 프로젝트에서 쓸지 정합니다.

**기본은 꺼짐입니다.** 켠다고 무엇이 실행되지는 않습니다. 에이전트는 제품과 별개로 도는 스택이라 그쪽 컨테이너를 띄워야 합니다. 토글을 켜면 그 사실을 화면이 알려 줍니다.

칸마다 무엇을 넣는지 적었습니다. 주소를 두 칸으로 나눈 이유도 함께 적었습니다. 이 두 칸에서 설정을 자주 틀립니다. 제품도 컨테이너라 `localhost` 는 자기 자신을 가리키고, 반대로 `host.docker.internal` 은 컨테이너 안에서만 풀려 사람의 브라우저는 알지 못합니다. 두 칸 중 하나만 맞추면 서버는 붙는데 실행 단추가 열리지 않거나, 단추는 열리는데 연결 확인이 실패합니다.

**영향:** 연동을 쓰지 않는 프로젝트는 이전과 같습니다. 조직 차원에서 기능을 막으려면 `AGENT_INTEGRATION_ENABLED=false` 로 덮습니다.

#### 에이전트가 남긴 화면을 대시보드에서 봅니다

에이전트가 올린 결과는 자동화 테스트 결과로 들어갑니다. 사람이 만든 실행과 섞이지 않게 실행명에 `[AI]` 가 붙고 태그가 `ai-agent` 이며 총평 첫 줄에 초안이라고 적힙니다.

케이스마다 **첨부 층**을 새로 만들어 실행 중 남은 화면을 붙입니다. 목록에서 미리보기로 열고, 스텝 타임라인에서는 그 스텝 자리에 바로 보입니다. JSON 으로 남는 값은 접었다 펴는 구조 보기로 읽습니다.

**영향:** 실패한 케이스에만 마지막 화면 세 장이 붙습니다. 통과한 케이스에는 붙이지 않아 저장소를 아낍니다.

#### 테스트 플랜 없는 실행의 집계가 0 으로 고정되던 결함

테스트 플랜을 지정하지 않고 만든 실행은 진척률과 판정 개수가 모두 0 으로 남았습니다. 실제로는 케이스를 수행했고 결과도 저장돼 있었는데 화면에만 반영되지 않았습니다.

**영향:** 기존 실행도 다시 열면 올바른 값이 나옵니다.

#### 서버가 뜨는 동안 영문 오류 대신 안내 화면을 냅니다

재기동하는 30초에서 1분 동안 아무도 응답하지 않으면 앞단이 영문 502 화면을 대신 냈습니다. 그 화면은 무엇을 기다려야 하는지, 언제 다시 오면 되는지 알려 주지 않습니다.

앞단에 게이트웨이를 두어 그 동안에도 계속 응답합니다. 오류 코드(502 Bad Gateway)를 함께 보여 주면서, 일시적인 문제일 수 있고 잠시 후 다시 시도하면 되며 같은 화면이 이어지면 서버 관리자에게 연락하라고 안내합니다. 화면은 15초마다 저절로 새로 고쳐지고, 브라우저에 저장된 언어 설정에 따라 한국어와 영어 중 하나만 나옵니다.

**영향:** 앞단(터널·프록시)이 보던 포트를 게이트웨이가 그대로 이어받으므로 서버 쪽 설정은 바꾸지 않아도 됩니다.

### 확인한 범위

- 프로젝트 설정에서 연동을 켜고 끄는 동작과 연결 확인을 실제 에이전트로 확인했습니다.
- 에이전트로 회차를 돌려 자동화 대시보드에서 그 결과와 첨부한 화면을 확인했습니다.
- 앱을 세운 상태에서 502 안내 화면이 나오고, 다시 켜니 9초 만에 정상 화면으로 돌아오는 것을 확인했습니다.
- 안내 문구는 기동할 때 자동으로 정정됩니다. 번역을 직접 고쳐 쓰던 곳은 그 값이 유지됩니다.
