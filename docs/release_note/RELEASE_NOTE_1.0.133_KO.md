# Release Note - v1.0.133

## [1.0.133] - 2026-10-26

작성: 2026-10-26 08:30 KST

1.0.132 이후 `dev` 에 들어온 변경 아홉 건을 묶었습니다. 일곱 건은 보안 수정으로, API 키 인증 주체를 발급자로 바꾸고 인증 없이 열려 있던 API 와 프로젝트 소속 검사가 빠진 조회 API 를 막았습니다. 나머지 두 건은 테스트케이스 버전 기록의 작성자와 세로 모드 실행 삭제를 고쳤습니다.

### 주요 변경 사항

#### API 키가 발급한 사용자의 계정과 역할로 인증됩니다

지금까지는 어떤 API 키로 호출하든 가상 계정 `service-account`(TESTER 역할)로 인증됐습니다. 그래서 누가 호출했는지 기록에 남지 않았고, 키로 만든 데이터의 작성자도 `service-account` 로 남았습니다. 이번 버전부터는 키를 발급한 사용자로 인증하고 그 사용자의 역할로 권한을 판정합니다.

- 발급자가 비어 있거나, 계정이 없거나, 비활성이면 401 을 돌려줍니다.
- 지라 연동의 임시 토큰 교환도 발급자 계정으로 토큰을 만듭니다.
- 관리자 화면에서 발급한 키는 발급자를 `admin` 으로 고정하지 않고 실제로 발급한 관리자로 기록합니다.
- 회원가입에서 `service-account` 로 시작하는 사용자명(대소문자와 앞 공백은 무시)을 거부합니다. 같은 이름의 계정이 새로 생겨 예전 인증 주체처럼 보이는 일을 막습니다.

**영향:** 키로 남긴 작업 기록과 작성자가 실제 사용자로 남습니다. 키 권한은 발급자 역할을 따르므로, TESTER 보다 낮은 역할의 사용자가 발급한 키는 할 수 있는 일이 줄어듭니다.

#### 인증 없이 열려 있던 API 를 잠갔습니다

로그인 전 화면이 쓰는 설정·언어·번역·매뉴얼·가이드 조회만 공개로 남겼습니다.

- 모니터링과 스케줄러 조회, 번역 캐시 비우기, `/api/config/environment` 는 관리자만 부를 수 있습니다.
- 방문 기록과 나머지 설정·번역 API 는 로그인한 사용자만 부를 수 있습니다.
- 공개 응답인 `/api/config` 에서 실행 profile 을 뺐습니다.
- 토큰 없이 요청하던 관리자 화면 네 곳이 로그인 토큰을 싣고 요청합니다.

#### 프로젝트 데이터 조회에 소속 검사를 붙였습니다

테스트케이스 버전과 결과 조회, 내보내기, 리포트, 수정 이력, 대시보드, JUnit 결과, 차터 조회, RAG 검색, 결과 첨부파일 조회가 이제 요청한 사용자가 그 프로젝트에 속하는지 확인합니다.

- ID 하나로 조회하면 그 대상이 속한 프로젝트를 찾아 검사합니다.
- 결과 조회는 projectId 와 함께 넘어온 플랜·실행 ID 도 모두 검사합니다. 자기 프로젝트 ID 에 다른 프로젝트의 실행 ID 를 붙여 조회할 수 없습니다.
- 범위를 정하지 않은 전체 조회는 관리자만 할 수 있습니다. 프로젝트를 고르지 않은 대시보드는 접근할 수 있는 프로젝트로 범위를 좁힙니다.

#### projectId 가 비거나 다른 프로젝트여도 저장·수정 권한을 검사합니다

- 테스트케이스 일괄 저장에 projectId 가 빈 항목이 있으면 묶음 전체를 거부합니다.
- 일괄 저장과 단건 수정은 DB 에 저장된 케이스의 프로젝트로도 편집 권한을 검사합니다.
- 테스트 플랜 수정은 저장된 플랜의 프로젝트로 권한을 검사하고, 요청에 다른 projectId 가 들어 있으면 무시합니다.
- 일괄 저장 API 는 거부할 때 500 대신 400 또는 403 을 돌려줍니다.

#### 차터와 LLM 호출 API 에 권한 검사와 호출 횟수 제한을 두었습니다

- 차터를 만들려면 대상 프로젝트에서 테스트 세션을 진행할 수 있는 역할(TESTER 포함)이어야 합니다. 수정도 차터가 속한 프로젝트에서 같은 권한을 요구합니다.
- 차터 작성자는 요청 본문 값이 아니라 로그인한 사용자로 남습니다.
- AI 메타 생성은 그 프로젝트의 편집 권한을, RAG 고급 검색은 projectId 가 있으면 그 프로젝트의 접근 권한을 요구합니다.
- AI 메타 생성, 채팅 모델 목록, RAG 고급 검색은 사용자마다 분당 20회로 제한합니다. 넘으면 429 를 돌려줍니다.

#### 범용 메일 발송 API 를 없앴습니다

`POST /api/mail/send` 는 TESTER 권한만 있으면 발신자·수신자·제목·본문을 요청에서 그대로 받아 회사 SMTP 로 보냈습니다. 화면, 지라 앱, MCP 서버 어디에서도 부르지 않아 엔드포인트를 지웠습니다. 이메일 인증, 비밀번호 재설정, 관리자 메일 설정의 시험 발송은 다른 경로를 쓰므로 그대로 동작합니다.

#### 테스트케이스 버전 기록에 실제 작업자가 남습니다

버전 기록은 비동기로 만들어지는데, 그 시점에는 로그인 정보를 알 수 없어 작성자가 모두 `System User` 로 저장됐습니다. 이번 버전부터는 변경을 요청한 사용자의 표시 이름을 작성자로 저장합니다. 로그인 없이 일어난 변경만 `System User` 로 저장합니다. 이미 저장된 기록은 바뀌지 않습니다.

#### 세로 모드 실행 목록에서 실행을 지울 수 있습니다

세로 모드에서는 실행을 지울 버튼이 없었습니다. 실행 영역 목록과 플랜 트리 아래 실행 행에 삭제 버튼을 넣었고, 확인 창 문구와 버튼을 보여 주는 권한 기준은 가로 모드와 같습니다. 열어 둔 실행을 지우면 상세 화면도 닫힙니다. 삭제에 실패하면 확인 창에 이유를 보여 주고 목록은 그대로 둡니다.

### 업그레이드할 때

- 로그인 없이 `/api/monitoring/*`, 스케줄러 조회, `/api/config/environment` 를 부르던 감시 도구나 스크립트는 401 또는 403 을 받습니다. 관리자 계정의 토큰이나 API 키를 쓰도록 바꿔야 합니다.
- 발급자 계정이 지워졌거나 비활성인 API 키는 더 이상 쓸 수 없습니다. 배포 전에 쓰고 있는 키의 발급자를 확인해 주세요.
- `POST /api/mail/send` 를 부르던 외부 도구가 있으면 그 호출은 실패합니다. 저장소 안에서는 호출하는 곳을 찾지 못했습니다.
- LLM 호출 횟수 제한은 `app.ratelimit.llm.limit-per-minute` 로 바꿀 수 있습니다. 기본값은 20 입니다.
- DB 스키마는 바뀌지 않습니다.

### 확인한 범위

- 아홉 건이 모두 합쳐진 `dev` 에서 백엔드 테스트 900건이 모두 통과했습니다. 프론트엔드 테스트는 화면을 고친 브랜치에서 757건이 통과했습니다.
- 접근 규칙 테스트, 프로젝트 소속·비소속 통합 테스트, 삭제한 메일 경로가 다시 생기지 않는지 확인하는 회귀 테스트를 추가했습니다.
- 실제 서버와 브라우저에서는 확인하지 않았습니다. 특히 프로젝트를 고르지 않은 통계 화면, 세로 모드 삭제 버튼, API 키로 호출한 작업의 작성자 표시는 배포한 뒤 확인이 필요합니다.

### 알려진 문제

- 1.0.132 에 적은 두 문제(조직 멤버가 아닌 사용자의 프로젝트 카드 403, 인증 메일 재요청 시 앞선 요청 결과의 경고)는 이번 버전에서 고치지 않았습니다.
