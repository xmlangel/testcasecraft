# Release Note - v1.0.116

## [1.0.116] - 2026-08-21

작성: 2026-08-21 23:17 KST

관리자 화면에서 막히던 두 가지를 고쳤습니다. 암호화 키가 없어 LLM 설정을 저장하지 못할 때 무엇을 해야 하는지 화면에서 알려 주고, 테스트 케이스 수에 폴더가 섞여 들어가던 문제를 바로잡았습니다.

### 주요 변경 사항

#### 🔑 암호화 키가 없을 때 해결 절차를 화면에서 안내

LLM 설정에서 연결 테스트를 누르면 이렇게 끝났습니다.

```
연결 테스트 실패: 암호화 키가 설정되지 않았습니다. 관리자에게 문의하세요.
```

관리자 본인이 이 화면을 보고 있는데 문의할 곳을 알려 주는 문장이라, 다음에 무엇을 할지 판단할 근거가 없었습니다. 운영 환경은 저장소에 담긴 기본 키를 쓰지 않으므로 `JIRA_ENCRYPTION_KEY` 를 넣지 않으면 반드시 이 상태가 됩니다.

이제 에러 아래에 해결 절차가 함께 뜹니다. 펼치면 키를 만드는 명령과 환경변수 줄을 복사할 수 있고, 키를 바꾸면 이미 저장한 값을 읽지 못한다는 경고도 함께 보여 줍니다.

| 단계 | 안내 내용 |
|---|---|
| 1 | 키 생성 명령 (`openssl rand -base64 32`) |
| 2 | 환경변수 지정. Docker Compose 는 `.env` 와 `docker-compose.yml` 양쪽에 넣어야 컨테이너까지 전달됩니다 |
| 3 | 애플리케이션 재시작 후 연결 테스트 재실행 |

화면은 에러 문구가 아니라 서버가 함께 내려주는 코드로 원인을 판정합니다. 문구를 다듬거나 영어로 옮겨도 판정이 그대로 유지됩니다.

**설정을 수정하는 경로에는 키 확인이 없어서** API Key 를 갈아 끼울 때 나는 오류가 원인 표시 없이 500 으로 올라가고 있었습니다. 생성·수정·연결 테스트 세 경로를 같은 기준으로 맞췄습니다. **저장이 실패해도 화면에 아무것도 뜨지 않던 문제**도 함께 고쳤습니다.

#### 📁 테스트 케이스 수에서 폴더 제외

AI 어시스턴트에게 물으면 폴더 1개와 테스트 케이스 1개가 있는 프로젝트를 두고 "총 2개의 테스트 케이스가 있습니다"라고 답했습니다.

폴더와 테스트 케이스가 같은 테이블에 나란히 저장되는데, 통계를 낼 때 둘을 가르지 않고 세고 있었습니다. 집계 네 곳(총계·상태별·결과별·우선순위별)에 구분 조건을 넣고, 폴더 수는 별도 항목으로 함께 내려주도록 바꿨습니다.

| 프로젝트 | 이전 | 이후 |
|---|---|---|
| ShopFlow | 120 | 케이스 108 + 폴더 12 |
| ShopFlow EN | 120 | 케이스 108 + 폴더 12 |
| QA팀 모바일 앱 테스트 | 105 | 케이스 100 + 폴더 5 |

미실행 건수도 함께 어긋나 있었습니다. ShopFlow 기준 37건에서 25건으로 바로잡혔고, 실행 결과가 있는 항목(통과·실패·차단)은 변하지 않았습니다. 폴더는 실행 대상이 아니어서 애초에 결과가 없었기 때문입니다. 바로잡은 뒤 상태별 합계가 총계와 정확히 맞습니다.

AI 어시스턴트는 이제 케이스와 폴더를 갈라서 답하고, 대시보드에도 폴더 개수 표시가 붙습니다. 폴더가 없는 프로젝트에서는 이 표시가 나오지 않습니다.

**순번으로는 폴더를 가려낼 수 없습니다.** 처음에는 이 저장소가 다른 곳에서 쓰던 기준을 재사용했습니다. 폴더 29개 가운데 24개가 이미 순번을 갖고 있어 ShopFlow 는 120 에서 내려가지 않았습니다. 이 함정을 회귀 테스트로 남겼습니다.

### 업그레이드 안내

* DB 마이그레이션 스크립트는 없습니다. 스키마 변경도 없습니다.
* **대시보드 숫자가 줄어 보입니다.** 폴더가 총계에서 빠지기 때문이며 데이터가 사라진 것이 아닙니다. 폴더 개수는 옆에 따로 표시됩니다.
* **영어 문구는 재시작 후에 반영됩니다.** 한국어는 즉시 보입니다.
* 이 버전이 `JIRA_ENCRYPTION_KEY` 를 대신 설정해 주지는 않습니다. 값이 없으면 안내가 뜰 뿐이므로, LLM 기능을 쓰려면 배포 환경에 키를 넣어야 합니다.
* **키를 새로 넣거나 바꾸기 전에 확인하세요.** 이미 저장한 LLM API Key 와 JIRA 토큰은 기존 키로 암호화되어 있어, 키가 바뀌면 다시 입력해야 합니다.
* 1.0.115 변경은 [RELEASE_NOTE_1.0.115_KO.md](RELEASE_NOTE_1.0.115_KO.md)를 참고하세요.
