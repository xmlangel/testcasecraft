# Release Note - v1.0.113

## [1.0.113] - 2026-08-20

작성: 2026-08-20 01:20 KST

프로젝트 역할을 화면에서 지정할 수 있습니다. 지금까지는 매뉴얼 18-4 의 역할 여섯 종이 API 로만 부여됐습니다. 함께 조회 전용 역할이 실제로 조회만 되도록 인가를 조였습니다. 프로젝트 멤버가 아닌 사용자가 남의 테스트케이스를 덮어쓸 수 있던 경로가 닫힙니다.

### 주요 변경 사항

#### 🔐 프로젝트 설정 화면 신설 — 사용자별 역할 부여

* **진입**: 프로젝트 화면 상단 우측 톱니 아이콘, 주소는 `/projects/{projectId}/settings` 입니다. 톱니는 프로젝트 매니저·리드 개발자·시스템 관리자에게만 보입니다.
* **일반 탭**: 프로젝트 이름·설명·정렬 순서를 바꿉니다. 코드는 생성 후 바꿀 수 없습니다. 프로젝트 매니저와 시스템 관리자에게만 탭이 보입니다.
* **멤버 탭**: 사용자를 검색해 추가하고, 역할 드롭다운으로 바꾸고, 제거합니다. 역할은 고르는 즉시 적용되며 저장 버튼이 없습니다. 마지막 남은 프로젝트 매니저는 역할을 바꾸거나 제거할 수 없습니다.
* **사용자 검색**: 두 글자부터 사용자명·이름·이메일로 찾고 최대 20명까지 보여 줍니다. 이미 멤버인 사람과 비활성 계정은 결과에서 빠지므로, 고른 뒤 추가가 중복으로 실패하지 않습니다. 조직 관리의 멤버 초대도 같은 검색을 사용합니다.
* **레이아웃**: 전역 헤더·브레드크럼·좌측 영역 메뉴를 그대로 두고 본문만 채웁니다.

#### 🛡️ 인가 정리 — 조회 전용 역할이 실제로 조회만 됩니다

* **인증만으로 열려 있던 경로**: 케이스 버전 복원·수동 생성·정리 네 개와 탐색 세션 쓰기 열 개에 프로젝트 역할 검사가 없었습니다. 버전 복원은 케이스 본문을 그 버전으로 덮어쓰므로, 로그인만 한 사용자가 프로젝트 멤버가 아니어도 남의 케이스를 바꿀 수 있었습니다.
* **읽기 권한으로 쓰기를 막던 자리 26개**: `canUploadToProject` 의 정의가 `canAccessProject`(읽기)였습니다. JUnit 결과 업로드·삭제, RAG 문서 업로드·삭제·분석, 케이스·결과 첨부 업로드, 결과 편집본 CRUD 가 조회 전용 역할에게 열려 있었습니다. 결과 기록 권한과 편집 권한으로 나눠 조였습니다.
* **시스템 역할로 판정하던 자리**: 탐색 세션 API 열두 개가 시스템 역할(ADMIN·MANAGER·TESTER·USER)만 봐서 프로젝트 역할을 무시했습니다. 프로젝트 뷰어라도 시스템 테스터면 세션을 만들고 상태를 바꿀 수 있었습니다.
* **탐색 세션 삭제**: 진행 권한에서 리드 이상으로 좁혔습니다. 세션은 여러 사람이 함께 보는 기록이라, 진행할 수 있는 사람이 남의 기록까지 지울 수 있으면 안 됩니다.
* **프로젝트 설정 변경**: 매뉴얼 18-4 대로 프로젝트 매니저와 시스템 관리자로 한정했습니다. 이전에는 리드 개발자와 조직 관리자도 통과했습니다.

#### 🙈 권한이 없으면 노출 자체를 하지 않습니다

* **신규 레이아웃(좌측 메뉴)이 통째로 열려 있었습니다**: 플랜·실행 작업공간에 역할 검사가 없어, 조회 전용 역할에도 「실행 만들기」와 폼 저장이 보였습니다. 서버는 막았으므로 눌러도 403 이었지만, 눌러 보고 실패해야 권한이 없다는 것을 알 수 있었습니다.
* **판정 축이 틀린 자리**: 테스트 플랜 목록이 시스템 역할로 버튼을 감춰, 프로젝트 매니저에게 안 보이고 프로젝트 뷰어인 시스템 매니저에게 보였습니다. 프로젝트 역할 기준으로 바꿨습니다.
* **트리 컨텍스트 메뉴**: 추가·삭제는 감쌌는데 이름 변경만 빠져 있었습니다.
* **자동화·RAG·탐색 세션**: 업로드·삭제·생성 입구를 각 백엔드 기준과 같은 역할로 가립니다. RAG 문서 목록의 빈 상태 안내에 있던 업로드 버튼과 탐색 세션의 차터 생성도 함께 가립니다.
* **스프레드시트 입력 모드**: 편집 권한이 없으면 입력 모드 토글을 내보내지 않습니다. 개별 폼만 남습니다. 이미 스프레드시트 모드로 들어와 있으면 개별 폼으로 되돌립니다.
* **케이스 화면**: 새 케이스 추가, 첨부 파일 업로드, 폴더 정보 편집 입구를 조회 전용 역할에서 감춥니다.
* **Tooltip 에 숨김을 걸면 동작하지 않습니다**: Tooltip 은 자기 DOM 을 만들지 않고 자식에게 props 만 넘기므로 `display:none` 이 어디에도 적용되지 않습니다. 탐색 세션 삭제 버튼이 이 방식이어서 조회 전용 역할에게 그대로 보였습니다. 조건부 렌더로 바꿨습니다.

#### 🧪 기동이 깨지던 문제

* `data-test.sql` 이 테스트케이스를 넣으며 낙관적 락 컬럼(`version`)을 빼먹어, 기동 직후 도는 Display ID 마이그레이션이 그 행을 수정하다 flush 에서 터졌습니다. 그 예외가 ApplicationContext 로딩을 깨뜨려 보안 테스트 두 클래스가 통째로 실패하고 있었습니다.
* 시드에 값을 넣고, 기동할 때 `version` 이 비어 있는 행을 0 으로 채우는 단계를 뒀습니다. SQL 로 직접 넣은 행은 어디서든 이 컬럼을 빠뜨릴 수 있고, 그러면 운영에서도 앱이 뜨지 않습니다.

#### 🌱 로컬 샘플셋이 역할 확인 계정을 함께 만듭니다

* ShopFlow 시드가 `pm`·`lead`·`contributor`·`viewer` 넷을 더 만들어 프로젝트 역할 여섯 종을 모두 덮습니다. 네 계정은 시스템 역할을 모두 `TESTER` 로 같게 두고 프로젝트 역할만 달리합니다. 두 축이 같이 달라지면 어느 축 때문에 막혔는지 구분할 수 없습니다.
* 계정이 이미 있고 로그인만 실패하면 관리자 권한으로 비밀번호를 문서값으로 되맞춥니다. 이전에는 "백엔드에서 직접 수정 필요" 로 끝나 그 계정으로는 아무것도 못 했습니다.
* `07_verify.py` 가 실제 멤버 역할을 계정 표와 대조하고 어긋난 계정을 밝힙니다.

#### 🔧 관리자 비밀번호 변경 400 오류

* 관리자가 다른 사용자의 비밀번호를 바꿀 때 「현재 비밀번호 확인 생략」을 켜면 `유효하지 않은 요청 데이터: [currentPassword] 공백일 수 없습니다` 로 막혔습니다. 요청 DTO 가 그 값을 필수로 강제하고 있었습니다. 본인 변경 경로는 컨트롤러와 서비스가 각각 필수 여부를 검사하므로 영향이 없습니다.

### 업그레이드 안내

* DB 마이그레이션 스크립트는 없습니다. 스키마 변경도 없습니다.
* 기동할 때 `testcases.version` 이 비어 있는 행을 0 으로 채웁니다. 실패해도 기동을 막지 않고 경고만 기록합니다.
* 신규 i18n 키는 39개입니다(`projectSettings.*` 34, `memberSearch.*` 5). 한국어·영어 모두 시드됩니다.
* **권한이 좁아진 동작이 있습니다.** 아래 세 가지는 이전 버전에서 통과했다면 이번 버전에서 403 이 됩니다.
  * 프로젝트 설정 변경: 리드 개발자·조직 관리자 → 프로젝트 매니저·시스템 관리자만
  * 탐색 세션 삭제·승인: 시스템 테스터·매니저 → 그 프로젝트의 리드 이상
  * JUnit 업로드·삭제, RAG 문서 변경, 첨부 업로드: 프로젝트 접근 권한 → 결과 기록·편집 권한
* API 키로 JUnit 결과를 올리는 경로는 이번에 확인하지 못했습니다. API 키 인증이 사용자명을 `service-account` 로 고정하는데 그 이름은 users 테이블에 없어, 이전 버전에서도 프로젝트 권한 검사를 통과하지 못합니다. 회귀는 아니지만 그 경로가 실제로 어떻게 동작하는지 확인이 필요합니다.
* 브라우저에 옛 화면이 캐시돼 있으면 강제 새로고침(⌘⇧R / Ctrl+F5)이 필요합니다.
* 1.0.112 변경은 [RELEASE_NOTE_1.0.112_KO.md](RELEASE_NOTE_1.0.112_KO.md)를 참고하세요.
