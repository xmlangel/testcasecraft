# Release Note - v1.0.115

## [1.0.115] - 2026-08-21

작성: 2026-08-21 01:20 KST

화면이 뜨는 속도를 고쳤습니다. 정적 자산 전송량이 2,449KB 에서 505KB 로 줄고, 네트워크로 나가는 요청이 22개에서 2개로 줄었습니다. 두 번째 방문부터는 자산을 거의 받지 않습니다.

### 주요 변경 사항

#### 🐢 왜 느렸나

프로덕션 네트워크 기록에서 0.8KB 짜리 청크 하나가 4.06초를 쓰고 있었습니다. 같은 파일을 서버는 4밀리초에 내주므로 처리 속도 문제가 아니었습니다. 응답 헤더가 원인을 갖고 있었습니다.

```
Cache-Control: no-cache, no-store, max-age=0, must-revalidate
Cf-Cache-Status: BYPASS
```

이름에 내용 해시가 붙어 절대 변하지 않는 파일인데도 `no-store` 가 붙어 있어 앞단 CDN 이 캐시를 통째로 건너뜁니다. 화면 하나에 자산 수십 개가 붙으니 그 왕복이 그대로 쌓였습니다. 헤더가 붙은 자리는 두 겹이었습니다. Vite 산출 경로에 자원 핸들러 등록이 아예 없어 캐시 지시가 비어 있었고, 그 자리를 보안 설정의 기본 헤더가 채웠습니다.

#### 🗄️ 캐시 지시를 경로 성격에 맞게

| 경로 | 지시 | 이유 |
|---|---|---|
| 빌드 산출 자산 | 1년, 변경 없음으로 표시 | 이름에 해시가 붙어 내용이 바뀌면 이름도 바뀝니다 |
| 파비콘·매니페스트·로고 | 하루 | 이름이 고정이라 오래 두면 교체가 반영되지 않습니다 |
| `index.html` 과 화면 주소 | 캐시하지 않음 | 이 문서가 캐시되면 새 자산 이름을 가리키는 문서가 갱신되지 않습니다 |
| API 응답 | 캐시하지 않음 | 이전과 같습니다 |

보안 설정은 정적 자산 전용 갈래로 나눠 캐시 금지 헤더만 빼고 나머지 보안 헤더는 그대로 둡니다.

#### 📦 응답 압축을 모든 환경에서

압축이 운영 설정에만 켜져 있었습니다. 운영은 앞단 CDN 이 압축하지만 서버에서 CDN 으로 가는 구간은 압축 없이 나가고 있었고, 개발 환경과 CDN 없는 배포는 압축이 아예 없었습니다. 공통 설정으로 옮겼습니다. 메인 번들이 964KB 에서 259KB 로 줄었습니다.

#### 🧩 청크 수

빌드 결과가 127개로 갈려 있었고 그중 56개가 2KB 미만이었습니다. **56개를 다 합쳐도 17KB 뿐입니다.** 이 크기에서는 파일 내용보다 요청 하나하나의 왕복이 비쌉니다.

작은 조각을 부모에 흡수하도록 바꾸고, 그래도 남은 2KB 미만이 전부 여러 화면이 함께 쓰는 아이콘이어서 아이콘만 한 덩어리로 묶었습니다.

| 항목 | 이전 | 이후 |
|---|---|---|
| 청크 수 | 127 | 67 |
| 2KB 미만 청크 | 56 | 3 |
| 첫 화면 묶음(압축 후) | 231KB | 189KB |
| 아이콘 | 청크 45개에 흩어짐 | 하나로 묶음(압축 후 50KB) |

큰 라이브러리를 손으로 묶는 방식은 쓰지 않았습니다. 이 저장소에서 전에 그렇게 했다가 첫 요청이 3MB 로 늘어난 적이 있습니다. 아이콘은 다른 코드를 끌어오지 않아 그 위험이 없고, 실제로 첫 화면 묶음이 오히려 줄었습니다.

### 업그레이드 안내

* DB 마이그레이션 스크립트는 없습니다. 스키마 변경도 없습니다.
* **배포 직후 첫 방문은 자산을 한 번 받습니다.** 파일 이름이 바뀌었으므로 정상입니다. 그 뒤부터 캐시가 듣습니다.
* 이전 버전에서 이미 방문한 브라우저는 캐시가 비어 있어 한 번은 전부 받습니다.
* CDN 을 쓰는 배포라면 응답 헤더의 캐시 상태 표시가 건너뜀에서 적중으로 바뀌는지 보면 반영 여부를 바로 알 수 있습니다.
* 파비콘·매니페스트·로고는 하루 동안 캐시됩니다. 이 파일들을 교체한 뒤 즉시 반영해야 하면 강제 새로고침(⌘⇧R / Ctrl+F5)이 필요합니다.
* API 응답과 화면 문서는 이전과 같이 캐시되지 않습니다. 인가 동작도 바뀌지 않았습니다.
* 1.0.114 변경은 [RELEASE_NOTE_1.0.114_KO.md](RELEASE_NOTE_1.0.114_KO.md)를 참고하세요.
