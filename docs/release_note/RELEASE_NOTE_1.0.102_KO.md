# Release Note - v1.0.102

## [1.0.102] - 2026-07-31

작성: 2026-07-31 23:55 KST

화면 구조를 고르게 했습니다. 지금까지 쓰던 가로 탭을 그대로 두고, 영역을 화면 왼쪽에 세로로 놓는 새 레이아웃을 함께 넣었습니다. 어느 쪽을 쓸지는 프로필에서 고르며 기본값은 지금과 같은 가로 탭입니다. 새 레이아웃에서는 테스트 플랜과 실행이 팝업이나 전체 화면으로 튀지 않고 한 화면 안에서 이어집니다. 테스트 결과 화면이 뜨는 시간도 줄었습니다 — 결과가 수만 건인 프로젝트에서 5초 넘게 걸리던 조회가 1초 아래로 들어옵니다.

### 주요 변경 사항

#### ✨ 새 기능

* **레이아웃 선택**: 프로필 → 테마 설정 맨 아래 `메뉴 구조`에서 두 가지 중 고릅니다.
  * `현재 레이아웃 — 가로 탭`: 지금까지 쓰던 구조. 기본값이라 아무것도 안 하면 화면이 바뀌지 않습니다.
  * `신규 레이아웃 — 좌측 메뉴`: 대시보드·테스트케이스·테스트 플랜 같은 영역을 왼쪽에 세로로 놓습니다. 영역이 많아도 이름이 잘리지 않고, 접어서 아이콘만 남길 수 있습니다.
  * 고른 값은 계정에 저장돼 다른 PC에서 로그인해도 유지됩니다. 상단 바 아이콘으로도 바로 전환됩니다.
* **프로젝트를 리스트에서 바꾸기**: 새 레이아웃의 위치 표시가 `프로젝트이름 / 대시보드` 형태가 되고, 프로젝트 이름을 누르면 프로젝트 목록이 펼쳐집니다. 목록 페이지로 나갔다 돌아오지 않고 바로 갈아탑니다.
* **플랜 아래 실행이 달리는 트리**: 테스트 플랜 영역의 왼쪽 목록이 트리가 됐습니다. 플랜을 펼치면 그 플랜의 실행이 아래에 붙어, 어느 플랜의 실행인지 목록만 보고 압니다. 이름으로 찾을 때 플랜 이름과 실행 이름을 함께 봅니다.
* **실행 목록에서 상태와 플랜을 함께**: 테스트 실행 영역은 프로젝트의 실행을 최신순으로 세운 목록입니다. 행마다 진행 상태와 그 실행이 속한 플랜 이름이 붙습니다. 이름으로 찾기는 서버에서 검색하므로 목록이 길어도 앞부분만 훑지 않고, 아래쪽 `더 보기`로 이어 받습니다.
* **검색으로 좁힌 뒤 전체 선택**: 테스트케이스 트리에서 검색으로 목록을 좁힌 상태에서 전체 선택을 누르면 화면에 보이는 결과만 선택됩니다. 숨어 있는 케이스까지 선택돼 엉뚱한 것이 일괄 처리되던 일이 없어집니다.

#### ⚡ 속도

* **테스트 결과 조회**: 케이스 1,200 · 결과 48,000건 규모로 재보니 폴더별 통계가 5.7초 → 0.8초, 최신 결과 50건 조회가 5.4초 → 0.3초, 결과 통계가 1.1초 → 0.2초입니다. 한 페이지를 보여주려고 프로젝트의 결과 전체를 메모리에 올려 세던 방식이 원인이었습니다. 이제 최신 결과를 가릴 때는 필요한 컬럼만 읽고, 화면에 나갈 것만 다시 읽습니다. 응답 내용은 그대로입니다 — 같은 요청의 응답을 바꾸기 전후로 대조해 확인했습니다.
* **첫 화면**: 앱 전체가 한 덩어리(6.8MB)로 내려오던 것을 화면별로 나눴습니다. 첫 요청이 733KB로 줄고 나머지는 그 화면을 열 때 받습니다. 처음 여는 화면에서 잠깐 회전 표시가 보일 수 있습니다.
* **플랜 목록의 자동화 개수 조회**: 플랜 수만큼 순서대로 기다리던 요청을 한꺼번에 보냅니다. 플랜이 많은 프로젝트에서 목록이 늦게 채워지던 것이 줄어듭니다.

#### 🔧 동작 변경 (신규 레이아웃에서만)

* **팝업이 없어졌습니다**: 플랜을 고르면 팝업이 화면을 덮는 대신 오른쪽에 내용이 열립니다. 플랜을 오가며 실행을 만들거나 결과를 볼 때 창을 닫고 다시 열 일이 없습니다.
* **실행·결과 입력이 같은 화면 안에서 열립니다**: 실행 상세와 케이스 결과 입력이 상단 바·왼쪽 메뉴가 없는 전체 화면으로 빠지지 않습니다. 어디에 있는지 잃지 않고 목록으로 바로 돌아옵니다.
* **각 단을 접을 수 있습니다**: 상세를 넓게 보려면 왼쪽 목록을 접습니다.

기존 레이아웃(가로 탭)을 쓰시면 팝업·전체 화면 동작이 지금까지와 똑같습니다.

#### 🎨 화면 정리

* 결과 입력 화면과 플랜·실행 화면이 서로 다른 화면처럼 보였습니다. 상세 안에 페이지가 한 겹 더 들어가 있고, 떠 있는 헤더 바가 겹쳐 보이던 것을 걷었습니다.
* 글자 크기·굵기 규격을 한 곳에 모아 두 레이아웃이 같은 값을 쓰게 했습니다. 레이아웃을 바꿔도 글자가 튀지 않습니다.

#### 📖 문서

* 사용자 매뉴얼을 한국어·영문 모두 이번 화면에 맞춰 갱신했습니다 — 레이아웃 선택, 플랜·실행 2단 화면, 트리의 이름·ID·태그 검색, 실행 필터의 태그, 결과 입력 화면의 케이스 첨부. 화면 캡처는 15장을 새로 찍거나 갱신했습니다.

### 업그레이드 안내

* DB 마이그레이션 스크립트는 없습니다. 다만 **첫 기동 때 인덱스 3개가 생성됩니다** — `test_plans(project_id)`, `test_plans(project_id, created_at)`, `test_executions(project_id, created_at)`. 플랜·실행이 아주 많은 데이터베이스라면 기동이 잠깐 길어질 수 있습니다.
* 기본값이 기존 레이아웃이라 업그레이드만으로 사용자 화면이 바뀌지 않습니다. 새 레이아웃은 각자 프로필에서 켭니다.
* 신규 i18n 키 3건(`testPlan.workspace.filterExecution`, `testPlan.workspace.emptyExecutions`, `testPlan.workspace.loadMore`)은 앱 기동 시 한/영 모두 자동 등록됩니다.
* 결과 조회·통계 API의 요청·응답 형식은 그대로입니다. 자동화로 결과를 넣거나 리포트를 받아 쓰는 스크립트는 손댈 것이 없습니다.
* 1.0.101 변경은 [RELEASE_NOTE_1.0.101_KO.md](RELEASE_NOTE_1.0.101_KO.md)를 참고하세요.

### 알려진 사항

* 새 레이아웃에서 `테스트결과` 를 눌러도 주소창이 `/results` 로 바뀌지 않습니다. 기존 레이아웃도 같으며 화면 전환에는 영향이 없습니다. 주소 체계 정리 때 함께 잡습니다.
* 결과 입력 화면에 들어갈 때 이전·다음 케이스 순서를 계산하려고 프로젝트의 케이스 목록을 받아옵니다. 케이스가 많은 프로젝트에서는 이 요청이 큽니다(운영 환경은 응답을 압축해 전송량이 작습니다). 필요한 항목만 주는 조회로 줄이는 일은 다음 판으로 넘겼습니다.
* 케이스가 1,000건을 넘는 플랜의 실행 표는 스크롤이 무거울 수 있습니다. 지금은 50건씩 늘려 그립니다.
* 벤치마크에서 뽑은 나머지 항목(케이스 목록 열, 빠른 생성, 실행 목록에서 결과 바로 지정)은 아직 들어가지 않았습니다.
