# Release Note - v1.0.111

## [1.0.111] - 2026-08-18

작성: 2026-08-18 13:40 KST

같은 실행인데 화면마다 다르게 나오던 진행률과 성공·실패 건수를 테스트 플랜 기준으로 맞췄습니다. 실행 목록의 작업 열에서 첨부가 있는 행만 어긋나 보이던 정렬도 함께 고쳤습니다.

### 주요 변경 사항

#### 📊 실행 통계를 테스트 플랜 기준으로 통일

* **화면마다 다르던 진행률**: 같은 실행을 두 화면에서 열면 실행 상세는 79%, 케이스 결과 입력 화면은 90%로 나왔습니다. 성공 건수도 222 대 254로 갈렸습니다. 두 화면 모두 분모는 플랜의 케이스 수(314)로 같았고 완료 건수만 달랐습니다.
* **원인은 분모와 분자의 범위 차이**: 분모는 플랜의 케이스 목록인데, 분자는 실행에 남아 있는 모든 결과를 세고 있었습니다. 실측한 실행에서는 결과 599건이 284개 케이스에 걸쳐 있었고 그중 35개 케이스가 플랜에 없었습니다. 35건 전부 최신 판정이 성공·실패·차단이라 완료로 잡혀, 분자만 늘고 미실행이 그만큼 줄었습니다.
* **네 곳의 집계를 하나로**: 실행 목록 진행률, 실행 상세 상단 요약, 실행 상세 API, 케이스 결과 입력 화면 헤더가 각각 따로 계산하면서 기준이 둘로 갈려 있었습니다. 이제 넷 다 플랜의 케이스 목록 안에서만 셉니다. 미실행은 플랜 케이스 수에서 완료 건수를 뺀 값입니다.
* **필터를 걸고 결과 화면을 열었을 때**: 분모만 필터된 건수로 줄고 분자는 실행 전체였습니다. 진행률이 100%에 붙고 미실행이 0으로 눌렸습니다. 통계 범위와 이동 카운터(1/N)를 분리해, 필터가 걸려도 통계는 플랜 전체 기준으로 표시합니다.
* **최신 결과를 고르는 기준**: 결과 배열의 첫 항목을 최신으로 삼던 계산을 실행일시가 가장 최근인 항목으로 바꿨습니다. 데이터베이스 쪽 집계 다섯 곳도 실행일시가 비어 있는 결과를 뒤로 보내도록 맞췄습니다. Postgres 는 내림차순 정렬에서 빈 값을 먼저 주기 때문에, 명시하지 않으면 실행일시 없는 결과가 최신으로 뽑힙니다.
* **실행 상세 응답에 차단 건수 추가**: 목록 응답에는 있고 상세 응답에는 비어 있던 필드를 채웠습니다.

#### 🧷 실행 목록 작업 열 정렬

* **첨부가 있는 행만 어긋나 보이던 문제**: 첨부 아이콘은 결과에 첨부가 있을 때만 뜹니다. 작업 열이 가운데 정렬이라 아이콘 하나가 늘면 묶음 전체 너비가 달라지고, 그만큼 입력 버튼과 나머지 아이콘이 왼쪽으로 밀렸습니다.
* **아이콘 세 개 기준으로 자리 고정**: 첨부가 없는 행에도 28px 짜리 빈 칸을 둬 첨부가 있는 행과 너비를 맞췄습니다. 복사·이전결과·첨부 아이콘 버튼 크기도 28px로 통일했습니다. 복사 아이콘만 글자 크기가 달라 미세하게 폭이 어긋나 있었습니다.

### 업그레이드 안내

* DB 마이그레이션 스크립트는 없습니다. 스키마 변경도 없습니다.
* 신규 i18n 키는 없습니다.
* **화면에 표시되는 숫자가 달라집니다.** 플랜 밖 결과가 있는 실행은 진행률과 성공·실패·차단 건수가 내려가고 미실행이 올라갑니다. 결과 데이터는 그대로 남아 있습니다. 세는 범위만 플랜으로 좁아졌습니다.
* 플랜 밖 결과 자체는 지우지 않았습니다. 테스트 결과 리포트 화면은 실행 단위로 결과를 뽑으므로 그 행들이 계속 보입니다. 그 화면의 표시 범위는 이번에 바꾸지 않았습니다.
* 결과를 기록할 때 그 케이스가 실행의 플랜에 속하는지는 여전히 검사하지 않습니다. API 로 이름을 찾아 결과를 넣거나 플랜의 케이스 목록을 나중에 바꾸면 플랜 밖 결과가 다시 생길 수 있습니다.
* 브라우저에 옛 화면이 캐시돼 있으면 강제 새로고침(⌘⇧R / Ctrl+F5)이 필요합니다.
* 1.0.110 변경은 [RELEASE_NOTE_1.0.110_KO.md](RELEASE_NOTE_1.0.110_KO.md)를 참고하세요.
