# Release Note - v1.0.135

## [1.0.135] - 2026-10-29

작성: 2026-10-29 20:47 KST

1.0.134 이후 `dev` 에 들어온 PR #204 를 묶었습니다. 운영 서버에서 꺼 두었던 Swagger 를 다시 켜고, API 명세는 시스템 관리자만 받도록 막았습니다. 내장 DB(H2)로 기동할 때 서버가 뜨지 않던 문제도 함께 고쳤습니다.

### 주요 변경 사항

#### 운영 서버에서 Swagger 를 다시 씁니다

1.0.134 까지 운영 프로필은 Swagger 화면과 API 명세를 모두 꺼 두었습니다. 이번 버전부터 운영에서도 Swagger 화면(`/swagger-ui.html`)이 열립니다.

- Swagger 화면과 화면 설정(`/api-docs/swagger-config`)은 로그인 없이 열립니다. 둘 다 API 구조를 담고 있지 않습니다.
- 화면이 불러오는 API 명세(`/api-docs`)는 시스템 관리자(`ADMIN`)만 받습니다. 로그인하지 않았으면 401 또는 403, 일반 사용자는 403 을 받습니다.
- Swagger 화면은 같은 브라우저에서 앱에 로그인할 때 저장된 `accessToken` 을 요청 헤더에 자동으로 붙입니다. 관리자 계정으로 앱에 로그인한 뒤 Swagger 화면을 열면 명세가 바로 보입니다.
- 로그인하지 않았거나 관리자가 아니면 화면에 "Failed to load API definition" 이 표시됩니다.

#### 내장 DB 로 기동할 때 서버가 멈추지 않습니다

기동할 때 LLM 공급자 제약을 점검하는 작업이 PostgreSQL 전용 함수를 호출합니다. H2 처럼 다른 DB 에서는 이 호출이 실패하고, 실패를 무시하도록 작성한 처리도 트랜잭션이 롤백 상태로 남아 있어 결국 기동이 실패했습니다.

- PostgreSQL 이 아니면 이 점검을 건너뜁니다.
- 점검이 실패해도 기동은 계속됩니다. 운영 PostgreSQL 에서 권한 문제 등으로 점검 쿼리가 실패해도 서버가 뜹니다.

#### 코드 포맷 정리

저장소의 Java 파일 128개에 google-java-format 을 적용했습니다. 공백과 줄바꿈만 바뀌었고 동작은 바뀌지 않았습니다. pre-commit 훅이 저장소 전체를 검사하기 때문에, 이 정리가 없으면 다른 파일을 고친 커밋도 훅에서 실패합니다.

### 업그레이드할 때

- Swagger 규칙은 운영뿐 아니라 로컬·개발 서버에도 똑같이 적용됩니다. 지금까지 로그인 없이 `/api-docs` 를 받던 스크립트나 도구가 있으면, 관리자 계정의 토큰을 붙여 호출하도록 바꿔야 합니다.
- DB 스키마 변경은 없습니다.

### 확인한 범위

- PR #204 브랜치의 마지막 커밋(`b7d39b15`)에서 백엔드 테스트 943건이 모두 통과했습니다. 1.0.134 노트에 적은 `JiraSmartRedirectIntegrationTest` 실패 9건도 이 수정으로 해소되었습니다.
- Swagger 접근 규칙은 통합 테스트 5건으로 확인했습니다. 비로그인, 일반 사용자, 관리자, 화면 설정 공개, 토큰 자동 첨부를 각각 봅니다.
- 포맷 정리 커밋은 공백·주석 줄바꿈·긴 문자열 분할을 걷어 낸 내용이 원본과 같고, import 목록도 그대로인 것을 확인했습니다.
- 운영 서버에 배포한 뒤 관리자 계정으로 Swagger 화면을 여는 확인은 아직 하지 않았습니다.

### 알려진 문제

- 1.0.134 에 적은 문제(결과 편집 이력에 스텝 결과 미포함, 스텝 통과율 통계·스텝별 첨부 미지원 등)는 이번 버전에서도 고치지 않았습니다.
