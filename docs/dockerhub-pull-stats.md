# Docker Hub pull 집계 기록

작성: 2026-08-30 15:51 KST
최종 갱신: 2026-08-30 15:51 KST

Docker Hub 가 공개하는 저장소 단위 누적 pull 횟수를 필요할 때마다 조회해 아래 표에 남긴다.
대상은 `xmlangel/testcasecraft` 와 `xmlangel/testcasecraft-rag-service` 두 저장소다.

## 기록 방법

저장소 루트에서 다음 명령을 실행하면 오늘 날짜 행이 표에 추가된다.
같은 날 다시 실행하면 그 날 행을 새 값으로 갈아 끼우므로 여러 번 실행해도 줄이 늘지 않는다.

```bash
python3 scripts/dockerhub_pull_stats.py                    # 기록한다
python3 scripts/dockerhub_pull_stats.py --dry-run          # 조회만 한다
python3 scripts/dockerhub_pull_stats.py --note "1.0.126 배포"  # 비고를 함께 남긴다
```

크론에는 걸지 않았다. 자동으로 매일 쌓으면 표가 길어지는 대신 어떤 날 무슨 일이 있었는지는
그대로 비어 있어서, 사람이 필요를 느낀 시점에 기록하는 편이 읽을 값어치가 높다.

증감 열은 직전 기록 대비 차이이고, 기록 간격이 하루가 아닐 수 있으므로 일일 증가량이 아니다. 간격은 날짜 열에서 확인한다.

## 집계 규칙과 제외 대상

Docker Hub 는 레지스트리에 들어온 매니페스트 GET 요청 1건을 pull 1회로 센다.
레이어를 이미 갖고 있어서 실제로 내려받은 데이터가 없어도 요청 자체가 집계된다.
반대로 존재 여부만 묻는 HEAD 요청은 세지 않는다.
멀티아키 이미지를 아키텍처별 매니페스트까지 받아 가면 아키텍처 수만큼 잡힌다.

2026-08-30 06:36 UTC 에 세 건을 보내 실제로 확인했다.
`1.0.117` 에 GET, `1.0.118` 에 HEAD, `latest` 인덱스에 GET 을 보냈고 카운터는 14,470 에서 14,472 로
정확히 2 만큼 올랐다. GET 두 건만 잡히고 HEAD 한 건은 잡히지 않았다.
이때 `tag_last_pulled` 값은 HEAD 를 보낸 태그에서도 갱신됐으므로, 두 방식을 가르는 지표로 쓸 수 없다.

`hub.docker.com/v2/repositories/...` 웹 API 조회는 레지스트리 요청이 아니라서 집계 대상 밖이다.
NAS 의 자동 업데이트 스크립트(`auto_update.sh`)가 1분마다 이 경로로 최신 태그와 digest 를 비교하고
값이 달라졌을 때만 `docker pull` 을 실행하므로, 폴링 자체는 아래 수치를 움직이지 않는다.

## 한계

Docker Hub 에는 과거 시점의 pull 횟수를 되돌려 주는 API 가 없다.
그래서 이 표는 기록을 시작한 2026-08-30 이후만 담고 그 이전은 복원할 수 없다.
태그별로 몇 번씩 받아 갔는지도 공개되지 않아 저장소 총합만 남는다.
