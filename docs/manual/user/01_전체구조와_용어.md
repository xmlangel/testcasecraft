## 1. 전체 구조와 핵심 용어

TestcaseCraft는 웹에서 쓰는 테스트 관리 도구입니다. 화면을 하나씩 익히기 전에, 이 장에서 데이터가 어떻게 이어지는지 먼저 봐 두면 뒤의 장을 읽을 때 지금 어느 단계에 있는지 알 수 있습니다.

### 1-1. 데이터 구조

모든 작업은 **프로젝트** 안에서 이루어집니다. 프로젝트끼리는 케이스나 결과를 공유하지 않습니다. 한 제품을 시험하는 팀이라면 프로젝트 하나를 만들고, 그 안에서 폴더와 플랜으로 일을 나누는 편이 관리하기 쉽습니다.

```text
프로젝트
├── 요구사항 문서 ── 요구사항 ──┐ (연결)
├── 폴더 ── 테스트 케이스 ◀────┘
├── 테스트 플랜 (실행할 케이스를 골라 담음)
│     └── 테스트 실행 (플랜을 한 번 돌릴 때마다 하나)
│            └── 케이스별 결과 (통과 · 실패 · 차단 · 미실행)
├── 자동화 테스트 결과 (JUnit XML 등 업로드)
├── RAG 문서 · 탐색 세션
└── 멤버와 역할
```

| 단계 | 하는 일 | 다루는 장 |
|---|---|---|
| 준비 | 프로젝트를 만들고 멤버에게 역할을 줍니다 | [4장](04_프로젝트.md#4-프로젝트-만들기), [16장](16_프로젝트설정_PM.md#16-프로젝트-설정-pm) |
| 요구사항 (선택) | 기획서·명세서의 요구사항을 등록합니다. 요구사항을 관리하지 않는 팀은 건너뜁니다 | [5장](05_요구사항.md#5-요구사항과-커버리지) |
| 설계 | 폴더를 나누고 테스트 케이스를 작성합니다. 요구사항을 등록했다면 케이스와 연결합니다 | [6장](06_테스트케이스_작성.md#6-테스트-케이스-작성), [7장](07_트리_정리.md#7-테스트-케이스-트리-정리), [5-2절](05_요구사항.md#5-2-테스트-케이스-연결) |
| 계획 | 이번에 돌릴 케이스를 플랜에 넣습니다 | [8장](08_테스트플랜.md#8-테스트-플랜) |
| 실행 | 플랜으로 실행을 만들고 케이스마다 결과를 기록합니다 | [9장](09_테스트실행.md#9-테스트-실행) |
| 보고 | 대시보드·결과 화면으로 진행 상황과 품질을 봅니다. 요구사항을 등록했다면 요구사항 리포트로 요구사항마다 판정을 봅니다 | [10장](10_결과와_리포트.md#10-결과와-리포트), [5-5절](05_요구사항.md#5-5-리포트-탭) |
| 자동화 | 자동화 도구가 만든 결과 파일을 올려 수동 결과와 함께 봅니다 | [11장](11_자동화테스트.md#11-자동화-테스트) |

```text
요구사항 작성 (선택) → 테스트 케이스 작성 → (요구사항과 연결) → 플랜 → 실행 → 결과·리포트
        └─ 요구사항을 쓰지 않으면 여기서 바로 케이스 작성으로 갑니다
```

요구사항은 케이스보다 **먼저** 등록합니다. 요구사항이 먼저 있어야 무엇을 시험할지 빠짐없이 정할 수 있고, 케이스를 쓰면서 바로 연결할 수 있습니다. 요구사항을 관리하지 않는 팀은 5장을 건너뛰고 6장부터 시작해도 나머지 기능을 모두 쓸 수 있습니다. 요구사항 화면에서 판정하는 커버리지와 리포트만 쓰지 못합니다.

### 1-2. 핵심 용어 여덟 개

본문 전체에서 아래 여덟 개를 기준으로 설명합니다. 나머지 용어는 [19장 용어집](19_용어집.md#19-용어집)에 있습니다.

| 용어 | 뜻 |
|---|---|
| **프로젝트** | 작업의 가장 큰 단위입니다. 케이스·플랜·결과·멤버가 모두 프로젝트에 속합니다. |
| **테스트 케이스** | 무엇을 어떤 순서로 해 보고 어떤 결과를 기대하는지 적은 것입니다. 단계(스텝)와 기대 결과로 이루어집니다. |
| **폴더** | 케이스를 기능이나 화면별로 묶는 단위입니다. 폴더 안에 폴더를 둘 수 있습니다. |
| **요구사항** | 제품이 갖춰야 할 기능이나 조건입니다. 케이스와 연결하면 요구사항마다 테스트가 충분한지 확인할 수 있습니다. |
| **테스트 플랜** | 이번 테스트에서 돌릴 케이스 목록입니다. 같은 케이스를 여러 플랜에 담을 수 있습니다. |
| **테스트 실행** | 플랜을 실제로 한 번 진행하는 일입니다. 빌드가 바뀌어 다시 시험하면 실행을 새로 만듭니다. |
| **결과** | 실행 안에서 케이스마다 기록하는 판정입니다. 통과(PASS)·실패(FAIL)·차단(BLOCKED)·미실행(NOT RUN) 네 가지 중 하나로 기록합니다. |
| **역할** | 프로젝트 안에서 그 사람이 할 수 있는 일의 범위입니다. 같은 사람도 프로젝트마다 역할이 다를 수 있습니다([18장](18_역할과_권한.md#18-역할과-권한)). |

### 1-3. 처음 설정할 때 정해 둘 것

- **프로젝트를 몇 개로 나눌지 정합니다.** 버전마다 프로젝트를 새로 만들지 않습니다. 버전 차이는 플랜과 실행으로 구분합니다. 프로젝트를 나누면 케이스를 서로 재사용할 수 없습니다.
- **폴더 기준을 하나로 정합니다.** 기능 단위나 화면 단위 중 하나를 골라 팀이 같은 기준으로 케이스를 넣으면 트리를 찾기 쉽습니다.
- **누가 무엇을 하는지 정하고 역할을 줍니다.** 케이스를 쓰는 사람, 결과만 기록하는 사람, 보기만 하는 사람의 역할이 다릅니다.

> ⚠️ 프로젝트를 지우면 그 안의 케이스와 결과가 모두 함께 지워지고 되돌릴 수 없습니다. 더 쓰지 않는 프로젝트라도 지우기 전에 결과 보고서를 내보내 두세요.
