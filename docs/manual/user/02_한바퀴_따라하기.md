## 2. 한 바퀴 따라하기

가상의 팀이 쇼핑몰 웹사이트의 로그인 기능을 시험하는 과정을 처음부터 끝까지 따라가 봅니다. 단계마다 자세한 조작은 괄호 안의 장에서 설명합니다.

### 2-1. 등장인물

| 사람 | 역할 | 맡은 일 |
|---|---|---|
| 민지 | PROJECT_MANAGER | 프로젝트를 만들고 멤버를 초대합니다. 플랜을 짜고 결과를 보고합니다 |
| 준호 | CONTRIBUTOR | 요구사항을 정리하고 테스트 케이스를 작성합니다 |
| 서연 | TESTER | 케이스를 실행하고 결과를 기록합니다 |
| 팀장 | VIEWER | 결과 화면만 봅니다 |

### 2-2. 진행 순서

1. **민지가 프로젝트를 만듭니다.** 프로젝트 이름은 `ShopFlow`, 코드는 `SHOP` 으로 정합니다. 코드는 케이스 번호 앞에 붙어 `SHOP-001` 처럼 표시됩니다([4장](04_프로젝트.md#4-프로젝트-만들기)).
2. **민지가 멤버를 초대하고 역할을 줍니다.** 준호는 CONTRIBUTOR, 서연은 TESTER, 팀장은 VIEWER 로 넣습니다([16장](16_프로젝트설정_PM.md#16-1-프로젝트-설정-화면)).
3. **(선택) 준호가 요구사항을 등록합니다.** 요구사항 문서 `로그인 기능 명세` 를 만들고, 그 아래에 `REQ-001 아이디와 비밀번호로 로그인한다`, `REQ-002 비밀번호를 5회 틀리면 계정을 잠근다` 를 넣습니다([5장](05_요구사항.md#5-요구사항과-커버리지)).
4. **준호가 테스트 케이스를 작성합니다.** `로그인` 폴더를 만들고 `정상 로그인`, `잘못된 비밀번호`, `5회 실패 시 잠금` 세 케이스를 작성합니다([6장](06_테스트케이스_작성.md#6-테스트-케이스-작성)).
5. **(선택) 준호가 케이스와 요구사항을 연결합니다.** 요구사항 화면의 커버리지 탭에서 `미연결` 로 남은 요구사항이 없는지 확인합니다([5장](05_요구사항.md#5-4-커버리지-탭)).
6. **민지가 플랜을 만듭니다.** 플랜 `v1.0 로그인 시험` 에 `로그인` 폴더를 통째로 담습니다([8장](08_테스트플랜.md#8-테스트-플랜)).
7. **서연이 실행을 만들고 결과를 기록합니다.** 실행 `v1.0 1차` 에서 케이스를 하나씩 열어 결과를 고릅니다. 결과는 통과 2건, 실패 1건입니다. 실패한 케이스에는 화면 캡처를 첨부합니다([9장](09_테스트실행.md#9-테스트-실행)).
8. **개발팀이 고친 빌드를 다시 받습니다.** 서연은 결과 화면에서 **실패** 항목을 눌러 지난번 실패한 케이스를 확인하고([10장](10_결과와_리포트.md#10-2-테스트-결과)), 실행 `v1.0 2차` 를 새로 만들어 그 케이스를 다시 시험합니다. 이번에는 모두 통과합니다.
9. **민지가 결과를 보고합니다.** 결과 화면에서 실행별 통계를 확인하고 보고서를 내보냅니다. 요구사항 화면의 리포트 탭에서 플랜을 고르면 요구사항마다 통과·실패 판정이 나옵니다([10장](10_결과와_리포트.md#10-결과와-리포트), [5장](05_요구사항.md#5-5-리포트-탭)).
10. **팀장은 결과 화면만 봅니다.** VIEWER 는 화면을 보기만 할 수 있고, 추가·수정 버튼은 비활성으로 나옵니다.

> 💡 요구사항을 관리하지 않는 팀은 3번과 5번을 건너뛰고, 9번에서도 요구사항 리포트를 빼고 진행합니다. 나머지 순서는 같습니다.
