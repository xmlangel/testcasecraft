## 1. 구성요소 목록

| 화면 | 경로 | 주요 요소 | 용도 |
|---|---|---|---|
| 로그인 | `/` (미인증 진입) | 입력 필드 2~5개 · 알림 · 모드 전환 버튼 | 로그인·가입 양방향 |
| 이메일 인증 | `/verify-email?token=…` | 아이콘 · 제목 · 상태별 액션 버튼 | 인증 결과 표시 |
| 매뉴얼 열람 | `/manual` (lazy) | 마크다운 뷰어 | 사용자 매뉴얼 읽기 |
| 가이드 열람 | `/guides/{name}` (lazy) | 마크다운 뷰어 | 가이드 문서 읽기 |

로그인 화면은 초기 번들에 포함. 매뉴얼·가이드는 필요할 때만 다운로드.

## 2. 표시 규격

### 2.1 로그인·가입 화면

**카드 구성**
- 배경: 중앙 카드 (최소너비 350px · 음영 있음)
- 제목: 중앙 정렬 · 상황에 맞게 "로그인" 또는 "계정 만들기"
- 언어 토글: 우상단 고정

**필드**
- 로그인: 아이디, 비밀번호 2개
- 가입: 아이디, 비밀번호, 비밀번호 확인, 이름, 이메일 5개 (라벨 맞춤정렬)
- 폭: 전체 너비 · 정상간격

**알림**
- 오류(빨강): "계정을 찾을 수 없습니다" 등
- 안내(초록): "가입 확인 메일을 보냈습니다" 등
- 규칙: 오류와 안내는 동시에 하나만 표시. 모드 전환이나 입력 시 사라짐

**버튼**
- 주 버튼(로그인/가입): 제출 시작 → 진행 표시로 변경 → 로딩 중엔 버튼 숨김 (비활성이 아닌 완전 제거)
- 모드 전환: 작은 크기 · 하단 · 로딩 중 숨김
- 매뉴얼 링크: 아주 작은 크기 · 하단 중앙 · 새 탭 열기

**필드 비활성**
- 로딩 중: 모든 입력 필드와 버튼 비활성

### 2.2 이메일 인증 결과 화면

**구성**
- 배경: 중앙 카드
- 상단 아이콘: 상태별 (성공/만료/사용됨/실패)
- 제목: 상태별 문구
- 하단 버튼: "로그인으로" 또는 "재발송"

**상태별 표현**

| 상태 | 아이콘 | 제목 색상 | 버튼 |
|---|---|---|---|
| 성공 | 체크 원 | 초록 | [로그인으로] |
| 만료됨 | 경고 | 노랑 | [재발송] |
| 사용됨 | 정보 | 파랑 | [로그인으로] |
| 실패·오류 | X 원 | 빨강 | [로그인으로] |

## 3. 상호작용 규격

### 3.1 로그인·가입 흐름

| 사용자 액션 | 화면 반응 | 서버 호출 | 성공 시 |
|---|---|---|---|
| 아이디 입력 | 기존 오류 사라짐 | 없음 | — |
| 제출 (로그인) | 필드 비활성 · 버튼 → 진행 표시 | `POST /api/auth/login` | 토큰 받아 세션 시작 |
| 제출 (가입) | 필드 비활성 · 버튼 → 진행 표시 | `POST /api/auth/register` | "확인 메일 보냈습니다" 표시 후 로그인 탭으로 |
| 모드 전환 | 다른 필드 세트 표시 · 입력값 유지 안 함 | 없음 | — |
| 매뉴얼 링크 클릭 | 새 탭에서 `/manual` 열기 | 없음 | — |

**선검증 (화면)**
- 비밀번호 2개가 다르면 "비밀번호가 일치하지 않습니다" 표시 · 서버 호출 안 함
- 이메일 형식 검사는 화면에서 안 함

**타이밍**
- 로딩 중 버튼: 약 0.3초로 숨김 (부드러운 전환)

### 3.2 이메일 인증 흐름

| 액션 | 반응 |
|---|---|
| 페이지 진입 | 즉시 `GET /api/email-verification/verify?token=…` 호출 · 결과에 따라 아이콘·제목 결정 |
| [로그인으로] | `/login` 경로로 이동 |
| [재발송] | `POST /api/email-verification/resend` 호출 · 성공/실패 표시 |

## 6. 반응형·접근성 규격

**좁은 화면**
- 카드 너비: 최소 350px → 90% 폭으로 줄어듦
- 언어 토글: 우상단 유지

**키보드 네비게이션**
- Tab 순서: 아이디 → 비밀번호 (→ 비밀번호 확인·이름·이메일) → 주 버튼 → 모드 전환 → 매뉴얼 링크
- Enter: 아이디 칸 자동 포커스 · 제출은 버튼 또는 Enter로 동일
- Escape: 모달 아님이므로 무시

**대체 텍스트**
- 아이디 칸: "사용자명 입력"
- 비밀번호 칸: "비밀번호 입력" · 표시/숨김 아이콘에 "비밀번호 표시"

## 7. 서버와 주고받는 정보

### 7.1 인증 API

| 경로 | 메서드 | 요청 | 응답 | 용도 |
|---|---|---|---|---|
| `/api/auth/login` | POST | `{ username, password }` | `{ accessToken, refreshToken, user }` | 로그인 |
| `/api/auth/register` | POST | `{ username, password, name, email }` | `{ success }` | 가입 |
| `/api/auth/refresh` | POST | `{ refreshToken }` | `{ accessToken }` | 토큰 갱신 (자동) |

**토큰 갱신**: 401 응답 시 자동으로 한 번만 시도. 여러 탭/창에서 동시 요청이 들어와도 갱신 호출은 한 번만.

### 7.2 이메일 인증 API

| 경로 | 메서드 | 요청 | 응답 | 용도 |
|---|---|---|---|---|
| `/api/email-verification/verify` | GET | `?token=…` | `{ success }` 또는 `{ error: "EXPIRED"\|"USED"\|"INVALID"\|"ERROR" }` | 인증 |
| `/api/email-verification/resend` | POST | 없음 | `{ success }` | 메일 재발송 |

### 7.3 문서 API (인증 불필요)

| 경로 | 메서드 | 응답 | 용도 |
|---|---|---|---|
| `/api/manual` | GET | 마크다운 텍스트 (한/영) | 사용자 매뉴얼 |
| `/api/guides/{name}` | GET | 마크다운 텍스트 | 가이드 문서 |

이 경로는 로그인 전에 열수 있어야 한다.

## 8. 유지보수 주의

1. **필드를 추가하면 세 곳을 함께 고친다**: 가입 필드 세트(5개) · 초기값 · 선검증 규칙. 초기값을 빼먹으면 undefined가 서버로 간다.
2. **로그인 실패 문구를 "계정을 찾을 수 없습니다" 단일로 유지한다.** 계정 존재 여부가 드러나므로 세분화하지 않는다.
3. **비밀번호 형식(길이 등) 검사는 서버에서만 한다.** 화면은 입력만 받고, 서버 오류로 규칙을 표시한다.
4. **매뉴얼·가이드는 ProtectedRoute 밖에 둔다.** 로그인 전이나 메일 링크에서도 열 수 있어야 한다.
5. **인증 결과(성공/실패)를 여러 컴포넌트로 나누지 말고, 설정 객체 하나로 분기한다.** 상태를 추가할 때 아이콘·색·제목을 한 곳에서만 정의한다.
