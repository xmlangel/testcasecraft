# 로그인·계정(S0) 업무프로세스

> 화면 ID **S0** 화면명 **로그인 회원가입 이메일 인증 매뉴얼 열람**
> 정본 입력: `00_전체_업무프로세스.md` 2절 단계 1 6.1절 매뉴얼 1절 15절

---

## 1. 업무 목적

제품에 들어오는 유일한 문이다. 세 가지를 맡는다.

| 목적 | 내용 |
|---|---|
| ① **계정 확보** | 아이디·비밀번호로 로그인하거나, 같은 화면에서 모드를 바꿔 계정을 만든다 |
| ② **토큰 발급** | 로그인 성공 시 액세스 토큰과 갱신 토큰을 함께 받아 세션을 연다 |
| ③ **로그인 전 정보 제공** | 계정이 없어도 사용자 매뉴얼(한/영)을 열 수 있다 |

**이 화면이 하지 않는 일**

| 하지 않는 것 | 이유 |
|---|---|
| 이메일 인증 강제 | 인증은 알림 수신·비밀번호 재설정에 쓰이고 진입을 막지 않는다. 회원가입 직후 로그인 모드로 돌아온다 |
| 비밀번호 변경 | 로그인 후 프로필 다이얼로그(S2)의 몫이다 |
| 소셜 로그인 | 제공하지 않는다. Google 연동은 로그인이 아니라 Sheets 연동용이다(S2 프로필) |
| 조직·프로젝트 선택 | 로그인 성공 후 S1이 맡는다 |

## 3. 업무 프로세스 흐름

### 3.1 로그인

| # | 사용자 행위 | 화면 동작 | 결과 |
|---|---|---|---|
| 1 | `/` 또는 `/login` 접속 | 로그인 폼(아이디·비밀번호) 표시 | — |
| 2 | 값 입력 후 `[로그인]` 또는 Enter | 버튼 비활성 + 로딩. 폼 전체가 `submit` 이벤트를 받는다 | — |
| 3 | 인증 성공 | 두 토큰 확인 후 세션 시작. 포커스를 `body`로 옮긴다 | S1로 이동 |
| 4 | 토큰 누락 응답 | "로그인에 실패했습니다" | 폼 유지 |
| 5 | 예외 | 서버 메시지를 그대로, 없으면 일반 문구 | 폼 유지 |

3단계의 포커스 이동은 로그인 직후 프로필 메뉴가 저절로 열리는 현상을 막기 위한 것이다.

### 3.2 회원가입

| # | 사용자 행위 | 화면 동작 | 결과 |
|---|---|---|---|
| 1 | `[회원가입]` 클릭 | 같은 화면이 회원가입 모드로 바뀐다. 필드 3개(비밀번호 확인·이름·이메일)가 추가된다 | — |
| 2 | `[회원가입]` 제출 | **화면에서 먼저 검사한다** — 빈 필드, 비밀번호 불일치 | 실패 시 서버 호출 없음 |
| 3 | 등록 성공 | "회원가입이 완료되었습니다. 로그인 해주세요." 안내 후 **로그인 모드로 되돌린다**. 비밀번호 두 칸만 비운다 | 로그인 폼 |
| 4 | 중복 아이디 등 서버 거부 | 서버 메시지 노출 | 회원가입 모드 유지 |

3단계에서 아이디·이름·이메일을 남겨 두는 것은 재입력 부담을 줄이기 위한 처리다.

### 3.3 이메일 인증

| # | 행위 | 동작 |
|---|---|---|
| 1 | 프로필에서 `[인증 이메일 발송]` | 인증 링크가 담긴 메일 발송 |
| 2 | 메일의 링크 클릭 | `/verify-email?token=…` 진입. 즉시 토큰 검증 |
| 3 | 결과 표시 | 성공·만료·이미 사용됨·실패 4가지 상태 화면 |
| 4 | 만료·실패 시 `[재발송]` | 새 토큰으로 메일 재발송 |
| 5 | `[로그인으로]` | 로그인 화면으로 이동 |

**결과 4상태를 한 화면에서 색과 아이콘으로 가른다.** 성공은 초록 체크, 만료는 주황 경고, 이미 사용됨은 파란 안내, 그 외는 빨간 오류다. 재사용된 링크를 오류로 다루지 않는 것이 의도다. 이미 인증된 사용자가 링크를 다시 눌렀을 때 실패로 보이면 혼란이 생긴다.

### 3.4 로그아웃

| 행위 | 동작 |
|---|---|
| 아바타 → `[로그아웃]` | 갱신 토큰 폐기 후 로그인 화면 |
| 장기 미사용 | 세션 만료 안내 후 자동 로그아웃 |

전 기기 로그아웃 경로(`POST /api/auth/logout-all`)가 서버에 있으나 이 화면에는 진입점이 없다. **상태: 숨김.** 기능은 있으나 화면에서 부를 길이 없다.

## 4. 계정 모델

| # | 규칙 | 내용 |
|---|---|---|
| A1 | **아이디는 변경 불가** | 로그인 식별자로 고정된다. 이름·이메일만 프로필에서 고친다 |
| A2 | **시스템 권한 기본값은 비어 있다** | 신규 가입자는 `role`이 없고, 프로젝트에 참여해야 무엇을 할 수 있다 |
| A3 | **가입만으로는 볼 것이 없다** | 참여 프로젝트가 0건이면 S1이 초대 요청 안내를 띄운다 |
| A4 | **초기 관리자 계정이 코드에 있다** | `admin / admin123`. 배포 직후 반드시 바꾼다 |
| A5 | **토큰 2종을 쓴다** | 액세스 토큰으로 요청하고, 만료 시 갱신 토큰으로 재발급한다 |

## 5. 사용자와 권한

이 화면은 인증 전이므로 프로젝트 권한이 적용되지 않는다. 구분되는 것은 두 가지 상태뿐이다.

| 상태 | 무엇이 보이는가 |
|---|---|
| 미인증 | 로그인·회원가입 폼, 매뉴얼 링크 |
| 인증 | 이 화면에 오지 않는다. 접근하면 작업공간으로 넘어간다 |

이메일 인증 여부는 권한이 아니라 **표시 상태**다. 미인증이어도 로그인·케이스 작성·결과 기록이 모두 된다. 인증이 필요한 것은 시스템이 보내는 메일을 받는 일이다.

## 6. 기능 규칙

| # | 규칙 |
|---|---|
| F1 | 폼 제출은 Enter로도 동작한다. 로딩 중 재제출을 막는다 |
| F2 | 화면 검사로 걸러낼 수 있는 오류(빈 값·비밀번호 불일치)는 서버로 보내지 않는다 |
| F3 | 서버 오류 메시지를 임의로 다듬지 않고 그대로 보여준다 |
| F4 | 비밀번호 입력값은 모드 전환·가입 성공 시 비운다 |
| F5 | 화면 문구는 전부 `t("키", "한국어")` 형태다. 폴백 한국어가 코드에 함께 있다 |
| F6 | 인증 실패 사유를 아이디·비밀번호 중 무엇이 틀렸는지로 나누지 않는다 |
