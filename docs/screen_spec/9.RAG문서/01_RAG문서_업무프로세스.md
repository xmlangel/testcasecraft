# RAG 문서(S9) 업무프로세스

> 화면 ID **S9** · 화면명 **지식 문서 업로드 · 임베딩 · 챗**
> 라우트: `/projects/{projectId}/rag`
> 노출 조건: RAG 보조 서비스가 살아 있을 때만 노출된다

---

## 1. 업무 목적

RAG(Retrieval-Augmented Generation)는 프로젝트 지식을 문서로 축적하고, 자연어 질의를 통해 관련 문서를 인용한 답변을 얻는 보조 서비스다. S9는 문서 업로드·임베딩·채팅과 선택적 전체 분석 기능을 제공한다.

| 목적 | 내용 |
|---|---|
| ① **지식 축적** | PDF·MD·HTML·이미지 등 문서를 프로젝트별로 업로드·관리한다 |
| ② **자동 색인** | 업로드된 문서를 청킹·임베딩해 벡터 데이터베이스에 색인한다 |
| ③ **의존 질의응답** | 자연어 질의에 대해 문서에서 찾은 관련 청크를 출처로 인용하며 답변한다 |
| ④ **선택적 분석** | 문서 전체를 LLM 순차 질의로 분석하고 요약·정보 추출을 저장한다(신규) |
| ⑤ **케이스 연결** | 테스트 케이스 작성 시 관련 RAG 문서를 추천·연결한다 |

**이 화면이 하지 않는 일**

| 하지 않는 것 | 어디가 맡는가 |
|---|---|
| 전역 문서(조직 공용) 관리 | S11 조직 관리(`/admin/rag`)|
| LLM·임베딩 모델 설정 | S11 RAG 시스템 설정(`/admin/rag/settings`)|
| 배치 관리(분석 재개/취소) | 분석 진행 중 자동으로 확인 팝업을 띄운다(배치별 토큰 상한) |

## 4. RAG 파이프라인 규칙

| # | 단계 | 내용 | 설계 근거 |
|---|---|---|---|
| P1 | **청킹** | 문서 단위 1000자/200자 겹침 슬라이딩 윈도우. 청크 인덱스 시간순 정렬 | `RAG_EMBEDDING_PROCESS.md` 3절 |
| P2 | **임베딩** | SentenceTransformer `paraphrase-multilingual-mpnet-base-v2` → 768차원 | 〃 4절 |
| P3 | **벡터 저장** | PostgreSQL + pgvector(코사인 유사도) | 〃 |
| P4 | **검색** | 질의 임베딩 → K=5 유사도 상위 | `SEQUENTIAL_CHUNK_LLM_QUERY.md` 2절 |
| P5 | **재색인** | 문서 재 분석 시 기존 청크 삭제 후 신규 저장 | 설계 참조 |
| P6 | **분석 비용** | 청크 수 × 토큰/청크(모델별) + 마진 10% | `estimate-analysis-cost` API |

## 5. 사용자와 권한

### 5.1 기능 × 역할

이 영역의 접근 판정은 프로젝트 권한을 그대로 따른다.

| 기능 | PM LEAD | DEVELOPER CONTRIBUTOR | TESTER | VIEWER | 권한 |
|---|---|---|---|---|---|
| 문서 업로드 | ○ | ○ | — | — | 편집 권한 |
| 문서 제거·재색인 | ○ | ○ | — | — | 편집 권한 |
| 채팅 | ○ | ○ | ○ | ○ | `hasReadAccess` |
| 분석 시작 | ○ | ○ | — | — | 편집 권한 |
| 분석 요약 저장 | ○ | ○ | ○ | ○ | 결과 기록 권한 |

**전역 문서(조직 공용)는 별도 권한이다.** 조직 공용 문서는 조직 ADMIN만 업로드 가능.

### 5.2 화면 요소별 노출

| 요소 | 노출 조건 |
|---|---|
| `[+ 문서 추가]` | 편집 권한 |
| 문서 행 `[⋮]` 메뉴 | 문서 소유 프로젝트 편집 권한 |
| `[분석]` 버튼 | 편집 권한 |
| 채팅 입력 | `hasReadAccess` |

⚠ **확인 필요.** 전역 문서와 프로젝트 문서의 권한 경계가 코드에 명확히 구분되는지 확인이 필요한다.

## 6. 기능 규칙

| # | 규칙 | 내용 |
|---|---|---|
| F1 | **영역 조건부 노출** | RAG 보조 서비스가 꺼지면 영역 항목이 목록에서 빠지고 뒤 항목의 순서가 당겨진다 |
| F2 | **문서 상태는 4가지** | 대기 · 임베딩 중 · 준비됨 · 실패 |
| F3 | **진행 표시 갱신 주기** | 임베딩 진행률은 약 3초 주기로 갱신하고, 채팅·분석은 응답이 오는 대로 표시한다 (⚠ 확인 필요) |
| F4 | **출처 인용** | 청크 번호·파일명·위치를 링크로 표시한다 |
| F5 | **배치 확인** | 분석 진행 중 청크 10개마다 계속할지 확인받는다 |
| F6 | **분석 요약** | 완료 후 화면에만 두거나 저장해 남긴다 |

## 9. 전제와 제약

| 항목 | 내용 |
|---|---|
| **RAG 서비스 의존** | FastAPI 포트 8001 필수. 비활성이면 S9 탭이 없다 |
| **파일 크기 제한** | 업로드 최대값(⚠ 확인 필요) |
| **임베딩 벡터 저장** | PostgreSQL + pgvector(768차원). 벡터 DB로 실시간 동기는 미지원 |
| **재색인 중 검색** | 진행 중 검색 결과는 최신 벡터를 포함하지 않을 수 있다 |
| **분석 비용** | 사용자가 비용을 확인하고 명시적으로 동의해야만 실행 |
| **배치 중단 불가** | 시작한 배치 10개 블록은 완료·실패까지 진행되며 취소 불가(설계) |
