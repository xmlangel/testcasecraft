## 5. 화면에 없는 백엔드 기능

백엔드에는 있지만 현재 화면에서 접근 불가능한 기능들. (추후 노출 대상)

| API | 엔드포인트 | 용도 | 노출 검토 |
|---|---|---|---|
| 케이스 매칭 | `PUT /api/junit-cases/{caseId}/link-testcase` | JUnit 케이스 → 수동 TC 연결 | 상세 화면 메뉴에 "케이스 연결" 항목 추가 검토 |
| 배치 상태 수정 | `PUT /api/junit-results/{id}/cases/batch-update` | 여러 케이스 상태 한 번에 변경 | 대량 선택·처리 기능(향후) |
| 결과 재파싱 | `POST /api/junit-results/{id}/reparse` | XML 재파싱(예: 매칭 규칙 변경 후) | 메뉴에 "재파싱" 항목 추가 검토 |

## 6. 유지보수 인계

새로 합류한 개발자·QA가 알아야 할 핵심 사항.

| 항목 | 핵심 내용 |
|---|---|
| **권한 게이트** | 업로드는 `canUploadToProject`, 편집은 결과 기록 권한, 삭제는 프로젝트 관리 권한 |
| **API 응답 필드** | `content`, `totalPages`, `totalElements` 반드시 포함 |
| **상태값 관리** | `JunitTestStatus` enum(PASSED/FAILED/ERROR/SKIPPED)과 `JunitProcessStatus` enum(PROCESSING/COMPLETED/FAILED) 분리 |
| **색상 정의** | `RESULT_COLORS`, `STATUS_COLORS`, `CHART_COLORS` 재사용 금지(중복 정의 방지) |
| **대용량 임계값** | 기본 50MB, 환경 변수 `junit.file.large-size-threshold` 로 조정 가능 |
| **브라우저 저장소** | 접이식 섹션 확장 상태만 저장(개인 설정 아님). 키: `testcase-manager-junit-accordion` |
