# 자동화 테스트(S8) 업무프로세스

> 화면 ID **S8** · 화면명 **JUnit 결과 업로드 · 목록 · 상세**
> 라우트: `/projects/{projectId}/automation` · `/projects/{projectId}/automation-results/{testResultId}`

---

## 1. 업무 목적

자동화 테스트 도구(JUnit·Playwright·Pytest 등)가 만든 결과 파일을 수집·정리·추적하는 채널이다. S6 수동 테스트 실행과 나란히 있으며, S3·S7 통계에 함께 집계된다.

| 목적 | 내용 |
|---|---|
| ① **결과 수집** | JUnit XML 파일(최대 100MB)을 업로드해 파싱한다 |
| ② **목록 추적** | 프로젝트의 자동화 결과를 시간순으로 나열한다 |
| ③ **상세 분석** | 스위트별·케이스별 성공/실패/건너뜀과 에러 메시지를 본다 |
| ④ **케이스 연결** | JUnit 케이스를 수동 케이스 ID와 매칭해 통계에 포함시킨다 |
| ⑤ **결과 편집** | 자동화 케이스의 상태·우선순위·노트를 수정할 수 있다 |
| ⑥ **내보내기** | CSV·PDF로 결과를 외부 보고서로 만든다 |

**이 화면이 하지 않는 일**

| 하지 않는 것 | 어디가 맡는가 |
|---|---|
| 자동화 스크립트 작성 및 실행 | 외부 자동화 도구 |
| JUnit XML 파일 생성 | 〃 |
| 결과를 플랜·실행으로 구조화 | S5(플랜) S6(실행) |

## 2. 화면 위치

| 항목 | 내용 |
|---|---|
| 전(前) | S3 대시보드에서 자동화 결과 수를 보거나, 좌측 영역 탭에서 자동화 탭 선택 |
| 후(後) | 결과 상세 화면(`/projects/{projectId}/automation-results/{testResultId}`) |
| 진입 조건 | 로그인 + 프로젝트 선택 |
| 진입 경로 | 헤더 탭바의 `[자동화 테스트]` 클릭 프로젝트 카드(S1)의 자동화 수 배지 |

## 3. 업무 프로세스 흐름

### 3.1 목록 조회

| # | 사용자 행위 | 화면 동작 | 결과 |
|---|---|---|---|
| 1 | `/projects/{projectId}/automation` 진입 | 프로젝트의 자동화 결과를 조회. 진행 중 스켈레톤 표시 | — |
| 2 | 데이터 수신 | 결과 목록 + 통계(성공률·기간별) 함께 렌더 | — |
| 3 | 결과 0건 | 빈 상태 안내(화면 중앙 메시지) | — |
| 4 | 목록 행 클릭 | 상세 화면으로 이동(`/projects/{projectId}/automation-results/{testResultId}`) | S8 상세 |
| 5 | 시간 범위 선택 | 통계를 재계산한다(기본 7일) | 차트 갱신 |

### 3.2 파일 업로드

| # | 행위 | 동작 |
|---|---|---|
| 1 | `[+ JUnit 결과 업로드]` 버튼 또는 업로드 영역 클릭 | 파일 선택 다이얼로그 열림 |
| 2 | XML 파일 선택(최대 100MB) | 파일 메타 표시 + `[업로드]` 버튼 활성화 |
| 3 | 선택 입력: 실행 이름·설명 | 폼 자동 저장 |
| 4 | `[업로드]` | POST `/api/junit-results/upload` |
| 5 | 업로드 중 | 진행바 표시 |
| 6 | 완료(파일 < 50MB) | 즉시 완료. "업로드 완료" 알림 + 목록 갱신 |
| 7 | 대용량(파일 ≥ 50MB) | PROCESSING 상태로 표시. 백그라운드 처리(별도 모니터링 화면) |

### 3.3 결과 검색·필터

| # | 기능 | 동작 |
|---|---|---|
| 1 | 검색 입력(`파일명·실행이름`) | 실시간 필터(debounce 500ms) |
| 2 | 상태 탭(`전체·통과·실패·건너뜀`) | 해당 건만 표시 |
| 3 | 기간 선택(7d·30d·90d·전체) | 통계와 목록 함께 갱신 |

### 3.4 결과 삭제

| # | 행위 | 동작 |
|---|---|---|
| 1 | 목록 행의 `⋮` 메뉴 | 항목: 상세보기·다운로드·삭제 |
| 2 | `[삭제]` 클릭 | 확인 다이얼로그 "정말 삭제하시겠습니까?" |
| 3 | `[삭제]` 확인 | DELETE `/api/junit-results/{id}` |
| 4 | 성공 | 목록에서 행 제거 |

## 4. 자동화 결과 모델 규칙

| # | 규칙 | 내용 |
|---|---|---|
| A1 | **JUnit 결과는 독립 개념이다** | 플랜·실행과 무관하게 따로 저장·추적된다 |
| A2 | **파일당 하나의 결과 레코드다** | XML → 파싱 → JunitTestResult 1건 |
| A3 | **케이스 매칭은 선택사항이다** | "이 JUnit 케이스 = 우리 수동 TC" 지정은 사용자가 수동 입력 |
| A4 | **상태는 4가지다** | PASSED / FAILED / ERROR / SKIPPED. 수동 실행의 BLOCKED는 자동화에서 들어오지 않는다 |
| A5 | **처리 상태는 별도다** | PROCESSING(대용량 진행) / COMPLETED / FAILED |
| A6 | **통계에 함께 집계된다** | S3·S7 통계의 성공률·기간별 추이에 자동 포함 |

## 6. 기능 규칙

| # | 규칙 |
|---|---|
| F1 | **목록은 페이지네이션된다** (기본 20건/페이지). 따로 내려받기를 지원하지 않는다 |
| F2 | **통계는 기간 필터를 받는다**(7d/30d/90d/전체). 선택하면 목록은 전체, 차트만 필터됨 |
| F3 | **업로드는 실행 이름·설명을 선택 입력으로 받는다** |
| F4 | **대용량 파일(≥50MB)은 비동기 처리된다**(상태 모니터링 가능) |
| F5 | **검색은 즉시 필터다**(debounce 500ms). 엔터를 기다리지 않는다 |
| F6 | **상태 필터는 탭이다** (클릭하면 즉시 적용). 라디오 버튼이 아니다 |
| F7 | **접이식 섹션 확장 상태는 브라우저 저장소에 저장된다** (새로고침 후도 기억) |

## 7. 타 화면 연동

| 연동처 | 데이터 흐름 | 참조 |
|---|---|---|
| **S3 대시보드** | 자동화 결과 수·성공률이 프로젝트 카드에 표시된다 | S3 문서 |
| **S1 프로젝트 목록** | 프로젝트 카드에 자동화 수 배지가 표시되고, 클릭하면 S8로 이동 | S1 문서 |
| **S7 결과 통계** | JUnit 결과가 수동 결과와 함께 집계되어 성공률·추이에 포함된다 | 매뉴얼 9절 |
| **케이스(S4)** | 매칭된 JUnit 케이스의 최신 상태·노트가 수동 케이스 하단에 표시될 수 있음 | |

## 8. 전제와 제약

| # | 항목 | 내용 |
|---|---|---|
| C1 | **파일 형식** | JUnit XML 표준. 다른 도구(Pytest·Playwright)도 JUnit 호환 형식으로 내보낼 수 있어야 한다 |
| C2 | **파일 크기 제한** | 최대 100MB. 초과 시 업로드 거부 |
| C3 | **업로드 권한** | `canUploadToProject` 확인. VIEWER는 불가 |
| C4 | **케이스 매칭** | 자동이 아니라 수동이다. 사용자가 JUnit 케이스 상세에서 "우리 케이스 ID" 입력 |
| C5 | **대용량 처리** | 50MB 이상은 비동기. 완료 시 알림 또는 폴링 모니터링 |
| C6 | **파싱 실패** | XML 문법 오류나 지원 태그 부족 시 오류 알림 + 예시 다운로드 |
