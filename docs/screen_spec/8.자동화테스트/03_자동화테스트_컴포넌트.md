## 2. 표시 규격

### 2.1 JUnit 결과 상태

| 상태 | 칩 색상 | 아이콘 |
|---|---|---|
| **PASS** | 초록 | ✓ |
| **FAIL** | 빨강 | ✗ |
| **ERROR** | 주황 | ⚠ |
| **SKIPPED** | 회색 | ⊘ |
| **PROCESSING** | 파랑 | ⟳ (로딩 인디케이터) |

### 2.2 통계 카드 표시

각 카드에 다음 정보 표시:
- 상태명 (예: "통과")
- 건수 (예: "125")
- 비율 (예: "94.2%")

### 2.3 성공률 진행바

- 길이: 85.5% (소수 첫째 자리까지)
- 색상: 95% 이상 진초록, 80~94% 초록, 70~79% 노랑, 70% 미만 주황

### 2.4 테이블 열 표시

**목록 화면 (결과 테이블)**
- 파일명: XML 파일 이름 (링크)
- 실행명: 업로드 시 지정한 이름 (없으면 비어있음)
- 총 테스트 수: 숫자
- 통과/실패/에러/건너뜀: 각 상태 건수
- 성공률: 진행바 + 비율 숫자
- 업로드 시간: YYYY-MM-DD HH:MM 형식

**상세 화면 (케이스 테이블)**
- 케이스명: 테스트 메서드명
- 상태: PASS/FAIL/ERROR/SKIPPED 칩
- 실행 시간: 초 단위 (예: "2.34s")
- 에러 메시지: 축약본 (전체는 우측 패널에서 조회)

## 3. 상호작용 규격

| 사용자 동작 | 결과 | 타이밍 |
|---|---|---|
| **목록 화면** | | |
| 업로드 버튼 클릭 | 파일 선택 다이얼로그 열기 | 즉시 |
| XML 파일 선택 | 파일명 표시 | 즉시 |
| 업로드 확인 버튼 클릭 | 업로드 시작 (< 50MB: 동기, ≥ 50MB: 비동기) | 즉시 |
| 기간 필터 선택 (7일/30일/90일) | 해당 기간 데이터만 표시 | 약 1초 |
| 검색 입력 | 파일명으로 결과 필터링 | 약 0.5초(디바운스) |
| 상태 탭 클릭 | 해당 상태 결과만 표시 | 즉시 |
| 파일명 클릭 | 상세 화면 진입 | 약 1초 |
| ⋮ 메뉴 > 다운로드 | 원본 XML 파일 다운로드 | 약 1초 |
| ⋮ 메뉴 > 삭제 | 결과 삭제 확인 다이얼로그 표시 | 즉시 |
| 페이지 변경 | 다음/이전 페이지 데이터 로드 | 약 0.5초 |
| **상세 화면** | | |
| 뒤로가기 클릭 | 목록 화면으로 돌아가기 | 즉시 |
| 스위트 탭 선택 | 선택한 클래스의 케이스만 표시 | 약 0.5초 |
| 케이스 행 클릭 | 우측 패널에 상세정보·에러 메시지 표시 | 즉시 |
| 케이스 검색 입력 | 케이스명으로 필터링 | 약 0.5초(디바운스) |
| 상태 필터 선택 | 해당 상태 케이스만 표시 | 즉시 |
| 편집 버튼 클릭 | 상태·우선순위·노트 필드 편집 가능 | 즉시 |
| 편집 내용 저장 | 서버에 저장·편집 모드 종료 | 약 1초 |

**대용량 파일(≥ 50MB) 처리**: 업로드 직후 다이얼로그에서 **약 2초 주기로 진행 상태 갱신**. 처리 완료 후 다이얼로그 자동 종료 및 목록 새로고침.

## 4. 상태 전이

| 상태 | 조건 | 화면 표시 |
|---|---|---|
| **로딩** | 초기 진입·필터 변경·페이지 변경 | 스켈레톤 또는 로딩 스피너 |
| **정상** | 데이터 로드 완료 | 통계·테이블 표시 |
| **업로드 중** | 파일 선택 후 업로드 시작 | 진행률 표시 (0~100%) |
| **처리 중(대용량)** | 50MB 이상 파일 업로드 완료 | "처리 중입니다" 다이얼로그 + 진행 상태 |
| **빈 화면** | 필터 결과 0건 | "결과가 없습니다" 메시지 |
| **오류** | 업로드 실패·조회 실패 | "오류 메시지" + "다시 시도" 버튼 |
| **편집 모드** | 케이스 편집 버튼 클릭 | 필드 활성화, 저장/취소 버튼 표시 |

## 6. 서버와 주고받는 정보

### 6.1 JUnit XML 파일 업로드

**POST** `/api/junit-results/upload` (파일 선택 후 업로드 확인 시)

파일 크기:
- < 50MB: 동기 처리, 즉시 결과 반환
- ≥ 50MB: 비동기 처리, 처리 상태는 폴링으로 추적

### 6.2 목록 조회

**GET** `/api/junit-results/projects/{projectId}` (화면 진입 및 필터 변경 시)

조회 조건: 기간·상태 필터

### 6.3 상세 조회

**GET** `/api/junit-results/{testResultId}` (파일명 클릭 시)

포함 정보: 파일명·실행명·통계·테스트 스위트 목록

### 6.4 스위트별 케이스 조회

**GET** `/api/junit-results/suites/{suiteId}/cases` (스위트 탭 선택 시)

조회 조건: 상태 필터·페이지네이션

### 6.5 케이스 편집

**PUT** `/api/junit-results/cases/{testCaseId}` (저장 버튼 클릭 시)

저장 내용: 상태·우선순위·노트

### 6.6 삭제

**DELETE** `/api/junit-results/{testResultId}` (메뉴에서 삭제 선택 후 확인 시)

## 9. 유지보수 주의사항

### 9.1 파일 크기 기준 변경 시

50MB는 동기/비동기 처리 분기점이다.

**변경 전에**: 백엔드 설정값 확인 후 프런트엔드 업로드 다이얼로그 검증 규칙과 동기화

### 9.2 대용량 파일 폴링 주기 변경 시

2초는 대용량(≥ 50MB) 파일 처리 상태 갱신 주기다.

**변경 전에**: 서버 처리 속도와 네트워크 부하를 고려해 조정

### 9.3 상태값 추가 시

PASS/FAIL/ERROR/SKIPPED는 JUnit XML 표준 상태값이다.

**커스텀 상태 추가 시**: 
1. statusConfig 객체에 색상·아이콘 추가
2. 필터 옵션에 추가
3. E2E 테스트 업데이트

### 9.4 새 필터 추가 시

새 필터를 추가하면:
1. 필터 UI 요소 추가
2. 브라우저 저장소 키 추가 (기본값 저장용)
3. API 쿼리 파라미터 추가
