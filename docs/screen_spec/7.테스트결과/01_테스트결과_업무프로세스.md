# 테스트 결과(S7) 업무프로세스

> 화면 ID **S7** · 화면명 **결과 통계 · 상세 테이블 · QA 총평 · 내보내기**
> 라우트: `/projects/{projectId}/results`

---

## 1. 업무 목적

S6에서 입력한 테스트 실행 결과를 **조회·분석·보고**한다. 실행된 케이스의 통과율·분포·추이를 한 눈에 보고, QA 총평을 달아, 정책에 맞는 형식의 보고서로 내보낸다.

| 목적 | 내용 |
|---|---|
| ① **통계 조회** | 기간별·필터별 실행 결과 집계를 카드·차트로 본다 |
| ② **상세 검토** | 케이스별 결과를 테이블로 정렬·필터·개별 조회 |
| ③ **QA 총평 작성** | 실행 단위로 분석 의견·권고사항을 마크다운으로 남긴다 |
| ④ **보고서 산출** | 통계를 Excel / PDF / CSV로 내보낸다. 고급 내보내기에는 QA 총평 포함 |

**이 화면이 하지 않는 일**

| 하지 않는 것 | 어디가 맡는가 |
|---|---|
| 실행 결과 입력 | S6 결과 입력 양식(`/executions/{id}/testcases/{tcId}/result`) |
| 자동화 테스트 결과 수집 | S8 자동화 테스트 JUnit 결과 관리 |
| 케이스·플랜 수정 | S4·S5 |
| 실행 삭제 | S6 실행 목록 |

## 2. 화면 위치

| 항목 | 내용 |
|---|---|
| 전(前) | S6 실행 상세에서 결과 입력을 마친 직후 |
| 후(後) | **다른 화면으로의 직접 후행은 없다.** 같은 화면 내에서 필터 변경 재조회 반복 |
| 진입 조건 | 로그인 + 프로젝트 권한 R 이상 |
| 상시 진입 | S2 좌측 메뉴 `테스트 결과` 헤더 탭 S7 항목 |

**라우트 정본: `00_전체_업무프로세스.md` 6.2절** 본 문서는 그 표를 참조만 한다.

## 3. 업무 프로세스 흐름

### 3.1 통계 조회와 필터

| # | 사용자 행위 | 화면 동작 | 결과 |
|---|---|---|---|
| 1 | `/projects/{id}/results` 진입 | 전체 실행 결과를 집계해 통계 카드·차트를 그린다. 데이터 로드 중에는 진행 표시 | 통계 대시보드 노출 |
| 2 | 필터 패널 열기(우상단 `필터`) | 기간·플랜·담당자·결과 상태 필터를 보인다 | 상세 테이블 위에 위치 |
| 3 | 기간 선택 | 시작·종료 날짜 입력 또는 사전 설정(최근 7일·30일·전체) | 필터 적용 |
| 4 | 플랜·담당자·결과 필터링 | 체크박스 또는 멀티셀렉트로 선택 | 상세 테이블과 통계가 함께 갱신 |
| 5 | `[초기화]` 버튼 | 모든 필터 값이 기본값으로 돌아간다 | — |

**통계는 테이블과 독립적이다.** 통계 카드는 전체 또는 선택한 플랜 범위에서 다시 계산되고, 상세 테이블은 그 결과에서 기간·담당자·상태로 추가 필터링 후 페이지네이션된다.

### 3.2 차트 영역과 통계

| # | 차트 종류 | 표시 규칙 | 상호작용 |
|---|---|---|---|
| 1 | 통과율 카드 | 전체 케이스 중 PASS의 비율(백분율) | — |
| 2 | 결과 분포 | PASS / FAIL / BLOCKED / NOTRUN의 카운트 | — |
| 3 | 추이 차트 | 일별·주별 실행 건수와 통과율 꺾은선 | 기간 필터 적용 |
| 4 | 폴더별 통계 | 폴더 트리의 각 노드별 결과 요약 | 접기/펼치기 |
| 5 | 비교 차트 | 여러 실행을 나란히 놓은 통과율 비교(선택적) | — |

**데이터 없음 상태:** 조회 범위에 실행이 0건이면 "결과 데이터가 없습니다" 안내문 + 케이스 작성·실행 유도 텍스트.

### 3.3 상세 테이블 보기

| # | 행위 | 동작 | 참조 |
|---|---|---|---|
| 1 | 테이블 스크롤 | 테이블이 보이는 행만 렌더(가상화) | 매뉴얼 9-3절 |
| 2 | 열 헤더 클릭(정렬) | 케이스명·상태·담당자·실행일시 기준 정렬 | MUI 데이터 표 네이티브 |
| 3 | 개별 행 클릭 | 해당 케이스의 결과 상세(이전 단계: 실행 파이프라인 흐름) | — |
| 4 | 페이지네이션 | "행/페이지 선택" "페이지 이동" | — |

### 3.4 QA 총평 작성

| # | 행위 | 동작 |
|---|---|---|
| 1 | 실행 선택(필터 적용 후) | 필터 결과에 포함된 실행 하나가 활성화된다 |
| 2 | QA 총평 패널 노출 조건 | 실행이 선택되지 않으면 패널이 나타나지 않는다 |
| 3 | 마크다운 에디터 | 최대 10,000자 실시간 프리뷰 |
| 4 | `[저장]` | `PUT /api/executions/{id}` (qaSummary 필드) |
| 5 | 메타데이터 | 작성자·수정 시각 표시(읽기 전용) |

**QA 총평은 실행 단위다.** 같은 날짜의 다른 실행을 선택하면 그 실행의 QA 총평(있으면 기존값, 없으면 비어 있음)이 로드된다.

### 3.5 내보내기

| # | 형식 | 구성 | 기능 |
|---|---|---|---|
| 1 | **Excel** `.xlsx` | 통계 요약 시트 + 상세 결과 시트 | 필터 적용 범위만 포함. QA 총평 미포함 |
| 2 | **PDF (가로)** | 차트 + 통계 테이블 | 한 페이지에 맞춘 가로 레이아웃 |
| 3 | **PDF (세로)** | 상세 테이블을 여러 페이지로 | 각 페이지에 헤더·푸터 |
| 4 | **CSV** | 상세 결과만 | 스프레드시트로 가볍게 옮길 때 |
| 5 | **고급 내보내기** | Excel · PDF · CSV + QA 총평 | PDF 에만 QA 총평이 함께 실린다(매뉴얼 9-4절) |

**고급 내보내기는 QA 총평이 들어간다:** "테스트 요약", "발견 사항", "권고사항" 구간이 각 실행별로 PDF에 삽입되고, Excel·CSV에는 포함되지 않는다(표 형식 부적합).

## 4. 결과 집계 모델

### 4.1 집계의 근거

이 화면의 모든 숫자는 **`TestResult` 테이블의 재조회**에서 나온다. 별도 캐시·집계 테이블이 없다.

| 계산식 | 대상 | 캐시 | 갱신 시점 |
|---|---|---|---|
| 통과율 | `COUNT(status='PASS') / COUNT(*)` | 없음 | 화면 진입 필터 변경 시 재계산 |
| 결과 분포 | `GROUP BY status COUNT(*)` | 없음 | 〃 |
| 추이 | 일/주 단위로 그룹화 | 없음 | 〃 |

**따라서 실시간 갱신이 제약 없다.** S6에서 결과를 저장하면 즉시 이 화면에 반영된다.

### 4.2 기간 필터 계산 규칙

| 필터 | 계산 | 예시 |
|---|---|---|
| **최근 7일** | `TODAY - 7` ~ `TODAY` | 2026-08-03 기준: 2026-07-27 ~ 2026-08-03 |
| **최근 30일** | `TODAY - 30` ~ `TODAY` | 〃: 2026-07-04 ~ 2026-08-03 |
| **전체** | 첫 실행 ~ 현재 | 제약 없음 |
| **사용자 정의** | 입력된 두 날짜 포함 | 〃 |

**날짜는 실행 생성 시각(`TestExecution.createdAt`)을 기준으로 한다.** 결과 입력 시각이 아니다.

## 5. 사용자와 권한

### 5.1 프로젝트 권한 적용

이 화면 진입은 프로젝트 **R 권한** (조회)만 확인한다.

| 권한 | 통계 조회 | 필터링 | QA 총평 작성·편집 | 내보내기 |
|---|---|---|---|---|
| **PM LEAD** | ◯ | ◯ | ◯ | ◯ |
| **DEVELOPER CONTRIBUTOR** | ◯ | ◯ | △ (실행 작성자만) | ◯ |
| **TESTER** | ◯ | ◯ | ◯ (자신이 입력한 결과의 실행) | ◯ |
| **VIEWER** | ◯ | ◯ | × | ◯ |

⚠ **확인 필요.** QA 총평의 편집 권한 (`DEVELOPER`가 모든 실행의 총평을 쓸 수 있는지, 아니면 자신이 담당한 실행만 쓸 수 있는지)을 코드로 확인한다.

### 5.2 시스템 권한

`ADMIN`은 모든 프로젝트의 결과를 본다. 프로젝트 권한 검사를 우회하지 않는다 (ADMIN이 모든 프로젝트에 자동 접근 가능이 아님).

## 6. 기능 규칙 10개 (G1~G10)

### G1. 필터와 통계의 동기화

필터 하나라도 바뀌면 통계 카드·차트·테이블이 모두 **동시에** 갱신된다. 스핀 표시는 한 번만 나타난다.

### G2. 상태 값의 정의

테스트 결과의 상태는 통과·실패·차단·미실행 네 가지다.

| 값 | 표시 | 조건 |
|---|---|---|
| **PASS** | 🟢 녹색 `통과` | 케이스 기대 결과와 실제 결과가 일치 |
| **FAIL** | 🔴 빨강 `실패` | 불일치. 결함으로 의심됨 |
| **BLOCKED** | 🟠 주황 `차단됨` | 실행할 수 없는 환경·선행조건 미충족 |
| **NOTRUN** | ⚪ 회색 `미실행` | 플랜에는 있으나 결과가 입력되지 않음 |

### G3. 실행 미선택 시 QA 총평 미노출

필터 결과에 실행이 1건 이상 있어도, 사용자가 어느 실행의 총평을 쓸지 명시적으로 선택해야 한다. 선택 전에는 패널이 회색으로 비활성화된다.

### G4. 내보내기 형식의 선택

"Excel" "PDF(가로)" "PDF(세로)" "CSV" "고급 내보내기(Excel+QA)" "고급 내보내기(PDF+QA)" 6가지 옵션을 드롭다운으로 제시한다.

### G5. 큰 결과 세트의 성능 최적화

테이블이 1,000건 이상이어도 가상화로 즉시 렌더된다. 페이지당 행 수는 기본 50개, 사용자가 변경 가능 (모두 보기·25개·50개·100개).

### G6. 내보내기 진행 표시

내보내기 버튼 클릭 후 "준비 중..." 상태를 1~3초 표시한 뒤 파일 다운로드가 시작된다.

### G7. 차트 범주 이름의 한국어화

차트 축 라벨 범례 툴팁은 모두 한국어 또는 국제화된 언어로 표시된다 (`t` 함수 사용).

### G8. 기간 필터의 기본값

화면 진입 시 기본값은 "최근 30일"이다. 사용자가 선택하면 로컬스토리지에 저장되어 다음 진입 시 유지된다.

### G9. 실행 비교 모드

2개 이상의 실행을 선택하면 비교 모드 차트(나란히 놓인 막대)가 활성화된다. 1개 선택으로 돌아가면 기본 통계로 복귀.

### G10. 상태 배지의 일관성

이 화면의 결과 상태 배지는 S6 (결과 입력 양식)의 것과 같은 색상·모양이다. 제품 전체에서 "PASS = 녹색"을 유지한다.

## 8. 전제와 제약

| 제약 | 사항 |
|---|---|
| **API 재조회** | 필터 변경마다 전체 결과를 다시 조회한다. 결과가 매우 크면 (1만건 이상) 응답 지연이 발생할 수 있다 |
| **오프라인 미지원** | 캐시 없이 항상 서버 조회이므로 오프라인에서는 통계가 갱신되지 않는다 |
| **시간대 표시** | 실행 시각은 서버 시간대 기준이다. 클라이언트 시간대는 반영되지 않는다 |
| **QA 총평 크기** | 10,000자 초과 입력은 저장 전에 차단된다 |
| **내보내기 크기** | 50,000건 이상 결과는 PDF 내보내기에서 성능 저하가 발생할 수 있다 |
