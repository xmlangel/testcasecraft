## 3. 데이터 로딩

### 3.1 멤버 조회의 중복 차단

`loadProjectMembers()`(`:143-194`)가 세 겹으로 막습니다.

```
캐시 히트 → 즉시 반환                              :146-149
진행 중 요청 있음 → 그 Promise 공유                :151-154
없음 → 요청 시작 + Ref에 Promise 등록 → 완료 시 삭제 :156-193
```

**캐시 키가 프로젝트 ID가 아니라 조직 단위입니다**(`membersCacheKeyFor`). 같은 조직에 프로젝트가 여러 개면 멤버 API는 한 번만 호출됩니다. 카드가 마운트될 때마다 자동으로 부르는 구조(`:493-503`)여서 이 차단이 없으면 같은 요청이 카드 수만큼 나갑니다.

### 3.2 소속에 따라 다른 API를 쓴다

| 소속 | 호출 | 근거 |
|---|---|---|
| 조직 프로젝트 | `GET /api/organizations/{orgId}/members` | `:165-168` |
| 독립 프로젝트 | `GET /api/projects/{projectId}/members` | `:169-170` |

돌아오는 객체의 형태가 달라서 역할 필드를 순서대로 골라 씁니다(`:651-655`). 조직 멤버는 `roleInOrganization`, 프로젝트 멤버는 `roleInProject`를 갖습니다.

### 3.3 실패해도 화면을 세우지 않는다

멤버 조회가 실패하면 콘솔에 남기고 빈 배열을 캐시합니다(`:184-188`). 카드는 `멤버가 없습니다`로 그려집니다.

조직 API가 실패해도 프로젝트 데이터로 화면을 그립니다(`:197-` 주석 `ICT-288`). 조직 정보는 부가 정보이므로 목록 전체를 막지 않습니다.

## 8. 유지보수 주의

1. **탭을 추가하면 세 곳을 함께 고칩니다**: 조건 플래그(`:739-741`), 표시/내부 인덱스 역변환(`:845-855`), `TabPanel` 블록. 인덱스를 박아 두면 조건부 탭에서 어긋납니다.
2. **`ProjectCard`를 파일 밖으로 분리하려면 클로저 의존 3개를 props로 옮깁니다**: `projectMembers`·`loadProjectMembers`·`renderJunitStatus`.
3. **멤버 캐시 키를 프로젝트 ID로 되돌리지 않습니다.** 같은 조직 프로젝트가 많을 때 요청이 카드 수만큼 늘어납니다.
4. **`project-code` 칩의 잘못 붙은 `htmlInput`을 지웁니다**(4절). testid 이름이 겹쳐 있습니다.
5. **삭제 확인 문구를 `t()`로 감쌉니다**(02 6절). 지금은 영어 모드에서 한국어가 나옵니다.
6. **`⋮` 메뉴에 권한 조건을 붙입니다**(01 5.2절). 지금은 권한 없이도 항목이 보이고 서버가 거부합니다.
7. **`hasProjectCreationAccess`를 시스템 역할 검사로 되돌리지 않습니다.** `role=null` 사용자가 막히는 회귀가 있었습니다(`:129-134` 주석).
