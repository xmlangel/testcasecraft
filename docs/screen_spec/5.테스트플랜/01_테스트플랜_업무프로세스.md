# 테스트플랜(S5) 업무프로세스

화면 ID: S5

---

## 1. 업무 목적

테스트 플랜은 **케이스 묶음을 실행 단위로 정의**한다. 케이스는 트리에서 산재하게 보관되지만, 한 번에 실행할 케이스를 고르면 그게 플랜이 된다. 플랜은 그 묶음의 이름·설명·포함 케이스 목록을 저장하고, 실행을 만들 때 같은 케이스 묶음을 물려받게 한다.

| 목적 | 내용 |
|---|---|
| ① **플랜 관리** | 프로젝트의 전체 플랜을 카드/목록으로 보고 어느 플랜에 몇 개의 케이스가 들어가 있는지 한눈에 본다 |
| ② **플랜 생성** | 이름·설명·포함할 케이스를 선택해 새 플랜을 만든다 |
| ③ **플랜 수정** | 생성한 플랜의 이름·설명·포함 케이스를 바꾼다 |
| ④ **플랜에서 실행 만들기** | 플랜을 선택 → 실행 생성 폼으로 넘어가며 그 플랜의 케이스를 실행에 자동으로 담는다 |
| ⑤ **플랜 아래 실행 목록 보기** | 좌측 메뉴 레이아웃에서 플랜을 펼치면 그 플랜의 실행이 트리로 딸려 나온다 |
| ⑥ **자동화 결과 연결** | 업로드한 JUnit 결과를 플랜과 매칭해서 통계에 합친다 |

**이 화면이 하지 않는 일**

| 하지 않는 것 | 어디가 맡는가 |
|---|---|
| 케이스 작성·수정 | S4 테스트케이스 |
| 실행 상세·결과 기록 | S6 테스트실행 |
| 통계·보고 | S3 대시보드 S7 테스트결과 |
| JUnit 파일 업로드 | S8 자동화테스트 |

## 3. 업무 프로세스 흐름

### 3.1 목록 조회

| # | 사용자 행위 | 화면 동작 | 결과 |
|---|---|---|---|
| 1 | `/projects/{projectId}/testplans` 진입 | 해당 프로젝트의 전체 플랜을 조회한다. 조회 중에는 로딩 표시 | — |
| 2 | 플랜 0건 | 빈 상태 안내 + `[+ 새 플랜 생성]` 버튼 | — |
| 3 | 플랜 N건 | 페이지네이션과 함께 테이블 또는 카드 그리드로 표시 | — |
| 4 | 카드/행 클릭 | 가로 탭 레이아웃: 플랜 상세 팝업 좌측 메뉴: 오른쪽 상세 영역 | 플랜 이름·설명·포함 케이스 수 표시 |

생성일(`createdAt`) 순으로 오래된 것부터 정렬된다.

### 3.2 생성

| # | 행위 | 동작 |
|---|---|---|
| 1 | `[+ 새 플랜 생성]` | 생성 폼 다이얼로그(가로 탭) 또는 오른쪽 영역(좌측 메뉴) |
| 2 | 이름·설명 입력 케이스 선택 | 다중 선택 트리 — 폴더도 선택 가능(폴더 안 모든 케이스 포함) |
| 3 | `[저장]` | `POST /api/test-plans` |
| 4 | 성공 | 목록 갱신. 새 플랜이 목록에 생긴다 |
| 5 | 실패 | 다이얼로그 안 빨간 알림. 입력값 유지 |

**⚠ 확인 필요.** 폴더를 선택할 때 폴더 자체가 포함되는지(폴더 안 전체 케이스만) 테스트로 확인한다.

### 3.3 수정

| # | 행위 | 동작 |
|---|---|---|
| 1 | 플랜 카드/행의 `✎ 수정` 메뉴 또는 상세에서 `[수정]` | 생성 폼을 수정 모드로 연다 |
| 2 | 이름·설명·포함 케이스 변경 | 새로 선택한 케이스로 교체 |
| 3 | `[저장]` | `PUT /api/test-plans/{id}` |
| 4 | 성공 | 목록 갱신. 플랜 정보 반영 |

**⚠ 확인 필요.** 포함 케이스를 빼거나 늘릴 때, 이미 실행으로 만들어진 케이스와 플랜의 케이스 목록이 달라진다. 이 경우 실행 상세에는 어느 케이스가 보이는지 확인한다 (S6 문서 참조).

### 3.4 플랜에서 실행 만들기

| # | 행위 | 동작 |
|---|---|---|
| 1 | 플랜 상세에서 `[실행 시작]` | 실행 생성 폼으로 이동 |
| 2 | 실행 생성 폼 | 플랜 선택 필드가 이미 "이 플랜"으로 채워져 있다 |
| 3 | 케이스 목록 | 이 플랜에 포함된 케이스만 표시된다 |
| 4 | 실행 저장 | 이 플랜의 케이스 묶음을 `TestExecution.testPlanId = {planId}`로 저장 |

실행 생성 후 실행이 플랜을 참조하므로, 나중에 플랜을 수정해도 기존 실행의 케이스는 그대로 유지된다.

### 3.5 2단 레이아웃에서 플랜 트리

좌측 메뉴 레이아웃(`LEFT_NAV_RESTRUCTURE.md` 참조)에서는 플랜 목록이 **플랜을 부모로 세운 트리** 형태다.

| 구조 | 동작 |
|---|---|
| **플랜(부모)** | 화면의 가지 아이콘 `▶` 클릭 또는 좌클릭 → 펼침 |
| **실행(자식)** | 플랜 아래에 그 플랜으로 만든 실행이 최신순으로 표시됨 |
| **실행 행 선택** | 실행을 클릭 → 오른쪽 상세가 그 실행 내용으로 바뀐다 |
| **플랜으로 돌아가기** | 실행 상세의 헤더에서 `← 플랜으로` 버튼 → 오른쪽이 플랜 내용으로 돌아감 |

## 4. 플랜 모델 규칙

| # | 규칙 | 내용 |
|---|---|---|
| T1 | **플랜은 케이스 스냅샷을 만들지 않는다** | 플랜에 케이스를 추가할 때 그 시점의 케이스 버전을 고정하지 않는다. 나중에 케이스 내용이 바뀌면 플랜에도 반영된다 |
| T2 | **실행은 실행 생성 시점의 케이스를 물려받는다** | 플랜에서 실행을 만들 때 그 플랜의 케이스 목록을 복사해서 `TestExecution.testCaseIds`에 저장한다. 이후 플랜이 바뀌어도 그 실행의 케이스는 그대로다 |
| T3 | **플랜이 없는 실행도 가능하다** | `TestExecution.testPlanId`가 nullable이므로 플랜 없이 케이스를 선택해 실행할 수 있다 |
| T4 | **플랜 삭제는 기존 실행에 영향을 주지 않는다** | 플랜을 지워도 그 플랜으로 만든 실행은 계속 존재한다. 실행의 `testPlanId`만 비워진다 |
| T5 | **케이스 삭제는 플랜에도 반영된다** | 케이스를 삭제하면 그 케이스를 포함한 플랜의 목록에서도 자동으로 제거된다 |

## 8. 전제와 제약

### 8.1 레이아웃 두 갈래

S5 화면은 프로젝트 설정에 따라 **두 가지 레이아웃**으로 표현된다 (`LEFT_NAV_RESTRUCTURE.md` 참조).

| 레이아웃 | 화면 구성 | 사용자 경험 | 문서 대상 |
|---|---|---|---|
| **가로 탭** (기본) | 탭 선택 → 전체 화면을 페이지 전환 플랜 카드 → 팝업 또는 별도 페이지 | 페이지 중심 내비게이션 | S5 → S6는 라우트 이동 |
| **좌측 메뉴** (신규, `LEFT_NAV_RESTRUCTURE.md`) | 좌측: 플랜/실행 트리 우측: 상세 영역이 바뀜 팝업 없음 | 2단 작업공간 맥락 유지 | 규약 |

두 레이아웃의 **기본 기능은 같지만 UX가 다르다.** 가로 탭에서는 팝업/전체 화면으로 빠지고, 좌측 메뉴에서는 왼쪽 목록에서 오른쪽 상세로 바뀐다.
