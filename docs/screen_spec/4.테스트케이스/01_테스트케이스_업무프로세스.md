# 테스트케이스(S4) 업무프로세스

화면 ID: S4

---

## 1. 업무 목적

프로젝트의 테스트 자산은 테스트케이스(TC) 트리로 조직된다. S4는 이 트리를 보고, 케이스를 만들고 고치고, 폴더를 짜고, 파일을 붙이고, 실행 이력을 추적하는 작업공간이다. 케이스는 한 번 작성되면 여러 프로젝트의 테스트 플랜에서 참조되므로, 수정·삭제·이동은 권한과 영향도를 엄격히 확인한다.

| 목적 | 내용 |
|---|---|
| ① **케이스 조회 검색** | 폴더 트리 또는 전체 케이스 목록을 보고, 이름 부분일치로 검색한다 |
| ② **케이스 작성** | 신규 폼 모드 또는 인라인 생성으로 케이스를 만든다. AI 자동 생성 옵션 유무 |
| ③ **케이스 편집** | 필드 가시성 토글, 필드값 입력, 버전 생성으로 케이스를 고친다 |
| ④ **트리 재구성** | 드래그앤드롭으로 폴더/케이스를 이동하거나, 다른 프로젝트로 옮긴다 |
| ⑤ **케이스 수명** | 복사 이동 삭제 버전 조회 첨부 관리 실행 이력 조회 |

**이 화면이 하지 않는 일**

| 하지 않는 것 | 어디가 맡는가 |
|---|---|
| 테스트 플랜 편성 | S2 테스트 플랜 |
| 케이스 실행 결과 기록 | S5 실행 관리 |
| 케이스 분석 통계 | S6 테스트 분석 |
| 자동화 스크립트 관리 | S8 자동화 |

## 2. 화면 위치

| 항목 | 내용 |
|---|---|
| 전(前) | S1 프로젝트 선택 → S2 작업공간 |
| 후(後) | S5 실행 관리(`/projects/{projectId}/testresults`) S6 분석(`/projects/{projectId}/analysis`) |
| 진입 조건 | 프로젝트 편집 권한(EDITOR 이상). VIEWER는 읽기만 가능. 익명 사용자는 진입 불가 |
| 상시 진입 | 영역 이동의 `[테스트케이스]` 항목 |

**동적 진입:** 헤더의 `프로젝트 선택` 드롭다운에서 다른 프로젝트를 고르면 같은 S4 화면이지만 다른 `projectId`로 리로드된다.

## 3. 업무 프로세스 흐름

### 3.1 트리 조회 및 폴더 구조

프로젝트는 시스템 생성 폴더 3개(`Uncategorized`, `Automated Test Case`, `Manual Test Case`)로 시작되며, 사용자가 추가 폴더를 만들 수 있다.

| # | 행위 | 동작 | 결과 |
|---|---|---|---|
| 1 | `/projects/{projectId}/testcases` 진입 | 프로젝트의 모든 TC 트리를 로드한다 | — |
| 2 | **보기 모드 선택** | `[폴더만]` 또는 `[전체]` 버튼으로 트리 모드를 전환한다 | 선택은 브라우저 저장소에 저장됨 |
| 3 | 폴더 전용 모드 | 폴더 노드만 보인다. 폴더 우측 숫자는 하위 케이스 개수(모두 포함) | — |
| 4 | 전체 모드 | 폴더와 그 안의 모든 케이스를 함께 본다 | — |
| 5 | selectable 모드 | 테스트 플랜(S2)에서 케이스를 선택할 때만 사용. 항상 전체 모드로 강제된다 | — |

### 3.2 테스트케이스 작성

#### 신규 폼 모드
| # | 행위 | 동작 |
|---|---|---|
| 1 | 트리에서 폴더 우측 클릭 → `[케이스 추가]` 또는 `[+]` 버튼 | 신규 폼 다이얼로그(전체 필드 표시) |
| 2 | 표시 ID(자동) 이름 설명 태그 우선순위 타입 스텝(표 형식) 입력 | 필드 자동저장(자동 버전 생성 X) |
| 3 | `[저장]` 클릭 | `POST /api/testcases` 엔드포인트 호출 |
| 4 | 성공 | 폴더 트리 갱신. 새 케이스 아이콘으로 표시 |

#### 인라인 생성
| # | 행위 | 동작 |
|---|---|---|
| 1 | 트리의 빈 폴더에서 `[인라인 추가]` 또는 Enter | 인라인 입력 필드(이름만 입력) |
| 2 | 이름 입력 후 Enter | 최소 필드로 케이스 생성 |
| 3 | 이어서 편집 팝업 열림 | 나머지 필드를 채울 수 있음 |

#### AI 자동 생성(선택사항)
| # | 행위 | 동작 |
|---|---|---|
| 1 | 신규 폼의 `[AI로 생성]` 버튼 | 요약 또는 제목에서 스텝 기대결과를 자동 생성 |
| 2 | 생성 결과 | 폼에 자동 삽입되며, 사용자가 수정 가능 |

### 3.3 테스트케이스 편집

| # | 행위 | 동작 |
|---|---|---|
| 1 | 트리에서 케이스 더블클릭 또는 우측 클릭 → `[편집]` | 편집 폼 다이얼로그 열림 |
| 2 | 필드 가시성 토글 | 약 50개 필드 중 보일 필드를 선택. 선택은 사용자별 저장 |
| 3 | 필드값 입력 | 이름 설명 스텝 테이블 기대결과 태그 등을 고친다. 자동저장 |
| 4 | `[저장]` 또는 자동저장 | `PUT /api/testcases/{id}` |
| 5 | 버전 생성(선택사항) | 의미 있는 변경 시 버전 샤프(#1, #2,...)를 명시적으로 기록 |

**스프레드시트 모드:** 여러 케이스를 표 형식으로 일괄 편집할 수 있으나, 이 화면의 기본은 폼 모드다(S4 상세 문서 참조).

### 3.4 트리 재구성 (DnD)

같은 프로젝트 내 이동:
| # | 행위 | 동작 | 반응 |
|---|---|---|---|
| 1 | 케이스/폴더 드래그 | 마우스 또는 터치로 드래그 시작 | DragOverlay 표시 |
| 2 | 다른 폴더 위에 드롭 | 목표 폴더가 강조(hover) | — |
| 3 | 드롭 실행 | `POST /api/testcases/{id}/move` 호출. parentId와 displayOrder 갱신 | 트리 즉시 갱신 |
| 4 | 검증 실패 | 시스템 폴더면 400 Bad Request. 권한 없으면 403 Forbidden | 다이얼로그 오류 표시 |
| 5 | 일괄 이동 | 여러 케이스 체크 후 `[선택한 것을 폴더로 이동]` | `POST /api/testcases/move-batch` |

다른 프로젝트로 이동:
| # | 행위 | 동작 |
|---|---|---|
| 1 | 트리의 케이스 우측 클릭 → `[다른 프로젝트로 이동]` | 대상 프로젝트 선택 다이얼로그 |
| 2 | 대상 프로젝트 선택 | 현재 프로젝트는 제외됨 |
| 3 | `[이동]` 실행 | `POST /api/testcases/cross-project/move` 호출. 테스트 결과를 미러 실행으로 함께 옮김 |
| 4 | 권한 확인 | 출발 조회(VIEWER 이상) + 대상 편집(EDITOR 이상) 필요 |
| 5 | 복사(결과 미포함) | `POST /api/testcases/cross-project/copy` 호출 |

**DnD 차단 규칙:** 시스템 폴더(`Uncategorized`, `Automated Test Case`, `Manual Test Case`)는 이동·삭제할 수 없다. 그 아래 케이스는 이동 가능하지만 폴더는 유지된다(매뉴얼 4-4절).

### 3.5 버전 첨부 실행 이력 관리

| # | 항목 | 동작 |
|---|---|---|
| 1 | **버전 탭** | `[v1.0]`, `[v1.1]`,... 링크를 누르면 그 버전의 스냅샷을 본다 |
| 2 | 버전 생성 | `[버전 저장]` 버튼으로 현재 상태를 명시적으로 기록. `{major}.{minor}` 형식 |
| 3 | **첨부 탭** | 스크린샷 문서 코드 파일 업로드 |
| 4 | 첨부 조회 | `GET /api/testcases/{id}/attachments/{attachmentId}/download` |
| 5 | **실행 이력 탭** | 이 케이스를 포함한 모든 테스트 실행 결과 조회(5건 최근순) |

## 4. 케이스 모델 규칙

| # | 규칙 | 내용 | 근거 |
|---|---|---|---|
| M1 | **표시 ID는 불변(자동)** | 프로젝트 코드 + 순번(예: `SMP-001`). 생성 후 바꿀 수 없다 | 매뉴얼 5-1절 |
| M2 | **시스템 폴더 3개는 보호** | `Uncategorized`(미분류), `Automated Test Case`(자동화), `Manual Test Case`(수동) 폴더는 이동·삭제 불가능 | `TestCaseTreeMoveService` 검증 |
| M3 | **폴더와 케이스는 레벨 구분** | 폴더 아래 폴더, 폴더 아래 케이스. 같은 부모 안에서 순서 변경 가능 | 트리 모델 |
| M4 | **버전은 명시적 스냅샷** | 자동저장은 초안이고, `[버전 저장]`만 히스토리에 남는다 | (v1.6.1 정책) |
| M5 | **태그는 상속 가능** | 부모 폴더의 태그를 자식이 자동 상속할 수 있다 | `TestCaseFormUtils.getCommonInheritedTags` |
| M6 | **캐스케이드 삭제** | 폴더 삭제 시 그 아래 모든 케이스·버전·첨부가 함께 삭제된다 | `TestCaseService.deleteTestCase` |
| M7 | **다른 프로젝트 참조는 명시** | 테스트 플랜(S2)에서 다른 프로젝트의 케이스를 참조할 수 있으나, 삭제 시에는 해제된다 | 매뉴얼 6-2절 |

| 케이스 다른-프로젝트 이동 | ❌ | ❌ | ✅ |
| 케이스 다른-프로젝트 복사 | ❌ | ✅ | ✅ |
| 첨부 업로드 | ❌ | ✅ | ✅ |
| 첨부 삭제 | ❌ | ❌ | ✅ |

## 6. 기능 규칙

| # | 규칙 | 내용 | 근거 |
|---|---|---|---|
| F1 | **트리 필터는 이름 부분일치** | 검색 필드에 텍스트 입력 시 케이스 이름이 포함된 항목과 그 조상(부모)을 보인다 | (filterText) |
| F2 | **선택은 필터 범위 제한** | 검색으로 좁혀진 상태에서는 체크/선택 대상도 필터링된 항목으로만 가능(ICT-431) | |
| F3 | **폴더 숫자는 하위 전부** | 폴더 우측의 개수는 그 아래 모든 케이스(하위 폴더의 케이스 포함)의 합 | `buildFolderCaseCountMap` 유틸 |
| F4 | **가상 노드(폴더 전용 모드)** | 폴더 전용 모드에서 보이는 "Unfiled"는 어떤 폴더에도 속하지 않은 케이스를 모은 가상 노드 | `VIRTUAL_UNFILED_ID` 상수 |
| F5 | **DnD 순서는 다음 케이스 전 또는 후** | beforeId/afterId 중 하나를 지정해 순서를 정한다. 둘 다 null이면 자식 끝에 추가 | `TestCaseMoveRequest` DTO |
| F6 | **같은 부모로 일괄 이동** | `/move-batch` 엔드포인트는 선택한 케이스를 모두 같은 부모 폴더로 옮기고, 순서는 선택 순서대로 | `TestCaseMoveBatchRequest` |
| F7 | **시스템 폴더 진입 금지** | 폴더 목록에서 시스템 폴더(`Uncategorized` 등)를 parentId로 선택하면 400 Bad Request | `SystemFolderProtectedException` |
| F8 | **버전 변경 감지** | 필드가 바뀌면 자동저장 상태로 전환되고 `[버전 저장]` 버튼이 활성화됨 | 자동 저장 훅 |
| F9 | **첨부 크기 제한** | 첨부 파일 개당 최대 100MB(HTTP multipart 설정, API 문서 참조) | 서버 설정 |
| F10 | **구버전 복원 금지** | 이전 버전을 보기만 하고 그것으로 되돌릴 수는 없다. 대신 수정 후 새 버전을 저장해야 한다 | VersionHistory 컴포넌트(읽기 전용) |

## 8. 전제와 제약

| 항목 | 내용 | 근거 |
|---|---|---|
| **프로젝트 존재** | 이 화면은 프로젝트 ID가 경로에 있어야 작동. 없으면 S1로 되돌아간다 | |
| **폴더 쓰기 권한** | 새 폴더를 만들려면 EDITOR 이상의 권한이 필요하다 | 권한 판정 규칙 |
| **API 응답 시간** | 트리 로드는 프로젝트당 케이스 수에 따라 0.5~2초 소요. 검색 필터링은 프론트 메모리 기반이라 <100ms | `testCaseService.getProjectTestCases` |
| **동시성** | 같은 케이스를 두 사용자가 동시 편집 중일 때는 마지막 저장이 우선된다(충돌 방지 로직 없음, 매뉴얼 주의) | — |
| **마이그레이션** | 기존 버전(v1.0 이전)의 케이스는 기본값으로 `Uncategorized` 폴더에 배치된다 | 매뉴얼 20절 |
