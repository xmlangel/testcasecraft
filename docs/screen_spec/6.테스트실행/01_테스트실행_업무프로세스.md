# 테스트 실행(S6) 업무프로세스

> 화면 ID **S6** 화면명 **테스트 실행 목록 생성 상세 결과 기록**
> 정본 입력: `00_전체_업무프로세스.md` 2절 단계 5 5절 6.3절 매뉴얼 8절 test_execution_manual.md test_result_input_manual.md
> 라우트: `/projects/{projectId}/executions` `/executions/new` `/executions/{executionId}` `/executions/{executionId}/testcases/{testCaseId}/result`

---

## 1. 업무 목적

테스트 케이스를 모아 구성한 실행 계획(플랜)을 바탕으로 실제 테스트를 진행하고, 케이스별 결과(통과/실패/차단/미실행)를 기록하는 화면이다. 플랜 없이도 실행을 만들 수 있으며, 기록된 결과는 대시보드와 결과 화면의 통계에 실시간 반영된다.

| 목적 | 내용 |
|---|---|
| ① **실행 계획 선택** | 미리 구성한 플랜(케이스 묶음)을 선택해 실행을 만든다. 또는 플랜을 지정하지 않고 실행을 만든다 |
| ② **진행 상황 조회** | 실행 목록에서 각 실행의 상태(진행 중/완료), 진행률(케이스 중 N개 완료), 소속 플랜을 본다 |
| ③ **케이스별 결과 기록** | 실행 안의 케이스를 하나씩 열어 결과(P/F/B/N)와 노트·태그·JIRA·첨부를 기입한다 |
| ④ **자동 저장** | 결과를 수정하면 약 1.5초 후 자동 저장된다. 보기만 하면 저장하지 않는다 |
| ⑤ **이전 결과 확인** | 같은 케이스를 다시 테스트할 때 이전 결과를 마크다운이나 평문으로 볼 수 있다 |

**이 화면이 하지 않는 일**

| 하지 않는 것 | 어디가 맡는가 |
|---|---|
| 플랜 생성·케이스 추가 | S5 테스트 플랜 |
| 통계·대시보드 조회 | S3 대시보드 S7 결과 통계 |
| 결과 내보내기(Excel/PDF) | S7 결과 통계 |

## 2. 화면 위치

| 항목 | 내용 |
|---|---|
| 전(前) | S5 플랜 상세에서 `[실행 만들기]` 또는 S3 대시보드 `[실행 시작]` |
| 후(後) | S3 대시보드 S7 결과 통계(결과 저장 시 자동 갱신) |
| 진입 조건 | 로그인 + 프로젝트 참여 + 편집 권한(실행 생성) 또는 결과 기록 권한(TESTER 포함) |
| 상시 진입 | S2 좌측 메뉴 `[테스트 실행]` 또는 헤더의 영역 탭 |

`/executions` 로 시작하는 URL은 모두 S6 영역에서 렌더된다. 플랜 선택은 S5 후속 → S6 진입이 일반적이나, S1 프로젝트 카드에서 직접 실행을 만들 수도 있다.

## 3. 업무 프로세스 흐름

### 3.1 실행 목록 조회

| # | 사용자 행위 | 화면 동작 | 결과 |
|---|---|---|---|
| 1 | `/projects/{id}/executions` 진입 | 해당 프로젝트의 모든 실행을 조회한다. 최신 순 20개씩 페이징 | — |
| 2 | (화면 표시) | 페이지마다 5개씩 표시하고, 아래로 스크롤하면 다음 페이지를 불러온다 | — |
| 3 | (배경) | 탭이 활성(포커스)된 동안 20초마다 목록을 자동 갱신한다. 탭이 비활성이면 일시정지 | 진행 중인 실행의 상태·진행률이 실시간 반영 |
| 4 | 제목으로 검색 | 입력한 문자가 제목에 포함된 실행만 보인다. 검색어는 세션 보존 | — |
| 5 | 실행 카드 클릭 | 그 실행의 케이스 목록을 열고, 필터 패널이 우측에 나타난다 | 상세 화면(영역 3) |
| 6 | 실행 삭제 | 메뉴에서 삭제를 선택하면 확인 다이얼로그가 뜨고, 승인하면 삭제된다 | — |

자동 갱신은 탭 가시성(Visibility API)을 감지해 브라우저 탭이 백그라운드면 멈춘다. 20초는 고정값이고 서버 설정으로 조정할 수 없다.

### 3.2 실행 생성

| # | 행위 | 동작 |
|---|---|---|
| 1 | `[+ 새 실행]` 버튼 또는 S5 플랜 상세에서 `[실행 만들기]` | 생성 폼을 열거나 S5 플랜을 미리 선택한 상태로 연다 |
| 2 | 실행 이름 입력 | 플랜과 무관하게 자유로운 이름 |
| 3 | 플랜 선택 | 드롭다운에서 플랜을 고르거나, 진입 버튼이 있으면 미리 선택됨 |
| 4 | `[저장]` | `POST /api/test-executions` 실행이 생기고, 같은 실행의 케이스 목록으로 진입 |

플랜이 필수가 아니므로, "이 회차는 임의로 선택한 몇 가지 케이스만 테스트하겠다" 같은 상황에도 대응할 수 있다.

### 3.3 케이스별 결과 기록

| # | 행위 | 동작 | 근거 |
|---|---|---|---|
| 1 | 실행 내 케이스 행 클릭 | 결과 입력 화면으로 이동 (`/executions/{eid}/testcases/{tcid}/result`) | — |
| 2 | (결과 입력 화면) | 케이스 제목·설명·스텝 수를 읽고, 아래 플로팅 버튼 4개(P/F/B/N)로 결과를 기입 | — |
| 3 | 노트·태그·JIRA 추가 (선택) | 각 필드를 채우면 약 1.5초 후 자동 저장된다 | — |
| 4 | 첨부 파일 추가 (선택) | 이미지·파일을 드래그 앤드롭하거나 업로드 버튼으로 추가 | |
| 5 | 이전 결과 확인 | 같은 케이스의 과거 결과를 다이얼로그에서 마크다운·평문 토글로 본다 | 매뉴얼 8-4-6절 |
| 6 | 이전/다음 버튼 | 같은 실행의 다음 미실행 케이스로 진행 | — |

PASS(P), FAIL(F), BLOCKED(B), NOT_RUN(N)이 4값이다. SKIPPED는 **자동화 도구에서만 들어오고**, 수동 기록에는 선택지가 없다.

**자동 저장 가드**: 결과 필드를 수정할 때만 저장을 시도한다. 같은 케이스를 여러 번 열어도 변경 없으면 빈 `TestResult` 레코드가 쌓이지 않는다. 이 가드를 제거하면 조회만 해도 레코드가 생기는 회귀가 발생(`매뉴얼 8-4-3절` 주의사항).

### 3.4 테스트케이스 첨부파일 영역

결과 입력 화면 하단에 **케이스의 첨부파일**(설정·스크린샷 등, S4에서 업로드된 것)을 읽기 전용으로 보여 준다. TESTER가 권한을 갖지 않으므로 첨부파일은 실행 전에 다 준비되어 있어야 한다.

## 4. 실행·결과 모델 규칙

| 항목 | 규칙 |
|---|---|
| **실행 상태** | DRAFT(작성 중) / IN_PROGRESS(진행 중) / COMPLETED(완료) |
| **결과 상태** | PASS FAIL BLOCKED NOTRUN SKIPPED |
| **SKIPPED 출처** | 자동화 도구(S8)에서만 들어온다. 수동 기록에는 선택지가 없다 |
| **태그 상속** | 실행에 태그를 붙이면 하위 모든 결과에 같은 태그가 상속된다 |
| **결과 타임스탬프** | 각 결과는 저장 시각을 기록한다. 같은 케이스를 다시 테스트해도 최신 결과만 표시된다 |

### 5.2 결과 기록

| 권한 | 기록 가능 | 근거 |
|---|---|---|
| PM·LEAD·DEV·CONTRIBUTOR | ○ | 프로젝트 편집 권한Content` |
| **TESTER** | **○** | 결과 기록 권한|
| VIEWER | — | — |

**TESTER의 역할**: 편집 권한이 없지만 **결과 기록은 가능**하다. 케이스를 읽고 테스트하고 결과를 남기는 것이 TESTER의 전담 업무다. 이 권한이 없으면 TESTER는 결과 입력 화면에서 P/F/B/N 버튼이 비활성화되고, 노트·태그·첨부도 채울 수 없다.

## 6. 기능 규칙

| 규칙 | 내용 | 위반 시 |
|---|---|---|
| **플랜 미지정 실행** | 실행 생성 시 플랜을 선택하지 않으면, 케이스를 수동으로 추가할 수 있다(현재 미구현, 로드맵 항목) | — |

| **검색어 보존** | 프로젝트별로 마지막 검색어를 sessionStorage에 저장했다가, 같은 프로젝트를 다시 열면 복원한다 | |

## 7. 타 화면 연동

| 출발지 | 도착지 | 계약 | 근거 |
|---|---|---|---|
| **S5 플랜** | S6 실행 생성 | 플랜 ID를 실행에 채워서 케이스 목록을 상속 | onClose |
| **S6 실행 목록** | S6 케이스 결과 입력 | 실행 ID + 케이스 ID | `/executions/{eid}/testcases/{tcid}/result` |
| **S6 결과 입력** | S3 대시보드 S7 결과 | 결과 저장 시 `TestResult` 테이블 갱신 | 실시간 통계 반영 |
| **S3 대시보드** | S6 실행 생성 | `[실행 시작]` 버튼 | 프로젝트별 통계에서 곧바로 시작 가능 |

## 8. 전제와 제약

| 항목 | 설명 | 회피 방법 |
|---|---|---|
| **플랜은 미리 만들어져야 함** | 케이스를 실행에 포함시키려면 플랜으로 미리 선택되어야 한다 | 플랜 미지정 실행 로드맵(현재 UI 없음) |
| **케이스 첨부파일은 읽기 전용** | 결과 입력 화면에서 케이스의 첨부파일 목록을 볼 수 있지만 수정할 수 없다 | S4에서 미리 준비 |
| **자동 저장만 지원** | 저장 버튼이 없다. 수정하면 자동으로 저장된다 | 의도하지 않은 변경을 피하려면 읽기 권한 사용자로 진입 |
| **탭 비활성 시 폴링 정지** | 다른 탭/창에서 작업하는 동안 실행 목록이 업데이트되지 않는다 | 수동 새로고침(브라우저 F5) 또는 탭 활성화 후 대기 |
| **TESTER는 결과 기록만** | 이름·플랜 같은 실행 속성은 편집할 수 없다. 읽기만 가능 | PM·LEAD가 실행을 생성하고 TESTER가 결과 입력 |
