# 공통 레이아웃(S2) 업무프로세스

> 화면 ID **S2** · 화면명 **전역 헤더 · 브레드크럼 · 영역 이동 · 프로젝트 전환 · 프로필 · 북마크**
> 라우트: `/projects/{projectId}` 의 공통 영역 · `/projects/{projectId}/bookmarks`

---

## 1. 업무 목적

S2는 본문 화면이 아니라 **본문을 담는 틀**이다. S3~S10이 이 틀 안에서 갈아 끼워진다. 네 가지를 맡는다.

| 목적 | 내용 |
|---|---|
| ① **위치를 알려준다** | 브레드크럼이 `프로젝트 / 이름 / 영역`을 항상 보여준다 |
| ② **영역을 옮긴다** | 8개 영역을 가로 탭 또는 좌측 메뉴로 이동한다. **같은 목록을 두 방식이 공유한다** |
| ③ **프로젝트를 바꾼다** | 보고 있던 영역을 유지한 채 다른 프로젝트로 넘어간다 |
| ④ **개인 도구를 얹는다** | 프로필 7탭 북마크 다크모드 매뉴얼 JIRA 상태 |

**이 화면이 하지 않는 일**

| 하지 않는 것 | 어디가 맡는가 |
|---|---|
| 업무 데이터 조작 | S3~S10 본문 |
| 프로젝트 생성·삭제 | S1 |
| 시스템 설정 | S11(헤더의 관리 메뉴가 입구만 제공) |
| 프로젝트 멤버 관리 | 없음. S1 7절 참조 |

## 2. 화면 위치

| 항목 | 내용 |
|---|---|
| 전(前) | S1 프로젝트 목록의 `[프로젝트 열기]` |
| 후(後) | 영역 8개(S3~S10) 중 하나. 진입 직후 기본은 S3 대시보드 |
| 진입 조건 | 로그인 + 경로에 프로젝트 ID |
| 되돌아가기 | 헤더 로고 브레드크럼 `프로젝트` 크럼 → S1 |

**프로젝트 ID가 경로에 없으면 공통 레이아웃이 프로젝트 선택 상태로 되돌아간다**. 프로젝트를 고르지 않은 채로 본문이 열리는 상태가 없다.

## 3. 업무 프로세스 흐름

### 3.1 영역 이동

| # | 사용자 행위 | 화면 동작 |
|---|---|---|
| 1 | 탭 또는 메뉴 항목 클릭 | 본문을 그 영역으로 갈아 끼우고 경로를 바꾼다 |
| 2 | 주소창에 직접 경로 입력 | 경로를 판별해 해당 영역으로 맞춘다 |
| 3 | 브라우저 뒤로·앞으로 | 2와 같은 경로를 탄다 |
| 4 | RAG·탐색 세션이 꺼짐 | 그 항목이 목록에서 빠지고 뒤 항목 번호가 당겨진다 |

**현재 영역은 순서 번호로 가리킨다.** 그 번호는 "보이는 항목 중 몇 번째"이고, 조건부 항목이 있으므로 고정값이 아니다. RAG가 꺼지면 그 뒤 항목의 번호가 한 칸 당겨진다.

**영역을 새로 넣을 때 함께 손대는 곳 4개**

1. 영역 목록 정의
2. 본문을 고르는 규칙
3. 주소에서 현재 영역을 판별하는 규칙
4. 영역을 고를 때 주소를 바꾸는 규칙

### 3.2 레이아웃 선택

같은 영역 목록을 두 방식으로 그린다. 고르는 곳이 두 군데다.

| 경로 | 저장 |
|---|---|
| 프로필 → 테마 설정 → `메뉴 구조` | 서버(사용자별) |
| 헤더의 전환 아이콘 | 같음 |

| 값 | 영역이 놓이는 곳 | 브레드크럼 첫 자리 | 그리는 컴포넌트 |
|---|---|---|---|
| 가로 탭(기본) | 브레드크럼 아래 | `프로젝트` 링크 | |
| 좌측 메뉴 | 화면 왼쪽 세로 | **프로젝트 선택기** | |

**좌측 메뉴에서는 브레드크럼의 `프로젝트 /` 크럼을 접는다**. 프로젝트 이름이 선택기와 크럼 두 곳에 나오는 중복을 없앤 처리다.

좌측 메뉴는 접을 수 있다. 접으면 아이콘만 남고 라벨은 `title` 속성으로 옮겨 간다.

### 3.3 프로젝트 전환

| # | 행위 | 동작 |
|---|---|---|
| 1 | 헤더 `[프로젝트 선택]` | S1 목록 페이지로 이동 |
| 2 | 좌측 메뉴 모드의 브레드크럼 프로젝트 이름 클릭 | 참여 프로젝트를 드롭다운으로 펼친다 |
| 3 | 목록에서 다른 프로젝트 선택 | `/projects/{id}`로 이동. 같은 프로젝트면 아무것도 하지 않는다 |
| 4 | 드롭다운 하단 `프로젝트 목록 보기` | S1으로 |

**두 경로의 성격이 다르다.** 1번은 목록 페이지를 왕복하고, 2번은 페이지를 떠나지 않는다. 참고 도구 대비 왕복이 문제였다는 진단이 `../../plan/LEFT_NAV_RESTRUCTURE.md` 4절에 있고, 2번이 그 처방이다.

⚠ 2번 선택기는 **좌측 메뉴 모드에서만** 브레드크럼에 나타난다. 가로 탭 모드에서는 1번만 쓸 수 있다.

### 3.4 프로필 다이얼로그

아바타 → `[프로필]`로 열린다. 탭 7개다.

| # | 탭 | 다루는 것 | 저장 |
|---|---|---|---|
| 1 | 기본 정보 | 사용자명(읽기 전용)·이름·이메일·역할 배지·이메일 인증 상태·버전 | 저장 버튼 |
| 2 | 비밀번호 | 기존 확인 후 변경 | 저장 버튼 |
| 3 | 언어 설정 | 인터페이스 언어 시간대 | 언어는 즉시, 시간대는 저장 버튼 |
| 4 | JIRA 설정 | 주소·이메일·연결 키 | 저장 버튼 |
| 5 | Google Sheets 설정 | 계정 연결 | 연결 절차 |
| 6 | API 토큰 | 발급·폐기(최대 10개) | 발급 시 즉시 |
| 7 | 테마 설정 | 화면 모드 디자인 시스템 **메뉴 구조** | 즉시 + 서버 저장 |

**API 토큰은 발급 직후 한 번만 전체가 보인다**(매뉴얼 13-6절). 전 화면 규칙 G7이다.

### 3.5 북마크

헤더 `☆` → `/projects/{projectId}/bookmarks`.

| # | 행위 | 동작 |
|---|---|---|
| 1 | 케이스 목록 행의 `☆` 클릭 | 기본 모음 `즐겨찾기`에 담는다 |
| 2 | 헤더 `☆` | 북마크 화면 진입 |
| 3 | 좌측 모음 선택 | 우측에 그 모음의 케이스 목록 |
| 4 | `[모음 만들기]` | 이름·설명 입력 |
| 5 | 모음 이름 변경·삭제 | 기본 `즐겨찾기` 모음은 삭제되지 않는다 |
| 6 | 케이스에 개인 메모 | 저장 |
| 7 | 케이스 제거 | 모음에서 빼낸다 |

**북마크는 개인 자산이다.** 다른 사용자 화면에 영향을 주지 않는다. 케이스 본문은 고칠 수 없고 모음 정리와 메모만 다룬다(매뉴얼 4-7절).

## 4. 레이아웃 규칙

| # | 규칙 | 내용 |
|---|---|---|
| B1 | **영역 목록은 한 곳에서 정의한다** | 가로 탭과 좌측 메뉴가 같은 배열을 읽는다. 두 곳에 적으면 항목 추가 시 한쪽만 고쳐진다 |
| B2 | **현재 영역은 순서로 가리킨다** | 고정 번호가 아니다. 조건부 항목 때문에 밀린다 |
| B3 | **개수 배지는 세 항목에만 붙는다** | 테스트케이스·플랜·실행. 자동화·결과·RAG·탐색에는 없다 |
| B4 | **배지 숫자는 화면이 셉니다** | 컨텍스트의 목록을 현재 프로젝트로 걸러 길이를 쓴다. 서버 집계가 아니다 |
| B5 | **두 레이아웃이 같은 글자 규격을 쓴다** | 레이아웃을 바꿔도 글자 크기가 튀지 않게 `CHROME_TYPOGRAPHY`를 공유한다 |
| B6 | **결과 입력·플랜 상세는 전체 화면으로 빠지지 않는다** | 헤더와 좌측 메뉴를 유지한 채 오른쪽 영역 안에서 열린다 |
| B7 | **접힘 상태는 브라우저에 남긴다** | 프로젝트 설명 접힘은 브라우저 저장소, 좌측 메뉴 접힘은 `useNavMode` |

## 5. 사용자와 권한

### 5.1 헤더 요소별 노출

| 요소 | 노출 조건 |
|---|---|
| 로고 + 버전 | 전원 |
| `[대시보드]` | **시스템 ADMIN** |
| `[관리 메뉴 ▾]` | **시스템 ADMIN** |
| `[프로젝트 선택]` | 전원 |
| JIRA 상태 배지 | 전원 |
| `?` 매뉴얼 | 전원 |
| 레이아웃 전환 | 전원 |
| 다크모드 | 전원 |
| 아바타 메뉴 | 전원 |
| `☆` 북마크 | 프로젝트 진입 시 |

**관리 메뉴가 ADMIN 전용이다.** 관리 메뉴 허용 판정(ADMIN 또는 MANAGER)가 정의되어 있으나 어디에서도 호출되지 않는다. 실제 판정은 전부 시스템 관리자 판정(ADMIN만)를 쓴다. MANAGER가 관리 메뉴에 들어가지 못한다.

⚠ 매뉴얼 17-1절은 "관리자 계정으로 로그인하면"으로만 적어 어긋나지 않지만, 관리 메뉴 허용 판정는 의도가 남은 죽은 코드다. 04에 기록했다.

### 5.2 영역 노출

프로젝트 권한이 영역 자체를 가리지 않는다. VIEWER도 8개 영역을 모두 본다. 편집 가능 여부는 본문 화면이 각자 판정한다(각 화면의 `02 권한별 차이`).

영역이 사라지는 조건은 기능 플래그 두 개뿐이다(`00_전체_업무프로세스.md` 4절).

## 6. 기능 규칙

| # | 규칙 |
|---|---|
| F1 | 프로젝트가 선택되지 않으면 이 공통 레이아웃을 그리지 않는다 |
| F2 | 브레드크럼의 마지막 크럼은 현재 영역 이름이다. 영역이 없으면 프로젝트 이름을 굵게 쓴다 |
| F3 | 프로젝트 전환 드롭다운은 현재 프로젝트를 선택 상태로 표시하고, 그것을 다시 눌러도 이동하지 않는다 |
| F4 | 드롭다운 항목에 프로젝트 코드를 보조 문구로 함께 쓴다 |
| F5 | 프로젝트 설명은 접을 수 있고, 접힘 상태가 다음 방문에도 유지된다 |
| F6 | 좌측 메뉴 선택 항목은 좌측 3px 선과 주 색상으로 표시한다 |
| F7 | 좌측 메뉴 접힘 시 라벨을 `title`로 옮겨 정보를 잃지 않는다 |
| F8 | 매뉴얼은 같은 탭을 덮지 않고 새 탭으로 연다 |
| F9 | 아바타 이니셜은 이름 첫 글자, 없으면 `U` |

## 8. 전제와 제약

| 항목 | 내용 |
|---|---|
| 영역 순서의 취약성 | 항목을 중간에 끼우면 뒤 번호가 밀려 본문 선택·주소 판별·저장된 마지막 위치가 함께 흔들린다 |
