# 탐색 세션(S10) 업무프로세스

> 화면 ID **S10** · 화면명 **차터 · 세션 · 노트 · 보고서 · 승인**
> 라우트: `/projects/{projectId}/exploratory`
> 노출 조건: 환경 변수 `SHOW_EXPLORATORY_SESSION_TAB` 이 켜져 있을 때만 노출된다

---

## 1. 업무 목적

탐색 세션은 사전 명세 없이 제품을 탐색하며 테스트하는 **SBTM(Session-Based Test Management)** 기법을 운영한다. 차터(목표)에서 시작해 정해진 시간 안의 세션을 진행하고, 노트·발견·중단을 기록한 뒤 보고서로 정리한다. 자동화나 케이스 기반 테스트로 다 커버하지 못한 영역을 보충한다.

| 목적 | 내용 |
|---|---|
| ① **차터 정의** | 테스트 목표·범위·아이디어·전략을 마크다운으로 기록한다 |
| ② **세션 진행** | 시작부터 종료까지 타이머를 두고 세션을 진행한다. 진행 중 노트·버그·중단을 기록한다 |
| ③ **세션 기록** | 세션 타이틀·테스터·테스트 시간 배분(%)·환경·버전을 저장한다 |
| ④ **보고서·승인** | 세션 후 사후평가와 QA 총평을 작성하고 승인을 받는다 |
| ⑤ **세션→케이스 승격** | 세션에서 나온 발견이 정식 테스트 케이스로 등록될 수 있다 |

**이 화면이 하지 않는 일**

| 하지 않는 것 | 어디가 맡는가 |
|---|---|
| 실행 결과(PASS/FAIL) 기록 | S6 테스트 실행 |
| 케이스 자산 관리 | S4 테스트 케이스 |
| 자동화 결과 흡수 | S8 자동화 테스트 |
| 차터 템플릿 관리 | 입력 시점에만 제공 |

## 2. 화면 위치

| 항목 | 내용 | 참조 |
|---|---|---|
| 전(前) | S3 프로젝트 대시보드 또는 S4 테스트 케이스 | 좌측 탐색 메뉴 |
| 후(後) | **계속 탐색 또는 S4로 전환** | 세션 발견을 케이스로 등록 가능 |
| 진입 조건 | 프로젝트에 진입 후 왼쪽 탭 `탐색 세션` 클릭 | **환경 변수로만 켜진다** |
| 환경 변수 | `SHOW_EXPLORATORY_SESSION_TAB=true` 일 때만 노출 | |

**환경 변수 미설정 시 영역이 없다.** 좌측 탭 자체가 나타나지 않는다. 조직 RAG도 같은 패턴인데(RAG 사용 가능 여부), 탐색 세션은 더 명시적으로 환경 설정이 필요하다.

## 3. 업무 프로세스 흐름

### 3.1 차터 조회 및 작성

| # | 사용자 행위 | 화면 동작 |
|---|---|---|
| 1 | `/projects/{projectId}/exploratory?tab=charters` 진입 | 차터 목록을 불러온다 |
| 2 | 차터 0건 | 빈 상태 안내 + `[새 차터 생성]` 버튼 |
| 3 | `[새 차터 생성]` 클릭 | 마크다운 에디터를 연다. 기본 템플릿이 들어간다 |
| 4 | 목적·범위·아이디어·전략 입력 | 자동 저장 또는 명시적 저장 |
| 5 | `[저장]` | 차터가 저장된다. 새 세션 생성 가능 |

### 3.2 세션 생성 및 진행

| # | 행위 | 화면 동작 |
|---|---|---|
| 1 | 차터 상세 → `[세션 시작]` | 세션 편집 탭이 열린다. 세션이 생성된다 |
| 2 | 테스터·리더·시간 배분(%) 입력 | 세션 초기값이 저장된다 |
| 3 | `[세션 시작]` | 타이머가 시작된다. 노트·버그·중단을 기록할 수 있다 |
| 4 | 진행 중 노트/버그 입력 | 항목이 즉시 추가된다 |
| 5 | `[중단 기록]` | 중단 사항과 시간이 저장된다 |
| 6 | `[세션 종료]` | 세션이 종료된다. 타이머가 멈춘다 |

### 3.3 보고서 및 승인

| # | 행위 | 화면 동작 |
|---|---|---|
| 1 | 세션 종료 후 `[사후평가]` 탭 | 사후평가 입력 양식이 표시된다 |
| 2 | 평가 입력 | 평가 항목이 저장된다 |
| 3 | `[제출]` | 세션이 제출 상태가 된다. 승인자에게 알림이 간다 |
| 4 | 승인자 검토 | PM·LEAD만 `[승인]` 또는 `[반려]` 버튼을 볼 수 있다 |
| 5 | 승인 완료 | 세션이 승인된다. 발견을 케이스로 승격할 수 있다 |

## 4. 탐색 세션 모델 규칙

| # | 규칙 | 내용 |
|---|---|---|
| E1 | **차터는 마크다운이다** | 목적·범위·아이디어·전략을 마크다운으로 기록·편집한다 |
| E2 | **세션은 시간 제약이 있다** | 보통 60~120분. 진행 시간을 명시해야 한다 |
| E3 | **세션 시간을 활동별로 분배한다** | 테스트 실행(%)·버그 조사(%)·관리(%) 3항목이 합 100%를 이룬다 |
| E4 | **세션은 상태 머신이다** | 작성 중 → 제출 → 승인 또는 수정 필요의 상태 전이를 따른다 |
| E5 | **세션 내 요소들을 기록한다** | 노트(비정형)·버그·중단·테스트 실행 흐름이 기록된다 |
| E6 | **발견은 케이스로 승격할 수 있다** | 세션 버그가 정식 테스트 케이스로 등록될 수 있다 |
| E7 | **세션은 프로젝트별이다** | 같은 프로젝트의 차터·세션이 함께 묶인다 |

## 5. 사용자와 권한

### 5.1 기능 × 역할

탐색 세션은 **차터 작성·세션 진행·보고서 승인**이 관여자가 다르다.

| 기능 | 시스템 ADMIN | PM LEAD | DEVELOPER CONTRIBUTOR TESTER | VIEWER |
|---|---|---|---|---|
| 차터 목록 조회 | ○ | ○ | ○ | ○ |
| 차터 생성·수정 | ○ | ○ | **○** | — |
| 세션 시작·진행·기록 | ○ | ○ | **○** | — |
| 세션 결과 제출(SUBMITTED) | ○ | ○ | **○** | — |
| 세션 승인(APPROVED) | ○ | **○** | — | — |
| 세션 발견을 케이스로 승격 | ○ | **○** | — | — |

**TESTER도 차터 작성·세션 진행이 가능하다.** 비정형 테스트 담당자가 세션을 주도해야 하기 때문이다.

**승인 권한은 PM·LEAD만이다.** DEVELOPER는 세션 제출까지만 한다.

### 5.2 화면 요소별 노출

| 요소 | 조건 | 참조 |
|---|---|---|
| 차터 탭 | 모두 | |
| 세션 목록 탭 | 모두 | |
| 세션 편집 탭 | 편집/결과 입력 권한 있을 때 | `결과 기록 권한 \| PM/LEAD` |
| 사후평가 탭 | 세션이 생성된 후 | `sessionId` 있을 때 |
| `[세션 시작]` | 결과 입력 권한 | 결과 기록 권한 |
| `[승인]` / `[반려]` | PM LEAD만 | 관리 권한 |

## 7. 타 화면 연동

### 7.1 세션 발견 → S4 케이스 승격

세션의 버그 발견이 테스트 케이스로 등록될 수 있다.

S10 세션 버그 목록
 ↓ [케이스로 등록]
S4 테스트 케이스 트리에 새 케이스 생성
 ↓
S5 플랜에 포함 가능
S6 실행 가능

### 7.2 S6 테스트 실행과의 차이

| 항목 | S6 실행 | S10 탐색 |
|---|---|---|
| 참조 | 정의된 케이스들 | 정해지지 않은 탐색 |
| 결과 기록 | PASS/FAIL/BLOCKED/NOTRUN | 노트·발견·중단 |
| 시간 관리 | 계획 vs 실제 | 활동별 배분(%) |
| 산출물 | 결과 통계 | 비정형 보고서 |

## 8. 전제와 제약

### 제약

| 제약 | 사유 | 우회 |
|---|---|---|
| **환경 변수 필수** | 탐색 세션은 선택 기능이므로 활성화 필수 | docker-compose.yml의 `SHOW_EXPLORATORY_SESSION_TAB=true` |
| **시간 배분이 정수(%)** | 소수 계산의 복잡성 회피 | 1% 단위로만 입력 가능 |
| **세션 생성 후 차터 수정 불가** | 진행 중 차터 변경 방지 | 새 세션 생성 전에 차터 확정 |
| **파일 첨부 크기 제한** | MinIO 저장소 용량 | `MINIO_` 환경 변수로 조정 |

### 전제

- 세션은 시간 제약이 있다(일반적으로 90분 이내).
- 차터가 선행되어야 세션을 시작할 수 있다.
- 테스트 환경에 직접 접근 가능해야 한다.
