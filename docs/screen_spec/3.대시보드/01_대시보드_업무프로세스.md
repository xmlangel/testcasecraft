# 대시보드(S3) 업무프로세스

# 화면 ID: S3
- 프로젝트 대시보드: `/projects/{projectId}` (기본 영역)
- 전사 대시보드: `/dashboard` (ADMIN 전용)

---

## 1. 업무 목적

대시보드는 테스트 작업의 **현황을 한눈에 보는 명령 센터**다. 케이스 수·진행도·멤버별 부하·최근 추이를 그래프와 수자로 정리하고, 실행 상황에 따라 신속하게 다음 액션을 결정하게 한다. 두 수준의 대시보드가 있다.

| 목적 | 대상 | 내용 |
|---|---|---|
| ① **프로젝트 현황 파악** | 프로젝트 참여자 (PM·개발·QA) | 케이스·실행·결과 진행도. 플랜별 성공률 |
| ② **전사 경영 현황 파악** | 시스템 ADMIN | 조직별 프로젝트·활동 추이·서버 성능 |
| ③ **담당자별 과제 인식** | 실행 중인 멤버 | 내게 할당된 케이스 진행도. 언제까지인지 |

**이 화면이 하지 않는 일**

| 하지 않는 것 | 어디가 맡는가 |
|---|---|
| 케이스·플랜·실행 생성·편집 | S4·S5·S6 |
| 상세 보고서 내보내기 | S7 결과 화면 |
| 시스템 설정·권한 관리 | S11 관리자 설정 |

## 2. 화면 위치

### 2.1 프로젝트 대시보드

| 항목 | 내용 |
|---|---|
| 전(前) | S2 작업공간 입장(`/projects/{projectId}` 기본) |
| 후(後) | S4·S5·S6·S7·S8·S9·S10 — 영역 탭으로 이동 |
| 진입 조건 | 프로젝트 액세스 권한. 권한 없으면 403 |
| 상시 진입 | 헤더 `[대시보드]` 탭 (가로 탭 첫 번째) |

**`/projects/{projectId}` 진입 시 기본 영역이다.** 프로젝트가 활성화되자마자 대시보드가 첫 화면으로 뜬다.

### 2.2 전사 대시보드

| 항목 | 내용 |
|---|---|
| 전(前) | S1 프로젝트 목록·관리 메뉴 |
| 진입 | 헤더 `[관리]` 드롭다운 → `[대시보드]` |
| 진입 조건 | 시스템 `ADMIN` 역할 |
| 라우트 | `/dashboard` |

**`MANAGER` 역할은 관리 메뉴만 열리고 전사 대시보드는 못 본다. 시스템 `ADMIN` 전용이다**.

## 3. 업무 프로세스 흐름

### 3.1 프로젝트 대시보드 — 진입과 새로고침

| # | 사용자 행위 | 화면 동작 | 결과 |
|---|---|---|---|
| 1 | 프로젝트 열기 | `/projects/{projectId}` 진입 → 대시보드 자동 로드 | 대시보드 데이터 조회 중 |
| 2 | 데이터 로드 중 | 진행 표시 + 로딩 메시지 | 사용자가 대기 중임을 알림 |
| 3 | 데이터 로드 완료 | 6개 위젯 모두 그린다 | 대시보드 완성 |
| 4 | `[새로고침]` 클릭 | 최신 데이터 재조회 | 차트 갱신 |
| 5 | 로드 실패 | 에러 메시지 + 재시도 버튼 | 사용자가 문제를 인식하고 행동 |

**프로젝트 전환 시 자동 재로드다.** 프로젝트 선택이 변경되면 대시보드 데이터를 자동으로 다시 조회한다.

### 3.2 위젯별 상호작용

| 위젯 | 동작 |
|---|---|
| **프로젝트 요약** | 접기/펴기 (브라우저에 저장) |
| **최근 테스트 결과** | 플랜 드롭다운에서 선택 → 그 플랜의 최근 결과만 표시 |
| **테스트 결과 추이** | 기간 필터 (기본 15일) |
| **담당자별 결과** | 멤버별 진행도 막대 표시 |

**플랜 선택 시 다른 위젯은 영향받지 않는다.** "최근 결과"만 선택된 플랜으로 필터링되고, 다른 차트들은 전체 프로젝트 기준으로 유지된다.

## 4. 데이터 집계 규칙

대시보드에 뜨는 숫자의 출처를 정리한다.

| 지표 | 계산 방식 |
|---|---|
| **총 케이스 수** | 프로젝트 소속 모든 테스트케이스의 개수 |
| **멤버 수** | 프로젝트에 할당된 모든 멤버의 개수 |
| **완료율** | (PASS + FAIL + BLOCKED + SKIPPED) / 총 케이스 × 100 |
| **실패율** | 최근 실행의 FAIL 건수 / 총 케이스 × 100 |
| **담당자별 진행도** | 현재 열린 실행 중 각 멤버별 PASS/FAIL/미완료 합계 |
| **플랜별 성공률** | 그 플랜의 최근 N건 실행 결과 |

**"최근 실행"의 범위는 명시되지 않았다.** ⚠ 확인 필요: 마지막 1건 실행만? 아니면 최근 7일? API 응답을 실행 확인해야 한다.

## 5. 사용자와 권한

### 5.1 기능 × 역할

프로젝트 대시보드는 참여 권한이 있는 모든 역할이 볼 수 있다. 수정 작업은 없다(읽기 전용).

| 기능 | ADMIN | PM LEAD | DEVELOPER CONTRIBUTOR | TESTER | VIEWER | 판정 근거 |
|---|---|---|---|---|---|---|
| 프로젝트 대시보드 조회 | ○ | ○ | ○ | ○ | ○ | 프로젝트 조회 권한 |
| 전사 대시보드 조회 | ○ | — | — | — | — | `isSystemAdmin`|
| 새로고침 | ○ | ○ | ○ | ○ | ○ | 모두 가능 |
| 기간 필터 변경 | ○ | ○ | ○ | ○ | ○ | 모두 가능 |
| 플랜 선택 | ○ | ○ | ○ | ○ | ○ | 모두 가능 |

**VIEWER도 대시보드를 본다.** 편집은 없으므로 권한 최소화(조회만)로 제한된다. 전사 대시보드는 경영 정보라 `ADMIN` 전용이다.

### 5.2 화면 요소별 노출

| 요소 | 노출 조건 |
|---|---|
| 프로젝트 대시보드 6개 위젯 | `activeProject` 존재하고 권한 있음 |
| `[새로고침]` 칩 | `activeProject` 존재할 때만. ADMIN·MANAGER도 클릭 가능 |
| 기간 필터 | 구현되어 있는지 ⚠ 확인 필요 |
| 전사 대시보드 링크 | `isSystemAdmin` = true |

## 6. 기능 규칙

| # | 규칙 |
|---|---|
| F1 | **접이식 섹션은 브라우저 저장소에 상태를 저장한다.** 닫은 섹션은 새로고침 후에도 닫혀 있다 |
| F2 | **플랜 선택이 비워져도 "최근 결과" 위젯은 남아 있다. 전체 프로젝트 최근 결과를 보여준다** |
| F3 | **에러 메시지는 재시도 버튼을 함께 표시한다. 네트워크 일시 오류 시 사용자가 쉽게 복구할 수 있다** |
| F4 | **프로젝트 전환 시 선택된 플랜이 초기화된다. 플랜이 다른 프로젝트와 묶여 있지 않으므로** |
| F5 | **데이터 없음 경고는 로딩 중·에러 중일 때는 숨긴다. 겹치는 UI를 방지한다** |

## 7. 타 화면 연동

대시보드는 **조회 전용**이지만 다른 화면으로의 진입점을 여러 개 가진다.

| 진입점 | 목표 화면 | 동작 |
|---|---|---|
| 위젯 클릭 | S4 / S5 / S6 | 해당 영역 탭으로 이동. 필터가 자동 적용될 수 있다 |
| 플랜 선택 | 같은 화면 | 선택한 플랜의 최근 결과만 표시 |
| (미구현) 기간 필터 | 같은 화면 | 차트의 기간 범위를 바꾼다 |

## 8. 전제와 제약

| # | 항목 | 내용 |
|---|---|---|
| T1 | **서버 API 필수** | 프론트 로컬 상태로는 대시보드 데이터를 만들 수 없다. `dashboardService` API 호출이 필수다 |
| T2 | **프로젝트 컨텍스트 필요** | 프로젝트 대시보드는 `activeProject` 존재를 전제로 한다. 프로젝트 없으면 빈 화면이다 |
| T3 | **권한 검증은 서버가 한다** | 프런트는 프로젝트 조회 권한 표시만 한다. 실제 403·401은 API 응답에 의존한다 |
| T4 | **실시간 동기화 아님** | 새로고침 버튼을 눌러야만 최신 데이터가 로드된다. 폴링이나 WebSocket은 없다 |
