# 관리자설정(S11) 업무프로세스

> 화면 ID **S11** · 화면명 **조직 · 사용자 · 메일 · LLM · 스케줄러 · 번역 관리**
> 라우트: `/organizations` · `/users` · `/mail-settings` · `/llm-config` · `/scheduler` · `/translation-management`

---

## 1. 업무 목적

조직과 시스템 전역 설정을 관리한다. 사용자 계정·인프라 설정·백엔드 작업 스케줄이 이 화면들에서 결정되고, 변경이 프로젝트 모든 곳에 영향을 미친다. S11은 접근 권한이 시스템 `ADMIN`으로 가장 제한적이다.

| 목적 | 내용 | 참조 |
|---|---|---|
| ① **조직 계층 관리** | 조직(Organization) 단위로 프로젝트를 그룹핑하고, 조직 내 그룹(Group)과 멤버 역할을 관리한다 | `/organizations` 라우트 매뉴얼 17-3절 |
| ② **전 사용자 관리** | 시스템의 모든 계정을 조회하고 역할·상태를 제어한다 | `/users` 라우트 매뉴얼 17-4절 |
| ③ **메일 시스템 설정** | SMTP 계정·발신자·템플릿을 정의해 인증·알림·보고서 메일을 보낸다 | `/mail-settings` 라우트 매뉴얼 17-5절 |
| ④ **LLM 프로바이더 설정** | RAG 챗·자동 메타 생성 등에 쓸 LLM 연동과 프롬프트를 정의한다 | `/llm-config` 라우트 매뉴얼 17-6절 |
| ⑤ **백그라운드 작업 관리** | Cron 주기, 수동 실행, 일시정지 등으로 스케줄된 잡을 제어한다 | `/scheduler` 라우트 매뉴얼 17-7절 |
| ⑥ **다국어 번역 관리** | UI 키·값 쌍을 동적으로 편집해 다언어 지원을 확대한다 | `/translation-management` 라우트 매뉴얼 17-8절 |

**이 화면이 하지 않는 일**

| 하지 않는 것 | 어디가 맡는가 |
|---|---|
| 프로젝트 단위 설정(멤버 초대·역할·폴더 규칙) | S1 카드 메뉴 또는 S2 헤더 프로젝트 메뉴(7절) |
| 전사 대시보드 조회 | S3 시스템 대시보드(`/dashboard`, 전 화면 규칙 G8 자동 갱신) |

## 2. 화면 위치

### 2.1 진입 경로

시스템 `ADMIN` 또는 `MANAGER` 권한이 있을 때만 헤더에 **[관리 메뉴 ▾]** 버튼이 노출된다.

| 항목 | 내용 | 참조 |
|---|---|---|
| 전(前) | S2 작업공간(모든 화면에서) S1 프로젝트 목록 | 헤더의 `[관리 메뉴 ▾]` 드롭다운 |
| 진입 조건 | 시스템 `ADMIN` `MANAGER` **번역 관리는 URL 직접 진입만 가능**(2.3절 참조) | |
| 상시 진입 | 헤더 `[관리 메뉴 ▾]`(로그인 후 모든 프로젝트 화면에서) | |

⚠ **기능 미구현.** 관리 메뉴는 현재 시스템 관리자(ADMIN)만 들어갈 수 있다. 매니저 권한을 허용하는 기능이 미구현되었다.

### 2.2 관리 메뉴 드롭다운

| 항목 | 경로 | 노출 |
|---|---|---|
| **조직 관리** | `/organizations` | ○ |
| **사용자 관리** | `/users` | ○ |
| **메일 설정** | `/mail-settings` | ○ |
| **LLM 설정** | `/llm-config` | ○ |
| **스케줄러 관리** | `/scheduler` | ○ |
| **번역 관리** | `/translation-management` | **× 주석 처리** |

**메뉴가 6개지만, 번역 관리는 URL 직접 입력으로만 진입한다.**

### 2.3 번역 관리 접근 경로

| 방법 | 라우트 |
|---|---|
| 드롭다운 메뉴 | **× 없음** |
| 직접 입력 | `http://.../#/translation-management` |

사용자가 수동으로 URL을 입력하거나 북마크에서 접근해야 한다. 한국어/영어 외 언어 추가 또는 키 편집이 필요할 때만 열린다(매뉴얼 17-8절).

## 4. 운영 모델 규칙

| # | 규칙 | 내용 | 참조 |
|---|---|---|---|
| O1 | **조직은 프로젝트 그룹화 단위다** | 한 조직 안의 모든 프로젝트는 공유 멤버·그룹·설정을 갖는다. 조직 없는 독립 프로젝트도 1급 개념이다 | 매뉴얼 17-3절 00_전체_업무프로세스 7절 모델 |
| O2 | **시스템 권한은 ADMIN/MANAGER/null 세 값이다** | ADMIN은 전 기능 접근. MANAGER는 관리 메뉴 접근만(전사 대시보드는 ADMIN 전용). null은 프로젝트 권한만 적용 | 00_전체 5.1절|
| O3 | **조직 역할은 OWNER/ADMIN/MEMBER 세 값이다** | 조직 상세 화면에서만 쓰이고, 프로젝트 데이터 접근에는 영향을 주지 않는다 | 00_전체 5.3절|
| O4 | **메일 설정은 전역 하나다** | 조직별·프로젝트별 SMTP가 아니라 시스템 전역 하나의 발신자·템플릿을 쓴다. 변경이 모든 메일을 영향시킨다 | 매뉴얼 17-5절 |
| O5 | **LLM 프로바이더는 여러 개를 등록할 수 있다** | 프로바이더별로 API Key·모델·프롬프트가 다르므로 여러 개 등록 가능. 프로젝트마다 기본 프로바이더를 선택한다(추정) | 매뉴얼 17-6절 |
| O6 | **스케줄러는 백엔드 등록 잡만 제어한다** | 새 잡을 추가하는 폼이 아니라 이미 등록된 잡의 주기·활성화만 관리한다 | 매뉴얼 17-7절 |
| O7 | **번역 키는 코드에서 생성되고 여기서 값만 입력한다** | 새 키를 추가하는 폼이 없다. UI에 `t("키", "폴백")`이 있는 모든 곳이 자동으로 키 생성 후보가 된다 | 매뉴얼 17-8절 00_전체 규칙 G10 |

## 5. 사용자와 권한

### 5.1 기능 × 역할 (시스템 차원)

S11 전체 진입에는 시스템 `ADMIN` 권한이 필수다. 그 안의 6개 하위 화면마다 권한이 같다(시스템 관리자 판정로 일괄 검사).

| 기능 | 시스템 ADMIN | 시스템 MANAGER | 그 외 |
|---|---|---|---|
| S11 진입 (`/organizations` 외) | ○ | ❌(일부 가능) | ❌ |
| 조직 조회·수정·멤버관리 | ○ | ⚠ **확인 필요** | ❌ |
| 사용자 전체 조회·역할변경·비활성화 | ○ | ⚠ 확인 필요 | ❌ |
| 메일 설정 변경 | ○ | ⚠ 확인 필요 | ❌ |
| LLM 프로바이더 설정 | ○ | ⚠ 확인 필요 | ❌ |
| 스케줄러 제어 | ○ | ⚠ 확인 필요 | ❌ |
| 번역 편집 | ○ | ⚠ 확인 필요 | ❌ |

⚠ **MANAGER 권한이 미구현 상태다.** 현재는 시스템 관리자(ADMIN)에게만 모든 기능을 허용한다. 매니저도 일부 기능(조직·사용자 조회, 메일 설정 등)에 접근하도록 하려면 각 컨트롤러의 권한 검사를 추가해야 한다.

### 5.2 하위 화면별 권한 요소 노출

| 하위 화면 | 목적 | 필수 권한 | 비고 |
|---|---|---|---|
| 조직 관리 | 조직 추가·편집·멤버초대 | 시스템 ADMIN | 조직 단위는 프로젝트 역할과 무관 |
| 사용자 관리 | 계정 역할·상태 제어 | 시스템 ADMIN | 개인의 프로젝트 역할은 여기서 못 바꾼다 |
| 메일 설정 | SMTP·발신자·템플릿 커스터마이즈 | 시스템 ADMIN | 변경이 시스템 전체 메일에 영향 |
| LLM 설정 | 프로바이더·모델·프롬프트 정의 | 시스템 ADMIN | 프로젝트마다 선택하는 것은 S1/S2(미확정) |
| 스케줄러 | 잡 주기·활성화·수동 실행 | 시스템 ADMIN | 백엔드 코드에 등록된 잡만 관리 가능 |
| 번역 관리 | 다국어 UI 값 입력 | 시스템 ADMIN | URL 직접 접근만 가능(메뉴 미노출) |

## 6. 기능 규칙

| # | 규칙 | 참조 |
|---|---|---|
| F1 | **조직 멤버 초대는 메일로만 이루어진다** | 메일 설정이 완료되어야 초대 메일이 발송된다 |
| F2 | **사용자 목록 검색은 실시간이다** | 입력할 때마다 필터링되고 페이지네이션이 재계산된다 |
| F3 | **스케줄러 잡은 코드에서만 추가된다** | 화면에는 추가 폼이 없다. 후속 변경만 가능하다 |
| F4 | **번역 키는 증분된다** | UI에 새로운 `t` 호출이 생기면, 자동으로 빈 번역 행이 생긴다(추정) |
| F5 | **LLM 프로바이더 여러 개를 등록할 수 있다** | 프로젝트마다 기본값을 선택하는 구조로 추정(확인 필요) |

## 7. 타 화면 연동

| 연동 대상 | 연동 내용 | 참조 |
|---|---|---|
| **S0 로그인** | 사용자 계정 생성·비활성화가 로그인 가능 여부에 영향 | 사용자 관리 |
| **S1 프로젝트** | 조직 소속이 여기서 결정된다. 조직 멤버가 프로젝트 권한 후보가 된다 | 조직 관리 프로젝트 생성 |
| **S2 헤더** | 프로젝트 메뉴(`/projects/{id}/settings`) — 프로젝트 단위 설정은 S2의 관리이지 S11의 관리가 아니다 | 사용자가 `PROJECT_MANAGER`면 노출 |
| **S3 시스템 대시보드** | 전사 통계가 LLM·메일·스케줄러 설정에 의존할 수 있다 | `/dashboard` (ADMIN 전용) |
| **S4~S10 전 화면** | 사용자 역할·메일 발송·RAG(LLM)·자동화 스케줄이 여기서 정의된 설정으로 동작한다 | 권한·메일·LLM·스케줄러 설정 의존 |
| **S9 RAG 문서** | LLM 설정에서 정한 프로바이더·모델이 임베딩·챗에 쓰인다 | `/projects/{id}/rag` 의존 |
